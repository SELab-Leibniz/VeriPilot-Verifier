# IR Stage 全局规范

本规范描述 Runtime Corrector 当前版本对 IR 的完整作者地图。项目实际启用的硬规则、别名和严重级别以 `ir.rules.yaml` 为准，语义判断以 `ir.reviewer.md` 为准。

## 输入与输出

- 目标产物：`ir.md` 或 config 中命中的 IR Markdown。
- 事实来源：用户原始需求及当前 IR 内容。
- 允许修改：只修改当前 IR。
- 禁止行为：不得为了通过检查扩张用户未提出的功能、权限、依赖或平台能力。

## 结构契约

IR 必须覆盖项目规则声明的章节或别名。默认四类核心信息是：

1. 目标与范围：应用目标、本期范围、明确范围外。
2. 功能需求：用户动作、系统响应、关键异常与边界。
3. 验收标准：使用 `- [ ]`，包含可执行动作和可观察结果。
4. 来源追溯：区分用户明确要求、必要推断、建议项和待确认项。

默认还要求明确 HarmonyOS/OpenHarmony/鸿蒙平台，并检查用户场景、范围边界和占位符。实际标题别名、最少 checklist 数量和 severity 必须读取当前项目规则，不能凭本规范覆盖项目配置。

## 精确语法

```markdown
# <项目名称>

## 目标与范围

应用目标：...
本期范围：...
范围外：...

## 功能需求

- 用户动作：...
- 系统响应：...
- 异常与边界：...

## 验收标准

- [ ] <动作> 后可以观察到 <明确结果>
- [ ] <异常输入或边界> 时可以观察到 <明确结果>

## 来源追溯

- 用户明确要求：...
- 必要推断：...
- 建议项：...
- 待确认：...
```

## 通过条件

- 当前 `ir.rules.yaml` 的所有 error 级规则通过。
- Reviewer 未发现无依据扩张、矛盾或不可执行验收。
- 不确定事实被标记为推断或待确认，而不是写成用户已批准。
- 候选 Patch 仅可用于确定性的缺章节修复，且不会自动应用。
