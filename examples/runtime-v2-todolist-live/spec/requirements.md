# TodoList 需求规格

## 目标与范围

在当前目录实现一个设计完整、依赖最少的 TodoList Web App。产品使用原生 HTML、CSS、JavaScript ES modules，不引入第三方运行时依赖、构建器或网络服务。核心状态逻辑与 DOM 分离，能用 Node 内置测试运行器（`node --test`）验证。

本规格仅覆盖本 Prompt 的原子需求（R01–R09），不静默增加需求。

明确不在范围内：账户、云同步、后端、多用户协作、拖拽排序、截止日期、标签、第三方 UI 框架。刷新后持久化不是本任务的硬性要求，不自行扩张范围。

## 原子需求

- **R01**：用户可以输入非空标题并新增待办；纯空白输入不得创建待办。
- **R02**：每条待办具有稳定且唯一的 ID；编辑标题和切换完成状态不得改变 ID。
- **R03**：用户可以把待办标记为完成，也可以恢复为未完成。
- **R04**：用户可以编辑待办标题；空白编辑不得破坏已有标题。
- **R05**：用户可以按 ID 删除且只删除目标待办。
- **R06**：用户可以在“全部 / 进行中 / 已完成”三个视图间筛选，计数与当前数据一致。
- **R07**：页面应清晰、响应式并可用键盘操作；交互控件有可理解的可访问名称，完成状态不能只靠颜色表达。
- **R08**：核心状态逻辑与 DOM 分离，能用 Node 内置测试运行器验证，不依赖浏览器或网络。
- **R09**（关键旅程）：新增两项 -> 完成一项 -> 筛选已完成 -> 编辑另一项 -> 删除目标项，且其余项不受影响。

## 验收标准

- R01：空白/纯空格输入不创建待办；非空标题创建成功，返回新待办。
- R02：新增即获得 ID；同一 ID 在多次操作中不变；不同待办 ID 互不相同；编辑标题与切换完成后 ID 不变。
- R03：可在 `completed` 为 `true`/`false` 之间双向切换，且只影响目标项。
- R04：编辑传入空白标题时不修改原标题（视为无效编辑，返回原状态或不变项）；非空标题更新成功。
- R05：按 ID 删除仅移除目标项，其余项数量与 ID 不变。
- R06：提供 `all`/`active`/`completed` 三种筛选；各视图计数与当前数据实时一致。
- R07：交互控件（输入、按钮、复选框）具备可访问名称/标签；完成状态以文字或非仅颜色的方式表达；支持键盘操作（Enter 新增）。
- R08：模型为纯 ES module，无 DOM 依赖，`node --test` 可运行其测试。
- R09：关键旅程在单一测试用例中按序通过，断言每步状态符合预期。

## 里程碑与关键旅程

里程碑：

- M1：纯状态模型（`src/todo-model.mjs`）实现 R01–R06、R08 的状态语义。
- M2：Node 测试（`test/todo-model.test.mjs`）覆盖原子行为与 R09 关键旅程。
- M3：可访问 UI（`index.html`、`styles.css`、`src/app.mjs`）绑定模型，满足 R07。
- M4：`package.json` 配置 `npm test` 使用 `node --test`，无第三方依赖。

关键旅程（R09）：新增两项 -> 完成一项 -> 筛选已完成 -> 编辑另一项 -> 删除目标项，且其余项不受影响。

## 事实、假设与待确认

事实：
- 运行环境为 Node（内置 `node:test`），浏览器用于加载原生 ES module 页面。
- 治理由 `.runtime-corrector/config.yaml` 与 JSON Schema 约束受控产物。

假设：
- ID 生成无需跨刷新稳定；本任务不要求持久化（除非显式确认）。
- “非空标题”指去除首尾空白后长度大于 0 的字符串。

待确认：
- 无。范围严格限定为本 Prompt 的 R01–R09，不引入额外功能。
