# HarmonyOS TodoList 方案

## 架构设计

页面通过 `TodoStore` 读取状态和提交命令。`TodoStore` 是待办内容、完成状态和持久化 revision 的唯一事实源，避免页面之间出现不同副本。

## 持久化设计

每次新增或切换完成态后，先形成新的不可变状态，再原子写入本地快照。应用启动时读取并校验快照；成功后一次性发布给页面。快照至少包含稳定 ID、文本、完成状态和 schema version。

## 失败与恢复

- 保存失败：保留可见内存状态、显示失败提示，并提供重试；不得静默宣称已保存。
- 快照损坏：保留原文件用于诊断，进入明确恢复状态，不用空列表覆盖原数据。
- 验证持久化时必须终止进程并重新启动；卸载、清数据或重新安装不能替代该旅程。
