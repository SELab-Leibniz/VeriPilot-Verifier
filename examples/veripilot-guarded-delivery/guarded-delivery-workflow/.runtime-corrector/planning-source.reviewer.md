# 六阶段到 Planning 来源投影审阅标准

当前目标只有 `planning-source.md`；六份 Stage 文档只读。

## 无损来源

1. `来源索引` 恰好列出六个固定文件，记录项目相对路径、SHA-256、字节数、
   换行格式、末尾换行状态、Stage 名称和权威类型。
2. `原文快照` 必须声明 `snapshot-encoding=indent4-v1`，并按索引顺序保存
   六份可逆快照。每个快照使用不构成 Markdown 标题的 begin/end 注释包围；
   原文每个非空行前精确增加四个 ASCII 空格，空行保持为空。
3. `indent4-v1` 的唯一解码是：在 begin/end 之间逐行移除非空行开头恰好
   四个 ASCII 空格，保留空行，再按索引记录的 LF/CRLF 和末尾换行状态还原。
   解码后的 UTF-8 字节必须与源文件逐字节相同，字节数和 SHA-256 必须一致。
   不能使用 fenced code block；当前确定性 Markdown 解析器会把 fence 内的
   `#` 误当成当前文档标题。
4. 解码后的标题、ID、否定表述、开放问题和测试细节不得被删改；索引 hash
   不能是示例值或重新排版后内容的 hash。

## 规范化映射

1. 每个 `REQ-*`、拆分项、验收 ID、方案决策、人工用例和 DT 场景都有明确的来源路径与原标识。
2. 功能意图、范围、约束、非目标和开放问题与需求分析/拆分一致。
3. 代码事实只能来自 code-understanding；未知项不得被方案或测试文档“多数表决”为事实。
4. 里程碑投影约束明确：每个 SR 只属于一个里程碑；`requires` 只表示执行硬依赖；跨里程碑依赖必须进入 PilotPlan 的 `Depends on`。
5. 文档不生成最终 SR 或 Milestone，不提前替 Planning 做未经审查的切分。

## 失败条件

任何来源缺失、hash 不符、原文不完整、ID 无去向、意图改写或无依据扩张都必须失败。
