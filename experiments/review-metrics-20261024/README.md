## 输入与独立核对

fixtures 包含43个精确工作区、task 和外置 oracle。basis 是权威输入；project/process 是候选或受控证据，oracle 从不进入 Agent 工作区。过程事件是明确标记的合成材料，仅证明 Review 阶段的语义边界；它们不能当作实际业务运行或整个 Stop 的证明。

## 复现

先准备 lib/review-task 的锁定依赖。在仓库根运行：

```powershell
node experiments/review-metrics-20261024/run.mjs run --variant=selected --profile=selected-v2.json --freeze=freeze-v2.json --split=all --out=preflight-new
```

默认不调用模型；显式 `--live` 使用当前已授权宿主配置，输出必须是新的子目录。worker 源码哈希、输入、oracle 和提示不符会拒绝，原配置和输入在运行后核验。共同参数：并发2，maxAttempts=2，maxTurns=100，每回复8192，未设置额外累计token或时长限制。生产接入另受原有单项与总截止时间，不能把实验无额外截止混同为生产扩预算。

run 支持 `--cases=` 限定复测；`--reuse=BASELINE_RUN` 只允许在同模型、同 worker、同任务/快照和空append情况下复用合法完成结果，重新核验引用。重跑路径和生成数据不覆盖历史报告。冻结 fixtures 已提交，prepare 命令只用于空实验目录的首次构建。

integration-plan 准备生产工厂/collector 的13个角色案例；e2e-plan 准备真实隔离 Gateway 的 Stop 和厨房从空开发。它们是后续阶段入口，预检或本阶段43例通过均不代表这三阶段已完成。最终状态另见交付报告。

原始 SDK 会话、全部工具轨迹和未压缩结果留在本机 `.runtime-correction/all-metrics-lab-20261024`，不随安装包分发。提交的精确输入、提示、短结果与审计可以核对结论并重新运行，不能重建已经生成的完整逐token轨迹。
