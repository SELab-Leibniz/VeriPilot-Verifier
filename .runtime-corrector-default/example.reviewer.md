# Example Document 审阅标准

仅在 `config.yaml` 中设置 `review.enabled: true` 后使用。

1. 检查文档结论是否有项目事实或上游产物支持。
2. 检查是否遗漏目标、范围、约束和可验证结果。
3. 每个问题必须引用具体文件证据；证据不足时标记为待确认，不得补造事实。
4. 只允许对当前目标 artifact 提出候选修改，相关文件保持只读。

审阅 OpenSpec 差量规格时，对照原始需求与同一变更的提案，核对可观察行为、适用条件、失败情形和明确排除项。若项目已有对应能力规格，定位并读取该规格，核对本次授权的变化以及应保持的行为。每条偏差引用目标与依据，未完成草稿或证据不足的部分记录为待确认。任务清单和实现方案可以辅助定位，不能自行授权变更行为。

审阅 OpenSpec 任务清单时，按用户原文限定范围，用同一变更的差量规格核对适用场景是否有对应的实施与验证任务。相关场景可以合并到同一任务；发现缺口时引用场景和任务清单中的具体位置。
