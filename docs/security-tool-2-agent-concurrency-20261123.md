# security_tool_2 的 RC Agent 并发实跑

2026 年 11 月 23 日 23:02（北京时间），在同一台 Windows 主机上用三个独立的 MA Gateway 和工作树并行运行 `security_tool_2`。样例要求刷新应用列表时应用账号策略快照并保留已加载的 3D 权限详情，选择应用时只加载该应用的详情。此前作废批次的记录单独保留。

## 配置

- 样例起始提交为 `d72abe27c935b878363f4e849bd370b017abf3ea`。三组提交相同任务，使用 RC `d6793ec` 和 MA OpenClaw `2026.7.1-2`。业务模型为 DeepSeek V4 Flash，RC 模型为 DeepSeek V4.1 Flash。每组总时限为两小时。
- 三组实际加载的项目配置与 `.runtime-corrector-default/config.yaml` 逐字节一致，SHA-256 为 `4092541fac3e5291b3c4841b445c6a67ec71d7c43775909f831c9c3b9ace8ddf`。需求帧、文档检查提议和 Stop 终审均开启，终审使用 `until_pass`。
- 对照变量为 Gateway 配置 `plugins.entries.runtime-corrector.config.agentConcurrency`。默认组省略该字段并沿用宿主调度，串行组设为 `1`，峰值 2 组设为 `2`。

## 实测结果

- **默认组**的提议峰值为 **5**，完成 **5/5** 个提议，需求帧耗时 **8 分 23 秒**。宿主收到 1 次需求帧简报，无自动修复轮。公开测试 **748/748**，独立评分 **PASS**（F2P **2/2**，P2P **746/746**）。
- **串行组**的提议峰值为 **1**，完成 **3/5** 个提议，需求帧耗时 **19 分 45 秒**。宿主收到 2 次自动修复简报。公开测试 **749/749**，独立评分 **PASS**（F2P **2/2**，P2P **746/746**）。
- **峰值 2 组**的提议峰值为 **2**，完成 **5/5** 个提议，需求帧耗时 **10 分 35 秒**。宿主收到 3 次自动修复简报。公开测试 **750/750**，独立评分 **FAIL**（F2P **1/2**，P2P **741/746**）。失败涉及刷新时保留 3D 权限详情和五项已有策略行为。

按原生私有 Agent 的运行时间区间统计每个 Gateway 的并发峰值。三组终审 Agent 峰值均为 **1**，最终 RC 判定均为 `NO_DEVIATION_FOUND`。从任务提交到 RC 收尾，三组分别约用 22 分 41 秒、41 分 12 秒、42 分 54 秒。三个需求帧均记录了 `SELECTION_INCOMPLETE`，生成了部分可用简报。本次在宿主记录中核实的需求帧简报出现在默认组的工具结果里。

在相同提议预算内，串行组少完成两个提议。每组各运行一次，独立评分差异的归因仍需要重复实验。峰值 2 组的最终 RC 判定和独立回归结果均按原始记录保留。
