文档与 Skill 的专项受控场景独立于官方成绩；需要注入规则、Skill 或缺陷的情况，只证明模块行为，不混入正式任务分数。正式任务中没有适用对象的模块记为不适用，不能为覆盖模块强迫新增文档或流程。

验证集在调优期间不向优化者暴露候选评分、隐藏测试或可用于修复的诊断。最终验证中一旦查看结果，同批样本已被观察；之后的修改另记为开发迭代，不能继续称同一轮未见验证。

## 四个模块的独立验收

每项先复核当前实现和既有回归；已经满足的行为直接记录证据，跳过重复实现。只有明确复现的问题才进入修改队列。

| 模块 | 触发与正常行为 | 关键反例和边界 | 验收证据 |
| --- | --- | --- | --- |
| 需求基线 | 首次相关动作建立依据，真实新要求按需刷新；无依据变化不反复提取 | 条件、例外、禁止项、PROCESS 与 IMPLEMENTATION 同源不同义务；开放目标；取消及来源变化 | 原文到义务的对应关系、完整来源、唯一身份、原子发布、无变化调用数 |
| 文档纠偏 | 匹配配置且真实写入后核对目标及适用依据，反馈当前偏差 | 写入失败、重复事件、shell 或 patch 写入的事件覆盖、缺前序、源变化、越界 diff | 真实文件事件、读取回执、版本复核、判断、反馈实际进入宿主 |
| Skill 纠偏 | 成功读取并准入后建立看护，按阶段或到期审阅 | 失败读取、截断源、未来步骤、条件未满足、并行结果未齐、重复事件、陈旧笔记 | 原 Skill、实际执行证据、触发次数、反馈额度、送达状态和 watcher 结算 |
| Stop 终审 | 权威业务终态后，在单私有工作区会话中完成适用对象审查及反馈 | 缺证据、错误范围执行、返回失败或抛错、多效果要求、迟到终态、重复派发、取消恢复 | 固定对象分母、原始引用、逐项判断、私有运行结算、真实修复开始及再次验收 |

Stop 先测量当前默认 M08、M09、M12、M13、M15、M16 的真实组件行为。内部标签与 checklist 结构可以重设计，不能将内部分类成功当主要目标，也不能通过遗漏原任务义务获得 PASS 或降耗。每个对照批次开始前冻结策略、模型和适用义务；开启指标不会自动打开 Skill watcher 或文档纠偏，也不会创造额外交付义务。先测当前实现，再对一个真实缺口做小型消融。

确定性工具和生命周期反例要求全部满足其契约。真实语义判断使用预先固定的受控正反例，逐项保存理由、实际回执和失败；组件通过不等于一般准确率或官方任务成绩提高。

任务清单中的 moduleAcceptanceCases 为四模块各列出正触发、负触发、不适用、缺证据、重复、取消恢复、来源变化七类，并为文档与 Skill 各增加一个全部要求满足的完成正例，共三十个场景。完成正例要求 PASS 或无偏差结算、不产生不必要的纠偏反馈及修复额度消耗，用于检查误报。每项包含输入、预期行为、需观察的证据、已有测试或历史轨迹引用及通过门槛。现有引用是待核查的覆盖入口，不冒充本轮执行结果；需要补足的真实宿主组合场景标记为待补 RC 回归或受控验收。

## 基础工具与效率的优化顺序

优先修复会造成错误判断、丢失依据或重复派发的缺陷，再根据实测成本处理重复读取和无效调用。按影响及因果证据排队，不按文件体积或代码行数决定重写。

| 优先级 | 关注点 | 修改必须保留的约束 |
| --- | --- | --- |
| P0 | 身份、来源、完整条件、执行顺序、取消及结算 | 缺证据保持未验证；已观察到错误执行与单纯缺证据分别处理 |
| P1 | 冻结来源、live workspace、文档与 Skill 的读搜分页 | UTF-8 原文、合法范围、哈希、来源变化失效及各协议自己的证据资格 |
| P1 | 同依据重复触发、错参往返、无效导航、重复上下文 | 零调用短路只能用于已核实相同依据；空搜索不伪装成不存在证明 |
| P2 | 有界笔记、会话复用、公共提示和工具描述 | 笔记只是导航；复用不跨身份、策略或变化的证据；保留条件与例外 |
| P2 | 多次整文件解码、分行、字符统计或扫描 | 先测真实 I/O、CPU、返回量与模型采用方式，缓存必须有正确失效机制 |

主要代码入口包括 lib/review-task/source-tools.mjs、live-source-tools.mjs、lib/document-tools.mjs、lib/runtime-v2/skill-care.mjs、baseline-task.mjs、orchestrator.mjs 和 stop-workspace-review.mjs。它们是调查范围，不是已批准的重写清单。

### 状态 证据和恢复

后续执行状态为 planned、ready、running、settled、verified、failed 或 blocked。ready 要求全部依赖通过，输入完整，修改范围及所需阶段授权有效；真实实验还要求预算、并发上限、轮数、重试规则和既有执行入口全部确定。settled 只表示执行结算，不表示评分或验收通过。failed 保存真实失败，blocked 保存缺少的前置条件及可继续的独立分支。

下表是归档索引所需内容，优先引用现有入口的原始输出，不据此新增评测框架或观察器。

| 证据 | 必需内容 | 恢复用途 |
| --- | --- | --- |
| 运行清单 | 任务与样本摘要、模型和端点、宿主版本、RC 开关、产物摘要、累计额度、评分器身份 | 决定结果能否复用，防止跨协议拼接对照 |
| 进度与所有者 | 阶段、owner PID 与命令、宿主 session 和 run ID、最后有效事件、取消状态 | 先确认同一运行是否仍活跃，避免重复派发 |
| 来源与审查回执 | 原始来源版本、固定义务、读范围、执行者与顺序、逐项判断、私有运行状态 | 恢复真实待办，不以笔记恢复旧 PASS |
| 反馈与修复回执 | 生成、返回、送达、宿主接收、实际修复开始、终态及再审身份 | 区分“已反馈”和“已修复”，未知派发不重发 |
| 候选与评分 | 归属明确的最终补丁、摘要、官方原始报告、有效测试集合、缺失和错误 | 保留原失败，完整结算后再作成绩判断 |
| 用量与时间 | 请求数、正用量记录覆盖、缓存分项、阶段及总耗时、未知用量 | 恢复完整账，不把中断或缺失请求算作免费 |
| 下一步记录 | 当前任务、缺少条件、已验证动作、允许重试次数、下一可执行任务 | 由另一 Codex 执行者接续，不重做已完成工作 |

确定的非模型临时读取或文件锁错误最多额外重试两次，分别等待一秒和三秒；仍失败则保存原因并阻塞该任务。身份错误、证据摘要变化、权限拒绝和确定性契约失败不自动重试。未知模型请求、未知反馈派发及仍活跃运行不重发。付费请求默认不自动重试，需在执行前明确可重试原因、次数及预算；每次计为独立尝试，不择优覆盖旧结果。最大调优轮数、无进展轮数和付费并发未定时，真实实验不得进入 ready。

## 质量和成本的报告规则

有有效 F2P 与 P2P 集合时，记录固定分母、逐例通过数、任务等权平均和按测试数加权结果。空集合为不适用；未执行、编译失败、基础设施错误和解析失败分别记录，不能当作正常零分测试或从分母静默消失。整体任务成功率保留所有计划任务，另报评分覆盖率。

TB和DeepSWE的最终质量判断各以六个冻结验证任务为范围。Lite先按固定三例pilot报告两组逐例和宏平均，不宣称它具有独立验证集性质。有有效分组时，候选F2P与P2P均须严格大于无RC对照；两组使用相同预先固定任务和分母，不依据结果删减。非空分母未完整评分时，只报覆盖与已观察结果。官方成绩、逐例及测试数加权结果一并保留，不以跨bench平均掩盖退化。相等或不下降不替代严格提高；满分对照如实记录上限。官方实现将空桶用于内部resolved计算时可返回1，本轮另报其N/A，不把空桶当作有效满分或双提升。

具体地，对 bench b、指标 m 分别固定非空有效任务集合 E(b,m)，每项任务的官方测试数为 n(i,m)，执行组 g 的通过数为 p(g,i,m)。宏平均为各 i 属于 E(b,m) 的 p(g,i,m) 除以 n(i,m) 的算术平均。F2P 使用自己的 E(b,F2P)，P2P 使用自己的 E(b,P2P)，两组共享相同集合。两项均要求 macro(candidate,b,m) 大于 macro(rc_off,b,m)。仅官方原本为空的桶记不适用；未执行、评分失败和缺失结果不能改变 E 或 n。完整性不足时只报告已观察结果及覆盖率。不提供有效两组指标的 bench 单列官方得分是否提高，不宣称双提升。

分别报告业务完成、RC 审查完成、模块适用及结算、官方任务成绩。RC PASS 不替代任务评分，官方满分也不替代模块行为验收。

成本包含业务、提取、文档、Skill、Stop、纠偏业务和重试。缓存读取与创建量分列并计入提供方报告总 token；缺失用量保持未知，不用零填充。模型用时、RC 阶段用时及端到端壁钟分别报告。减少了 token 但变慢时分别陈述，不合并宣称两项提升。

同职责 RC 组件之间的效率比较要求输入、适用范围、正确性、完成度和计量覆盖可比。以冻结的 28071d1 为组件参考，使用固定输入、固定重复次数及交替顺序，每次运行相同完整组件套件。分别比较各完整轮次的 token 总量中位数与套件总耗时中位数，两项均下降才称组件双降耗；逐组件、原始轮次和长尾时间单列。重复次数在获定预算后、看到结果前固定。缺失用量或不完整审查时不发布合格降耗结论。

无 RC 与候选的整任务比较是在测插件净收益，不能要求无 RC 也执行审查；其真实总成本差异照常报告，不作为 RC 组件降耗的替代证据，也不预设候选整任务更便宜。

## 冻结 验证和停止条件

每个候选先通过必要的 RC 行为回归、真实宿主加载和打包契约，再进入昂贵实验。最终验证前运行完整工程回归并核对条件跳过项；不把未配置真实宿主而跳过的用例计作同等覆盖。构建到独立产物目录，不覆盖既有冻结产物。

冻结记录包含源码提交、产物逐文件摘要、插件开关、任务与数据版本、主模型及审查模型和端点、宿主版本、工具描述、额度、评分器及环境身份。任何影响比较条件的变化都需要新运行协议，旧成绩和失败保留。

当前两组一次全样本对照为21×2，即42次任务运行。优先Lite3×2为6臂；TB/DeepSWE的12例最终验证为24臂，6例调优为12臂。旧27例/54臂仅是历史计划。开发迭代、组件实验及重复另计，运行次数不等同于预算或已安排工作。

| 停止或转向条件 | 处理 |
| --- | --- |
| 关键工具或模块回归失败 | 留在相应组件修复，不启动下一轮整任务 |
| 接入需修改范围外代码 | 记录具体前置阻塞，继续其他不依赖事项 |
| 预算耗尽或达到预定轮数 | 保存已完成、失败及在途状态，停止新派发；按已声明的安全终止策略结算 |
| 连续迭代没有新增证据或收益 | 达到预定无进展上限即停止，不自动扩大上下文、额度或模型 |
| 对照指标满分 | 如实记录严格提升不可达，不更换样本、不降低目标 |
| 最终验证不达标 | 交付实际结论与原因；后续修改另启开发周期，不将同批数据继续称为未见验证 |
| 达到全部选定门槛 | 交付冻结插件、验证结果、成本账及剩余限制 |
