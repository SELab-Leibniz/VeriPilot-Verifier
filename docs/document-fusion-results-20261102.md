## 方案和实验边界

保留主目录较新的动态基线、独立审计和评审逻辑。显式复制任务使用 `review.copyFrom` 比较完整已声明原文，语义模型返回 PASS 也不能覆盖真实字符差异。只允许非围栏区域行尾空格/制表符不同，正文、缩进、代码块内空白、换行数量和 EOF 仍严格校验。关闭默认风格规则时尊重该配置，保留来源自身标题，不增加原文未要求的权威声明。

该复制任务的动态基线只提取实际用户复制契约和项目文件权限；完整 benchmark 原文仍是文档 Ground Truth，由原生评审读取和完整比较。普通方案设计任务的材料默认值不变。两组使用相同模型、完整原文、四处预置偏差、提示、预算和验收；共享的工具参数、有限 JSON 回执和关闭后原始审计证据保留修复同时应用到两组，不计作文档能力收益。

仅启用动态基线和文档自动 Hook。由真实主 Agent 写入初稿、接收宿主自动反馈并执行原生修复；驱动程序不写修订稿。Skill、实现检查、Stop、阶段指标和官方 benchmark 执行均关闭。样例保留完整 SWE-bench problem_statement、固定数据集版本、原文哈希、来源和说明，不提供修复答案或测试补丁。

模型为用户授权的 `glm-5.3-flash`，使用指定 Coding API。业务和文档角色 low，基线提取及独立审计 high。有界格式重试默认 12。配置 `examples/document-e2e/dynamic-benchmark-options.json` 分别控制基线/文档评审 20 分钟、Hook/主运行 30 分钟、整轮 40 分钟，均可调整；没有放宽终稿标准或跳过独立审计。

## 两个宿主修复路径的实验证据

原生 edit 会把纯行尾空白替换判为模糊无变化并终止运行。仅提示完整 write 的尝试仍未通过；最终对短且唯一的空白差异提供可见 JSON 空格和精确原生 apply_patch 参数。完整 pytest 原文加额外第五处代码块空格偏差的真实测试通过，主 Agent 实际执行一次原生补丁，无 no-op，全文逐字恢复。原始失败保持不变。

原生 apply_patch 又可能把 EOF 换行处理为无变化。最终仅在正文完全一致时提供精确原生 edit 参数：使用相同正文后缀，分别附加实际换行数量，避免独立截断后缀导致正文丢字符。评审只提供参数，仍由主 Agent 执行，不覆盖宿主终止行为。实际安装宿主的零网络实验和完整 xarray 原文加受控 EOF 偏差的模型测试分别验证：
