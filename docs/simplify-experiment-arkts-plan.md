# RC Stop 第二轮 ArkTS 本机补充计划

第一轮已有 8 条观测绑定 `simplify-experiment-plan.md` 的工作树文件 SHA256 `4e822f278b1b26a95270982d9b283c4646f979e018c320e689b4f3d4cb9b7a65`。续跑及后续计分沿用该 SHA256。本补充计划替代主计划中第二轮样例、S0 和第二轮验收的旧描述，其余条款继续适用。

## 样例和冻结首稿

- 使用本机 `swe-arkts-bench` 的 `security_tool_1` 和 `security_tool_2`。模型 `custom/deepseek-v4-flash`。安装包源提交 `b6700c1`，SHA256 `ec358bfbd52df682ca921a185195293682ee470630f1be011c147e11a480fa9a`。
- 在独立评分区校准。基准提交加隐藏测试后 FAIL_TO_PASS 全失败。再加黄金补丁后 FAIL_TO_PASS 和 PASS_TO_PASS 全通过。校准不通过的样例移除。两个样例均移除时，修复后通过数判为未能判定。
- 每例 S0 关闭 Stop、Skill 和文档纠偏，宿主自然结束，外层限时 120 分钟。冻结工作区提交、会话和补丁，记录 SHA256，另行执行隐藏评分。补丁完全没有实现改动时可重新生成一次，再为空则移除该样例。业务工作区仅使用公开任务输入。
- FAIL_TO_PASS 未全过的首稿作为自然缺陷对象。全过的首稿作为误报对象，并从首稿中撤回一项使 FAIL_TO_PASS 通过的改动，记录撤回内容，用隐藏评分确认该项重新失败后冻结为注入缺陷对象。
- 首次计分前提交 `round-two-inputs` JSON，记录校准、首稿、审查对象和摘要。S0 数值取本机首稿隐藏评分。

## 执行和判定

- 各对象从同一冻结状态开始，A 和入围臂各两次。第一次 A 先行，第二次首个入围臂先行。A、B2 启用真实基线提取和审计，B1、B12 使用原文清单。触发 Stop 后，宿主按反馈续修，各臂采用相同续修上限。工程检查和隐藏评分串行执行。
- 记录首次 Stop 的缺陷检出和误报，最终 FAIL_TO_PASS 与 PASS_TO_PASS 通过数，RC 耗时、token 和覆盖率，以及 A 中基线提取和审计占 RC 总耗时和 token 的比例。
- 最终推荐同时要求第一轮注入检出率和正确实现误报达到 A，第二轮首次 Stop 检出及正确对象误报达到 A，并且每个缺陷对象修复后 FAIL_TO_PASS 通过数的两次平均至少达到 A，PASS_TO_PASS 不退化。缺失或异常隐藏评分标为未能判定。证据不足时保留 A。
