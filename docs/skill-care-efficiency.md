# Skill 看护效率改进

目标：在独立审阅里按需定位原始 Skill 和执行证据，减少重复读取、整份内容披露和错误触发；笔记帮助恢复工作，不替代原始证据。修改仅在 RC 内，MatrixAssistant 和内置 OpenClaw 不修改。

## 工作流与实现

1. **触发**：保留项目、会话和 Skill selection 开关。OpenClaw 通过 SKILL.md 阅读识别 Skill 时，等阅读成功后才建立看护；失败的阅读不视为执行 Skill。内部审阅不会再次触发看护。
2. **采集**：只扫描被选择的 Skill 目录，不遍历或复制业务代码仓。扫描保留稳定内容摘要；先处理 SKILL.md，跳过链接、敏感文件和生成目录。文件/字节预算导致的遗漏明确标为 truncated，禁止用不完整源建立看护。
3. **复用**：OpenClaw 长驻进程缓存最多 16 个扫描范围，以真实路径、大小、纳秒 mtime/ctime、设备和 inode 检查文件版本；添加/删除通过重新列目录发现。变化时重新读内容；读前后版本变化直接拒绝。CLI 跨进程没有此内存缓存收益。`cache:false` 可强制重读。
4. **审阅**：首次请求只披露 Skill 文件清单；完整原文保存在本次审阅的证据文件，模型通过 `rc_skill_care` 查询。`inventory` 分页列证据，`search` 做字面搜索，`read` 逐字符分页读取原文；查询结果包含原始位置和摘要。工具不执行 shell、不修改业务文件、不创建仓库副本。原始证据不截去尾部，分页必须继续读到所需依据完整。
5. **笔记**：`note` 按稳定 key 更新，最多 32 项、每项 1200 字符和 8 个已知证据 ID，按 task/Skill 隔离，使用文件锁与原子写入。位置为 `.runtime-correction/tasks/<task>/skill-care/<skill-id-hash>/notes.json`（以实际 taskDirectory 为准）。每次保存即持久化，压缩前另存检查点。`resume` 恢复约束目录与笔记索引，`notes` 分页恢复正文。Skill、任务依据或会话证据版本变化后笔记标记 `current:false`；不能凭笔记自动 PASS 或恢复旧结论。
6. **看护行为**：保留原有回合间隔、并行工具结果齐备条件、总回合上限、反馈预算及 Stop 强制检查。一次 NOT_COMPLETED 后，相同会话、Skill 和 Ground Truth 的调度重试不再调用审阅模型；先刷新当前源，Stop/看护期限仍强制检查。未执行的未来步骤不当成当前偏差，声称完成时核对前置条件。缺失、超时、读取失败不转换为 PASS。
7. **宿主提示**：复用已兼容的 tool progress UI 通道，显示 `RC · Skill 读取` / `RC · Skill 核对`，随父运行结束、取消或期限到达清理。既有 30 秒保活服务于宿主观察器，不注入 assistant 文本、工具结果或模型会话。仅向宿主回传原有预算内的有效偏差。

`knowledge/skill-care/SKILL.md` 由原生审阅入口直接注入，放在私有资源目录，避免加入宿主的自动 Skill 目录而额外消耗主会话上下文；私有工具仅在所属隔离审阅中可发现，结束后不可调用。Claude/CodeAgent 使用冻结证据路径和 Read/Grep 回退，当前不提供原生私有工具及持久笔记交互，不能宣称同等收益。

## 验证与可复现实验

执行 `node --test test/skill-care.test.mjs` 验证缓存、变更失效、准确的截断标记、分页原文恢复、路径隔离、并发笔记、进程重建恢复和原生工具所有权。

执行 `node scripts/benchmark-skill-care.mjs` 生成 `.runtime-correction/skill-care-experiment.json`。实验只在唯一临时目录建立合成 Skill，不复制代码仓；退出删除自己创建的测试目录。对照比较旧请求内嵌全部源码与新请求清单加一次相关原文查询；另测重复扫描读取字节数和耗时。输出字节数是上下文披露量指标，不是计费 token。

2026-10-28 测量：80 个辅助文件，原文 673,727 字节。首次请求加一次入口原文查询从 708,066 字节降到 10,733 字节（减少 98.48%）。冷扫描 99.42 ms，7 次热扫描中位数 56.56 ms，热扫描每次文件内容读取为 0 字节，摘要一致。读写压力和操作系统缓存影响耗时；这个数字不代表端到端工作耗时。

显式运行 `node scripts/experiment-skill-care-live.mjs --live` 会启动 8 次真实模型请求，单次上限 USD 0.35；默认使用已配置 Claude CLI（可用 `RC_CLAUDE_EXECUTABLE` 指定路径），关闭工具、Hook 和会话持久化。结果保存在 `.runtime-correction/skill-care-live-experiment.json`。这验证原始证据披露方式的模型判断，不是完整 MA 上线实验，也没有宣称完成真实多轮压缩测试。

本次 CLI 使用配置中的 `glm-5.3-flash`，交替对照顺序，覆盖进行中、完成却漏做验证、验证成功、原始记录缺失（附陈旧 PASS 笔记）四种情形。两组均 4/4 正确。输入 token 合计（未缓存 + 缓存创建 + 缓存读取）为 19,150 → 3,214，减少 83.22%；输出为 510 → 551。CLI 报告的估算费用为 USD 0.089874 → 0.054540，并非账单核验。总耗时 60.25 s → 74.98 s，优化组更慢，不能由此宣称模型响应加速。样本小、缓存及服务波动存在；可确认的是输入缩减、重复内容读取消除，以及程序在同一证据调度重试中省下一次模型调用，Stop 与源变更仍重新审阅。

这是针对 Skill 执行看护的改动，不重写独立 Stop/实现覆盖审阅的证据采集协议。插件正常构建产物属于发行打包，不用于复制业务仓库做实验。
