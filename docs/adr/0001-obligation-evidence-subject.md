# 原始义务决定证据主体

真实原生终审中，一个仅要求实现 `next(value)` 的正确产物获得 M16 PASS，却因 M12 一律要求过程记录而无法通过；错误产物的源码偏差也被同一证据边界拒绝。采用原始义务驱动的证据契约：明确的 IMPLEMENTATION 义务可用当前源码及必要依赖判断源码可判定的履约行为，明确的 PROCESS 义务仍需可归属的原始调用和执行结果；旧账本或证据主体未明确时保留保守边界。

这项内部语义调整避免为未要求执行的任务制造额外动作，同时保留实际运行、验收和业务旅程的独立证明要求。源码 PASS 不宣称程序已经执行，不替代 benchmark 官方评分；保留旧策略的实测失败，并用相同原始义务的正反例、混合过程义务回归及真实模型复测检验收益。

后续真实提取中，草稿模式把同一句“实现函数且实际运行验证器”保留成单个 IMPLEMENTATION，显示原句完整性不能代替证据主体的区分。采用现有全文模式分别表示实现与执行义务，共用完整原文和读取凭据，保留各自适用的全部条件；不增加新的分类器或账本类型。单一证据主体优先于草稿中的整句合并规则，模型是否正确遵守仍以同原始输入的真实复测为准。
