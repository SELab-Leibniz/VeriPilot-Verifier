# Skill 义务激活与执行证据分开判断

真实 Skill 组件三案中，实际退出 3 得到 DEVIATION、实际退出 0 得到 PASS；第三案仅有无法匹配调用的结果，却得到 DEVIATION。模型明确指出缺少可归属调用，仍根据 Stop 和完成声明报告确定违规。原始实测与全部用量保留在 `native-skill-live-001`。

旧代码明确要求 forcePartial 的 Stop 将缺失前置动作报告为 finding，与既有过程策略中“真实义务缺少证据应保持 UNVERIFIED”存在冲突。这是内部语义调整，不能当成字段笔误处理，也不能靠删除 finding 获得 PASS。

采用义务激活与执行判断分离的契约。当前完成尝试使原始的完成前置条件需要检查，但不能单独证明动作未执行。无匹配调用、结果或必要归属时保留 UNVERIFIED；实际非零退出或由同一义务、执行者及操作的可归属事件证明的反序，仍可支持 DEVIATION。成功结果仍需真实调用、适用范围和所需先后关系。

优先复用现有 Skill 评审中 `checkerError` 进入 UNVERIFIED 的路径，不新增自然语言动作分类器或状态枚举。该字段已经承载“无法建立可靠判断”的既有行为；证据缺口不得伪装成成功，也不得消费确定偏差的反馈或纠偏额度。具体实现须保留有效兄弟发现，并明确此路径的诊断含义，不混淆为已经证实业务失败。

相同三案、原始 Skill、原始用户要求与验证器保持不变。修复前先核对既有测试保护的真实次序偏差和未验证分支，再做针对性回归与真实复测；不能通过重新标记样例、缩减原始义务或改变官方评分使结果变好。此决策不表示实现或复测已经完成。
