# Stop 多真实大需求样例

本批新增 DeepSWE 1.1 三个原始任务：HTTPX multipart 响应解析、etree XML diff/patch/三方合并、Narwhals 跨后端滚动窗口。沿用原始公开需求、基准提交和任务镜像；原始隐藏评分器在另一个无网络容器中运行，不向业务或终审模型提供隐藏用例、参考实现及前次判分报告。

仅启用 Stop 默认六项指标和必要的单阶段需求抽取；抽取 panel、文档纠偏、Skill 纠偏和写入时实现纠偏关闭。没有注入故障或运行 RC 关闭对照。

## 最新预算

- 最外层时间窗口：24 小时，恢复和排队使用原窗口剩余时间。
- 每次审查：`stopCorrection.maxReviewSteps: 2000`。
- 每次宿主业务修复：`stopCorrection.maxRepairSteps: 2000`。
- Stop 发现偏差后最多自动续修 3 次：`maxCorrectionsPerSession: 3`、`maxCorrectionsPerFlow: 3`；每次结束后重新审查。

三个样例的零模型启动检查均通过。三例真实 Stop worker 的保存结果确认 `limits.maxTurns = 2000`，实际分别用了 26、26、37 轮。时间预算同时对齐宿主、Hook、角色审查、无进展保护和会话锁；修复步骤只按可信的插件自有运行事件计数，不影响新的用户回合。

## 结果

| 样例 | Stop | 自动续修 | 官方新增项 | 官方回归项 |
| --- | --- | ---: | ---: | ---: |
| HTTPX multipart | PASS | 0 | 121/122 | 1272/1272 |
| etree XML diff/patch/merge | PASS | 0 | 52/52 | 15/15 |
| Narwhals rolling window（同版本 CPU 兼容运行库） | PASS | 0 | 103/103 | 10093/10093 |

HTTPX 存在一项实际漏检：不完整的引号边界参数没有按官方验收抛出 `DecodingError`，Stop 仍判了 PASS。其官方二元分数为 0；不能用接近满分的部分分数把它写成验收全部通过。首稿和最终提交相同，没有触发自动修复。

etree 的首稿和最终提交相同，官方二元分数均为 1。Narwhals 在同版本 CPU 兼容运行库下的首稿和最终提交二元分数均为 1。

Narwhals 原始评分镜像中的 Polars 1.39.3 默认运行库要求 AVX/AVX2，本机 x86 模拟容器不支持，导致 `conftest` 导入失败，测试未执行，原始评分记录为全零。保留这两份原始记录；另在原评分镜像上仅增加 `polars-runtime-compat==1.39.3`，配置 `POLARS_FORCE_PKG=compat` 后，对相同提交补丁重新评分。四个官方评分文件的 SHA256 均与原版相同，评分容器仍断网；上表第三行属于该兼容环境的补充结果。

三例的宿主任务、Stop 审查和关闭流程均完成，所有私有工作者已结束，首稿与最终补丁均相同。本批没有触发偏差续修，不能据此宣称大需求故障修复路径已被覆盖，也不能宣称纠偏提升了官方分数。此前的小型正常例与故障修复例单独保存，不混入这批真实大需求统计。

相关配置、原生审查调用、取消隔离、打包和恢复控制共 34 项定向检查通过；未重新验证整个仓库测试集。冻结的 246 个插件产物文件和 314 个执行源码文件均复核无变化。已扫描 3808 个源码及证据文件、13 个压缩包成员，未检出本次提供的六套真实凭据。
