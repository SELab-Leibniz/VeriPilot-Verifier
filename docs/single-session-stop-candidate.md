# 单 Reviewer 分批 Stop 候选

基线为 `28ef939cbde79c369b4eafb9d92446898a6cce42`。本候选使用一个原生 Reviewer 会话，保留同一次 Stop 的原始要求、执行记录、原件身份和公开裁决。宿主继续负责会话和压缩。

## 待证假设

1. 先登记直接及间接采纳的权威原件，再按其实际内容分批保存带坐标的义务，可避免把未提取的强制附件随主文一起封存。
2. 同一份原件可用稳定身份和精确字节页重复读取。超长物理行不会阻挡提取，批次上限也不会变成整份规范的义务上限。压缩后 Reviewer 可从产品的任务记录找回待处理原件与已提交结果。
3. 只有已审定的范围可以公开无偏差。缺少当期执行凭据应公开为未核实；同一原件上不同义务分别审定，旧轮回执不能证明当期执行。分批仍依赖同一宿主会话的时间与上下文容量。

## 回归目标

通过生产 Stop 入口验证一般项目的强制附件、长行中独立坐标、多于 256 项的连续批次、重复批次、不完整读证及未处置项。分别核对公开状态、原清单、按项结果及原始引证。资格材料使用单独构造的本地项目。保留既有路径/行引用、现有配置、普通 source_read 和宿主的原生审核工具。
