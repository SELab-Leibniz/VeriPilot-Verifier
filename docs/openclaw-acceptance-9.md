# OpenClaw .9：评审等待、活动传递和进度显示

日期：2026-09-17。适配 OpenClaw `2026.7.1-2`。

## 根因

受影响会话于 14:17:58 启动，执行模型为 `ark-work/ark-code-latest`，运行时配置为原生 `openclaw`，评审模型为 `review/glm-5.3`。第一次执行工具前进入纠偏任务初始化，两路提取分别用时 150 秒、211 秒，随后核对用时 265 秒。提取和核对最终成功。

此前只有受控执行器将评审子运行的活动同步给父运行。原生 Hook 模式同步等待同样的评审，却没有这条活动关联：宿主看到父运行最后进展仍停留在 `tool:read:ended`。14:24:29 被判停滞，14:24:44 触发 `abort_embedded_run`；14:26:03 基线核对才完成。历史出现缺失工具结果的修复标记，任务无法继续。延长总运行超时无法消除这一误判。

另一个使用 GLM Flash 的先前会话经历三轮完整面板失败，每轮接近 10 分钟。已耗尽预算的同一工作在下一个工具事件中重跑，会放大等待。受控执行器虽然保存了细分进展，却只向聊天发送粗略阶段文字。

## 修复

- 原生评审通过准确的父 runId、sessionId 和评审 runId 关联真实诊断活动；不转发其他任务、已结束的评审或反射回来的插件活动，不增加定时保活。
- 父运行终止、生命周期出错或进入宿主恢复时，取消对应评审；关闭监听器，迟到事件不能延续父运行。
- 原生评审开始及受控模式的阶段切换会发出简洁进度，不暴露内部评审内容，不提前公布候选完成回复。
- OpenClaw 评审预算耗尽具有明确错误码；面板全部因预算耗尽失败时直接进入既有增量提取路径，不再自动完整重跑同一面板。普通短暂失败仍保留原有有界重试；失败不冻结不完整基线，也不授予通过资格。
- GLM 低推理强度兼容提示覆盖 `glm-5.3-flash`；它是提示，不是硬 token 上限。
- 本机保留用户指定的执行 `ark-code-latest`、评审 `glm-5.3`，将执行 provider 接入 `runtime-corrector-supervised`，使完成验收和自动纠偏由同一控制器负责。

## 验证

- 完整回归：642 项，640 通过，0 失败，2 项 Windows 专用测试跳过。
- 固定宿主契约：使用真实 OpenClaw 诊断事件接口，确认原生评审活动更新宿主停滞检测所读取的父会话状态。
- 回归覆盖：其他任务及迟到事件隔离、反射循环防护、父运行取消、监听器清理、预算耗尽不重复面板、增量需求仍保留、既有短暂故障重试。
- 独立真实模型验收：`.9` 配合 `glm-5.3` 的手动压缩、超限自动压缩、续聊全部通过，摘要保留早期约定，原历史和纠偏状态保持。
- 已备份安装及配置，安装 `.9` 后完整重启 Gateway，健康检查通过。已在原业务会话恢复任务，沿用原 taskId、基线版本 1 和 epoch 1；业务成果以该会话后续真实评审和构建证据为准。

## 范围

本修复解决有实际评审活动却被误判卡死的问题，以及相关进度和重复等待问题。模型实际速度仍受接口影响；它不会将无活动的评审永远保活，也不会把构建、设备或外部服务的真实阻塞标为通过。业务应用最终完成与插件运行恢复分别验证。
