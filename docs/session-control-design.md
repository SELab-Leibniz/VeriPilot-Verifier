# Runtime Corrector 项目与 Session 开关设计

项目配置决定是否允许运行 RC，以及新登记 Session 的默认状态；本地会话配置保存每个 Session 的选择。控制层只负责准入、保存和启停，沿用现有需求提取、Reviewer、指标、PASS 判定和预算规则。使用方式及 UI 接口见 [项目与 Session 开关](session-control.md)。

## 最小改动范围

本期作用于已经支持的 OpenClaw `2026.7.1-2`、MatrixAssistant 原生目录适配和 OpenClaw `2026.10.3`。其他宿主的零配置行为保持原状。宿主的会话页按钮由接入方实现，本仓库提供认证后的读写接口。

保留以下必要改动：

1. 项目 YAML 增加根级 `enabled` 和 `sessionDefaults.enabled`，两者缺省均为 `true`，兼容版本 1 和版本 2 的既有配置。
2. `.runtime-corrector/sessions.local.yaml` 保存各会话的单个布尔值；首次生命周期登记时保存项目默认值，包括默认关闭的情况。
3. 当前 Session 的状态查询、明确设置开启或关闭，以及用户命令，都通过同一套项目解析和控制逻辑。
4. 关闭时取消 RC 工作并拒绝迟到结果；重新开启复用原作用域任务、基线和预算。
5. 保存时使用短锁、重新读取合并和原子替换，避免 A 的设置覆盖 B。

不增加文件监听器、`apply` 步骤、待接受配置快照、独立操作账本或新的宿主身份实体；不接入旧版停止业务、更新需求和复验等控制路径。

## 配置职责和优先级

`.runtime-corrector/config.yaml` 保存项目总开关、首次登记默认值及原有纠偏功能配置。`.runtime-corrector/sessions.local.yaml` 只保存本地会话选择，加入 Git 忽略规则。任务和预算继续使用现有运行目录，项目绑定和作用域继续使用宿主状态目录。

实际准入顺序是：宿主插件可用，现有身份和项目权限校验通过，项目配置存在且有效，项目总开关开启，当前 Session 选择开启。Session 选择覆盖初始默认值，不能覆盖上层停用；开启后仍按各功能自己的设置工作。

已有会话的默认选择会物化保存，后来修改默认值不改变该记录。删除本地记录后会再次采用项目默认值；这个动作不创建新任务，也不能清空已消耗预算。reset/new 产生新的 `sessionId` 后，使用新记录和新会话原有的生命周期规则。

项目总关闭保留各会话的选择，恢复后按各自选择工作。真实项目切换仍按现有作用域边界处理，不能因为开关恢复而接回其他项目的旧任务。

## 身份和存储

项目目录本身限定设置范围，复用准确的 `agentId`、`sessionKey`、`sessionId`，并用宿主状态目录命名空间区分 profile。记录键为 `s_` 加身份摘要，兼容现有受控 YAML 读取器；不使用会话标题匹配身份。

本地设置的只读加载不创建或改写会话文件，不创建任务或 Reviewer。首次生命周期登记或明确设置时才保存记录。单个 Session 的变化只使对应 RC 运行失效，不因整份文件改变而取消其他会话。

文件是会话选择的唯一持久化来源。内存只缓存执行状态；重启重新读取文件，沿用现有持久化作用域和任务。非法 YAML 或身份数据返回错误，不自动覆盖；合法手工修改在下一次已有生命周期、状态查询或提交／派发检查点读取后生效。

## 启停执行边界

关闭与结束项目作用域分开。普通关闭使用现有取消机制停止 Reviewer、Stop 等待链和待派发反馈，同时保留持久化 scope；不开新任务或纠偏 epoch，不将业务任务标成完成或失败。业务执行、审批和宿主已接受的工作继续由宿主管理。

停止新工作后，复用现有 `enabledRevision`、取消信号和捕获的运行身份检查迟到结果。工具结果、评审提交、反馈和续作准入必须拒绝关闭前的旧运行；同一宿主 run 再次开启时，不能误用已取消的 Stop 检查。

旧取消回调只能处理旧控制器，不得取消重新开启后的 Reviewer；主动关闭的回调不得把任务终结为 `STOPPED_UNVERIFIED`。真正超时和业务取消仍遵守原终结规则。预期的开关取消也不应转成 `RC_REVIEW_UNVERIFIED` 反馈或增加检查器失败次数。

重新开启只恢复准入，在下一个正常检查点继续处理当前依据。不重放关闭期间的逐条工具事件或旧纠偏，不将历史评审结果当作当前文件的通过证据。关闭期间仍处理项目切换、reset、session_end 等身份和生命周期元数据。

## 用户入口和生效时机

用户命令为 `/rc-session status`、`/rc-session on`、`/rc-session off`。UI 使用认证后的 `runtime-corrector.session.get` 和 `runtime-corrector.session.set`；设置参数是目标布尔值，重复请求保持幂等，不提供反转状态的 toggle 操作。

UI 和命令保存后立即执行状态协调，关闭无需等待正在运行的评审排队结束。手工编辑文件不承诺保存瞬间取消；需要即时停止时使用关闭命令。状态返回保存的选择、实际启用状态及上层阻断原因，UI 不单独根据文件中的一个布尔值猜测运行结果。

控制文件是本机管理配置。UI 和命令沿用宿主认证，文件编辑本身不证明人类身份；本期不建设防同权限程序篡改的系统边界。现有 `stopCorrection` 任务内规则保持不变，也不伪造用户消息来绕过它。

## 验收不变量

- 默认配置全部开启时，既有纠偏判定、反馈和预算行为保持一致。
- A 关闭后不再提交或派发新的 RC 结果，B 的评审、需求和预算不变。
- 同一作用域反复开关后 taskId、需求基线、纠偏 epoch 和已消耗次数不变。
- 关闭不停止宿主业务，旧回调不影响重新开启后的评审；真正超时仍按原规则终结。
- UI、用户命令和合法文件修改最终得到同一开关状态；保存失败或配置错误明确返回，不覆盖其他会话。
