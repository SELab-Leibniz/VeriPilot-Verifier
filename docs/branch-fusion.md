## 冲突决策

`openclaw/runtime.mjs` 保留 A 的 post-run 调度，不恢复 B 分叉时仍有的原轮 stop-chain。`orchestrator.mjs` 保留 A 的真实用户来源与延迟更新，以 B 的单会话替换旧分类/分组派发。`production-stop.mjs` 使用 B 的结算方式，同时保留 A 的完整范围清单、基线版本和空范围未验证状态。控制页和取消后的 runtime.dispose 均保留。

融合补充：把 A 的分类一致性检查提为独立模块，供新会话和开发期旧协议共用；空的可选阶段列表拒绝所有阶段；原消息在选范围期间变化时，在扫描交付物之前停止；补齐 B 的发行包文档缺项。逐项原始证据、过程证据归属和 M16 生产链证明仍必须验证。

## 实验预案

评价顺序为正确性、完整性、效率和体验。不能用更少的原始义务、放松证据、隐藏超时取得改善。失败和未验证分别记录。

1. 两个原分支先运行完整回归。初次并行运行的负载可能影响墙钟断言，对失败文件单独复验，保留两次日志；持续存在的问题不能归因于负载。
2. 同一安装宿主 OpenClaw 2026.7.1-2、相同环境模型和审查窗口，分别加载每个分支构建产物。每例独立进程及状态，不修改安装。冻结已知要求及代码、Git 基线，以程序事件激活审查。初始代码和事件为夹具，不冒充真实业务模型执行。
3. 固定六类真实模型案例：正确实现 PASS；项目外原始契约错误 DEVIATION；隐藏依赖错误 DEVIATION；没有原始执行证据 UNVERIFIED；完成后附可选建议但实现错误 DEVIATION；六项独立函数全部 PASS。每项按原对象判断，全部对象保留才算命中。
4. 记录每个样本的代码摘要、分支提交、实际模型、判断、未验证/错误、总耗时、私有审查启动/结束数、工具数、读取数、拒绝数及宿主 token 计数。含缓存 token 不能换算账单。接线失败不计模型样本；模型超时必须计未验证，不能择优删除。
5. 融合后的额外机制验收：新需求进入同一任务的下一轮清单、可选建议不能缩小范围、真实等待/阻塞合法、空阶段与无对象不能 PASS、修改原消息时停止、取消/未知派发/额度与队列保留。浏览器验证目标会话、任务历史、指标范围、并发页面状态和窄屏。
6. 用真实隔离 Gateway 验证融合后的运行结束再审查、独立修复与新 Stop，交叉核对可信启动、扣量和排队任务。工程回归和真实模型实验分别报告。

复现入口：`scripts/evaluate-branch-fusion.mjs --live --source <checkout> --output <new-directory> --host-root <installed-openclaw> --case <correct|external|hidden|execution|optional|six>`。只从环境读取供应方凭据。初次接线未启动模型的记录保留为夹具错误。完整结果与限制随实验结束补充。

这组六类是配对小样本和反例验证，不是总体准确率或延迟保证。分支实现和审查提示一起变化，不能把所有速度变化归因于会话数量一个因素。未进行安装到桌面 MA、Electron 端到端或执行中途崩溃恢复测试。

## 已完成的对照结果

2026-10-28，实际安装宿主 OpenClaw 2026.7.1-2 / GLM-5.3-flash。每个版本运行相同六类案例，每类一次，共 18 个有效模型样本。每例保留独立进程、原始输入、模型会话、程序回执和结果；前两轮没有激活审查的接线失败及融合开发期的一个试跑没有纳入正式矩阵。模型阶段的超时仍纳入结果。机器可读明细见 `branch-fusion-results.json`。

- A：预期结论完整命中 3/6；11 个预期对象中提交了 4 个正式对象判断；13 个私有审查启动全部结算；总耗时 684.895 秒，100 次工具调用、57 次原文读取、13 次工具拒绝。
- B：完整命中 6/6，11/11 个对象；6 个私有审查全部结算；353.249 秒，43 次工具调用、22 次读取、0 次拒绝。
- 融合版：完整命中 6/6，11/11 个对象；6 个私有审查全部结算；370.439 秒，46 次工具调用、23 次读取、1 次拒绝。

A 的外部契约案例未能给出预期的已确认偏差；没有执行证据的案例产生了不应确认的偏差；六函数案例达到审查截止、保留未验证，均没有删去。其余三个案例与预期一致。B 与融合版对正确实现、外部契约错误、隐藏依赖错误、缺少执行证据、完成附可选建议、六项函数均给出预期的逐对象结论。

相对 A，融合版本组总耗时减少约 45.9%，会话从 13 次降到 6 次。两者共同命中的三个案例耗时从 239.107 秒降到 170.650 秒，约减少 28.6%；这一补充比较避免把 A 的超时全部当成正常性能成本。相对 B，融合版本组总时间增加约 4.9%，工具调用多 3 次。融合没有在本组所有效率指标上超过 B；结构化范围校验和更完整的需求行为有一定成本。

宿主提供的总 token 计数（含缓存）分别为 385142 / 248424 / 298972。它们不是独立核对的账单用量，不换算费用。每类仅一次采样、执行顺序和本机负载不同，且融合批次中包含一项只影响范围字段序列化的修复；每例保留源码摘要，不宣称统计显著或普遍延迟提升。

## 语义与体验验收

`evaluate-fusion-semantics.mjs` 使用每个分支实际支持的提取协议和程序入口，三类确定性案例单独计分，不计入 18 个模型样本：

- 两轮用户要求：A 与融合版保留 quicksort 并追加 insertion sort，第二轮正式审查两个对象；B 仅保留 quicksort，却以一个对象发布 PASS。
- 显式空阶段：A 与融合版保留全量对象及排除原因，返回 `STOP_STAGE_METRICS_UNDECLARED`；B 虽未宣称通过，却只给出 `NO_CURRENT_DEVIATION`，没有范围清单。
- 测试源码及执行义务：A 与融合版保持 M12=3、M16=1；B 不支持结构化实现归属，把测试源码也投射到 M16，得到 M16=2。

三类实验分别为 A 3/3、B 0/3、融合 3/3。首次 B 的需求实验因发送新协议才有的 `implementationRole` 被拒绝；已按各分支 schema 修正夹具并重新运行，以上结论来自修正后的正式记录。

融合后的关键协议回归 54 项及最终分类/读取/CLI 回归 39 项通过，相互重叠不相加。包括原消息在选范围时变化的提前围栏、必需输入与可选建议、真实等待/阻塞、合法空范围、部分回执、外部和链接文件、证据过期、执行证据和 M16 证明。

真实 Chrome 控制页检查通过：目标会话、跨会话隔离、任务领取后的持久历史、未知回执、逐指标对象、103 会话分页/搜索/深链接、旧请求竞态及窄屏。三宿主构建通过，发行包 17 项检查通过；发行包开发文档断链已修正，开发进度和实验材料继续不打包。只读安装宿主的 11 项契约检查通过，无跳过。

另修复了首次范围结果含 `undefined` 字段、持久化重读后字段消失的问题；`runtime-v2` 的 34 项复验通过。两个原分支的并行全量测试均有墙钟或单文件时限失败，相应原始文件单独复验通过；B 的发行文档断链是持续存在的实际问题。原始失败日志保留，没有改写成成功。

最终全量运行覆盖 147 个文件、1744 项：1721 通过、22 跳过、1 项失败，无文件超时。唯一失败来自未改动的 `openclaw-supervised.test.mjs`：1 秒总预算可能在进入最终发送前耗尽，无法满足夹具所期待的 UNKNOWN 发送状态。该文件单独复验 37/37 通过，未放宽原断言或时间窗口。全量原始日志为 `.runtime-correction/fusion-final-suite.log`，复验为 `fusion-supervised-recheck.log`；不将这次全量运行表述为零失败。

## 真实宿主的运行后纠偏闭环

实际鉴权的 `sessions.create` / `chat.send` 创建并执行业务首轮，使用真实会话存储、宿主终态、插件派发和可信启动观察。在隔离项目内，通过仅用于实验的本地插件，在原轮真正结束前把 `accept(value)` 的正确实现一次性改为错误的原值返回。错误由程序故障注入产生，不声称是业务模型自然犯错；宿主终态、审查、独立修复与计量没有注入替代实现。

最终记录 `.runtime-correction/live-native-loop/2026-10-28T05-41-30-197Z` 取得：

- 真实原轮结束后，首个 Stop 判定 DEVIATION；之后才独立派发修复。审查前和派发前计数均为 0，真实业务启动后为 1，最终仍为 1；只有一份 USED 准入。
- 修复模型实际改正 `app.mjs`，新 Stop PASS。原始三个 M16 对象在偏差与最终通过中保持同一身份，分母没有缩减。
- 一个来源提取私有会话、两个 Stop 私有会话，均已 SETTLED；原始与修复业务运行由真实诊断交叉核对，共 20 次模型调用开始事件。最终只读复验记录属于这次真实修复，未为复验再领取修复额度。
- 独立程序验证 0、7、-2 的实际返回值正确。调度状态最终 IDLE。关闭 Gateway 后，离线审计继续 PASS。
- 不调用模型，临时改变已审源码使官方报告 STALE、审计拒绝通过；恢复原始字节后重新 PASS。证据为 `audit.json` 和 `stale-source-audit.json`。

两次实验接线不足保留在原记录：旧脚本预置的终态不属于实际 Gateway 运行，新的调度器因不能获得可信终态而未启动任何模型；第一次故障插件缺少宿主的包入口声明，没有实际注入错误，真实正常业务首轮仍完成了零纠偏 PASS，其离线审计单独通过。修正插件声明后先进行零模型接线检查，之后才运行上述有效闭环。没有改写历史 `complete: false` 为成功，也没有通过重复调用模型修饰历史结果。

两个实际首轮实验在 Gateway 已关闭后，独立嵌入 Node 进程仍有滞留。核对 PID、父进程、启动时间、完整命令和已通过的离线审计后，仅结束这些实验的拥有进程，记录在各目录 `process-cleanup.json`。退出后的离线审计仍通过；不能据此宣称嵌入宿主总能自行退出，也没有把滞留归因于某个生产组件。未操作桌面 MA 的进程、配置或安装目录。

复现真实故障闭环：`node scripts/evaluate-native-stop-loop.mjs --live --initial-turn --inject-defect --host-root <installed-openclaw>`。离线核对：`--audit <run-directory>`。汇总脚本 `scripts/summarize-branch-fusion.mjs` 只读取已保存结果，重建 `branch-fusion-results.json`，不启动模型。

## 当前选择

选择融合分支：它在本组保留 B 的审查结论与单会话结构，同时恢复 A 的跨轮需求、正确分母、范围解释和任务控制体验；相对 A 提高了已知案例的审查完整性和效率。相对 B 的约 5% 样本耗时增加需如实保留，不能宣传为所有维度都更快。

后续扩大样本时应优先测长任务、并发编辑和供应方超时；不为争取更好数字删除原始对象、证据证明或失败样本。当前实现保持独立分支和构建产物，没有安装或重启用户的 MatrixAssistant。
