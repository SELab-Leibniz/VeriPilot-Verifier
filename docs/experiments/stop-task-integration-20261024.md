# Stop 单项 Review 首版接入与交付验证

日期：2026-10-24。分支：`codex/stop-review-integration`，从 `81a5b9e` 开始接入。插件版本：`1.9.1-openclaw.11-session-projects.11`。

结论：冻结已经对照实验的 Prompt，先交付有明确职责的单项审阅。生产 OpenClaw 默认选择新的 task 传输；原 Stop 编排和 collector 继续负责分类、验收分母、逐项保存、失败隔离、缓存和纠偏续作。代码接入、隔离验证和安装包已准备；没有替换正在运行的 Gateway，没有干预原项目或原 session。

## 接入与回退

新传输支持当前任务完成时的 M01、M05 单个冻结对象，以及 M12 的源码实现与运行证据两种独立子证明。M01 使用已验证的 v1 提示，M12 源码使用 v2；M05 和 M12 运行证据使用基础提示。没有追加总评 Agent。

分类、Ground Truth、Skill、PROCESS、阶段完成、适用性待判断及其他指标沿用 native 路径。只有新传输涉及的指标逐对象分派；其他 native 指标保留同源组批。不会枚举条件组合。M01 对象覆盖通过不能变成整个文件质量通过。

大输入的处理是：保留选定义务、公共条件与显式依赖的原文，将必读基线按准确 UTF-8 字节分片；文件和过程事件留在只读快照中按需检索。初始提示不展开整个过程索引或文件表。模型提交短判断与 citeId，程序获取引用原文和位置。独立 Pi 会话复用原生 compact、旧轨迹检索与请求前健康检查。没有扩大父截止时间或删验收条件。

单项失败保留 UNVERIFIED，并给出白名单失败类型及该项结果位置；已有成功项不依赖失败 Agent 正常退出。迟到结果、取消、GT 或源码变更不能升级为 PASS。缓存身份包含协议及提示摘要，仍核验读取依赖。现有缓存最多128个依赖的限制保留，大项目可能重新审查。

配置 `stopReviewEngine: "native"` 可恢复旧审阅传输。安装条件、源码范围和其他边界见 [接入说明](../stop-task-review.md)。

## 真实模型：生产工厂与 collector

运行入口是生产 `createOpenClawReviewerFactory` 与 `collectReviewItems`，没有注入假 worker，禁止 native fallback。使用已授权的 `custom/deepseek-v4-flash`，只读此前冻结的厨房/花店 review 输入，未重新生成业务应用、未跑完整业务任务或 Gateway。

`stop-integration-live-04` 的六个新结果，加上 `live-02` 已完成且未重跑的 K09，共七个对象。独立核对源文件、范围、引用原文与哈希，七项的判断和诊断均与对应基准一致：

- K01 / M01：PASS，烹饪义务的需求分解覆盖齐全，仅证明分解覆盖。
- K04 / M05：PASS，正式验收单元覆盖齐全，不代表这些业务测试已经执行。
- K07 / M12 源码：PASS，源码子证明成立。
- K08 / M12 源码：DEVIATION，`cmd_cook` 检查足量后原样保存，未扣减库存，导致烹饪不消耗食材。
- K09 / M12 运行证据：UNVERIFIED，源码不能替代缺失的实际运行证明；该结果已正常收集，并非执行器崩溃。
- F08 / M12 源码：DEVIATION，商品卡片一直显示 emoji，数据没有图片 URL，列表加载状态也不能实现逐图片加载占位。
- F07 / M12 源码：PASS，八个权限声明齐全，只证明声明，不证明动态授权或实际运行。

合计4个 PASS、2个 DEVIATION、1个正确的 UNVERIFIED；七项反馈中最大1419字节。引用位置与程序提取原文一致。它们是选定对象/子证明，不是整个指标分母或项目的验收结果，也不是统计意义上的准确率估计。

详见 [逐项语义与引用核对](stop-task-integration-20261024-semantic-audit.json)。

## 复杂输入：只测冻结的一个 Stop 对象

使用之前保存的 `complex-preflight-01` 快照，不访问当前原项目或 session。原始 M01:f1 的 AGENT_INFERRED、SOFT、hard=false 等归属不变，未改成 HARD 实现闸门。完整180条 canonical claim 保留；选中的 f1 加79条公共条件共80条，逐字典与历史必读材料核对一致。历史必读材料45,655字节，67个源码文件159,029字节，无删条件或扩预算。

生产单项传输用4个模型回合、11次工具调用，在18,388毫秒完成；父上限仍为120秒。初始 Prompt 4156字节，读取70,984字节，最大上下文健康估计83,439 tokens，低于原模型204,800窗口。无溢出、无 compact 触发、无重复行读取；反馈705字节。累计输入68,834 tokens、输出1569 tokens，累计输入不是峰值上下文或实际计费金额。

独立核对确认该 PASS 支持“候选需求覆盖图片/名称/价格及加载占位”这一分解义务。它不证明实现、运行或79条公共条件分别全部通过。此前失败的四对象套件没有整体重测，不能把本次结果说成原来的0/4全部修复。

详见 [复杂单项审计](stop-task-integration-20261024-complex-audit.json)。

## Stop 续作、对照与回归

Native Stop 隔离闭环覆盖两个宿主版本 `2026.7.1-2` 和 `2026.10.3`：有缺陷 A 经一次纠偏到 PASS；原本正确 B 保持 PASS 且无纠偏。使用真实 Python 子进程与原9条业务断言；宿主、reviewer 和修复行为是确定性 doubles。它验证续作协议和结果落盘，不是完整真实模型修复效果实验，也没有操作运行中的 Gateway。

全纠偏关闭的 K08 对照由生产事件入口返回 `V2_DISABLED`，没有模型调用和反馈；启用后的同源 K08 给出有依据的扣库存缺陷反馈。这说明增加了有效缺陷反馈，不能据此估计整个业务任务的修复收益，也不是保持 V2 其他部分活跃的 Stop-only 消融实验。见 [关闭纠偏对照](stop-task-integration-20261024-disabled-control.json)。

最终全量回归 `npm test -- --test-concurrency=2`：1188项，1179通过、9跳过、0失败，耗时172.9秒。较早并发4的全量运行有一项旧 SessionEnd 1200毫秒 watchdog 在调度压力下观察到1327毫秒；原文件隔离复跑7/7通过，随后降低测试并发的全量通过。未放宽产品或测试时限、未删断言。

新增机制检查覆盖：单项路由和原路径兼容、条件范围、源码证据、原文分片、真实目标前缀、schema、取消/过期/源码变更、失败原因与结果位置、保密错误处理、缓存身份、collector 部分成果，以及独立依赖的安装包构建。

## 接入时发现并修复的问题

保留失败运行，避免只报告最后一次成功：

1. `live-01`：宿主模型元数据缺失 cost，SDK 访问 `cost.tiers` 失败；提供未知费用的零结构占位以兼容，不能把零值解释为免费。SDK 在响应 usage 解析时计算费用；失败轨迹的零用量不是零请求或零计费的证明，早前“请求前失败”的说明不准确。
2. `live-02`：实现角色报告错误携带 Stop-only 字段；一个受限文件名使准备阶段过早终止。修复角色格式，并继续拒绝受限文件，同时让其他允许的业务源码可审查。K09 当时已完成，后续复用。
3. `live-03`：模型已有正确偏差，但实验入口给 implementation collector 传入 Stop 分类，触发收集拒绝。修复实验入口；生产实现审查调用原本不传该分类。
4. `live-04`：六个对象全部完成，随后独立核对。最后的失败诊断透传补丁晚于这些已完成模型运行，由兼容机制测试验证；复杂单项真实运行使用该补丁后的代码。

源码和证据哈希、原始本机轨迹位置、测试计数及结果汇总见 [机器记录](stop-task-integration-20261024.json)。原始轨迹留在仓库忽略目录 `.runtime-correction`，不随插件分发；引用核对与本报告另存并提交。没有将原始模型配置或认证值写入报告。

## 首版边界与交付

Prompt 仍有提升空间：过去实验的 F10 未知商品 ID fallback 漏报尚未解决。分类、Ground Truth 和其他 native 指标的上下文风险没有被本次局部接入全部消除。原生提前 compact 与历史检索有机制验证，本次复杂单项未逼近到触发 compact，不能把它当作压缩后的长任务实测，更不能承诺任意进程崩溃后的自动恢复。general Stop 与后续 implementation reviewer 仍可能存在原有重复职责。

发布产物位于 `dist/runtime-corrector-openclaw`，根 package-lock 可用于目录内 `npm ci --ignore-scripts --omit=dev`；标准 npm tgz 默认不包含根 package-lock，不承诺所有 tgz 安装途径都按该锁安装传递依赖。精确 SDK 版本及 undici 8.12.2 覆盖同时写入根 package。最终安装、模块加载、包摘要记录在 `dist/stop-task-integration-delivery.json` 和 `dist/SHA256SUMS`。没有新增在线运行时安装步骤。

首版验收结论是：支持范围内的单项模块已经接入生产调用路径，能产生可定位的有效反馈，失败项可独立保留，既有 Stop 续作协议通过隔离闭环验证。保留 native 回退，冻结提示，后续以真实漏报案例增量改进。
