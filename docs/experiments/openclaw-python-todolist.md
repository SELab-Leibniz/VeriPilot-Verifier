# Python TodoList：真实 OpenClaw 与模型验收

实验分支：`codex/file-transaction-deltas`。全部业务文件、Gateway profile、插件安装和会话均位于新建测试目录；原 Gateway 与配置未修改。

## 链路与证据

入口是 `scripts/diagnostics/openclaw-python-todolist.mjs`。它调用实际安装的 OpenClaw `2026.7.1-2`，启动独立 loopback Gateway，并通过 `sessions.create`、`chat.send`、`agent.wait` 执行真实原生会话。执行模型和各审阅角色使用独立会话，均为用户授权的智谱 Coding Plan `glm-5.3-flash`。使用 [智谱 OpenAI 兼容接口](https://docs.bigmodel.cn/cn/guide/develop/openai/introduction)，没有注入 reviewer factory 或用测试退出码代替模型审阅。

模型读取实际 `todo.py` 和 `test_todo.py`，修复预置的 `complete` 持久化错误，实际运行九项 Python 单测及 add/list/rename/complete/reopen/delete。测试文件始终与仓库原件逐字节一致。产物审阅与 Stop 审阅均调用真实模型；Python 测试提供实际执行证据。

诊断只对**生成的隔离插件**加入原有 journal fault 回调与第一个报告文件写完后的观察点，并把检查点间隔设为 4。观察点不生成状态、审阅结论、提交或输出。被终止的是执行实际 hook 的 Gateway 本身。生产检查点默认值和宿主安装未改变。

每次恢复重新启动同一个隔离 Gateway，再向原生会话提交继续消息，沿用原任务及业务操作 ID。检查已提交 operation ID 唯一、历史评估仍存在、应用回执不重复添加数据、输出使用原 round ID，以及检查点数量恢复到两份以内。这验证由真实宿主 hook 触发的文件恢复；不承诺 OpenClaw 自动重启中断中的模型请求。完全相同 hook 的重复投递另由自动化恢复测试覆盖。

## 本次发现并修复

1. 原生 Stop 构造决策上下文时丢失规则摘要，且未保存证据采集回调。内部回执可以 PASS，但对外报告无法确认该结果与当前文件一致。现在保留上下文、源码指纹和规则摘要，并统一使用 `decisionGuard` 的默认 generation/cancel epoch。
2. Gateway 重启后内存中的产物路径为空，后续仅执行命令时可能只绑定到配置文件。现在从已验证的原生会话当前分支恢复曾写入的文件路径，再采集这些文件的**当前**指纹；历史内容不授予当前通过资格。复用原有 `restoreBinding` 路径恢复逻辑。
3. 工具 hook 之外的直接事件追加遇到半截 JSON 时，会把新事件拼进坏行。直接追加和已提交事件投影现在共用现有文件资源锁，先按字节修复不完整尾部再追加；普通路径仅查看最后一个字节，不反复读取整个历史。回归同时覆盖半个 UTF-8 字符与并发追加。
4. 当前原生终止审阅没有产生有效结果时，异步回执曾可能沿用任务上轮 PASS。现在回执必须绑定到本轮 Stop 决策；当前记录缺失或读取依据失败就保持 UNVERIFIED，不替换历史验证。

新增回归验证真实原生模式的通过报告、源文件修改后的 STALE，以及新运行时通过历史宿主记录重新发现产物。取消、身份、预算、工具交互保留等原有测试仍执行。

第一轮完整真实实验的残缺事件尾部检查确实失败，尽管当时内部回执显示 PASS；该失败记录保留在初轮测试目录。修复后重新创建独立 profile，从头运行完整模型与中断场景，最终统计只使用这一轮重新验收的数据。

## 运行条件与失败记录

当前默认配置的两组旧凭据在智谱接口认证失败；实际验收使用本次用户提供的地址、密钥和模型。密钥不进入仓库、报告或采集证据。

真实调用出现过宿主的 `LLM idle timeout (120s)`。这些尝试记录为 UNVERIFIED，未计为通过；保留了基础设施重试、截止时间失效及后续重新验收证据。测试中的 provider 超时设为 300 秒，独立 reviewer 与产物语义审阅上限为 600 秒，Stop 总预算为 900 秒；保留有限截止时间与原有纠偏次数限制。显式使用非思考模式，不修改审阅结论或指标覆盖要求。

执行模型曾把完整命令放进字符串变量，遇到 zsh 的词拆分差异并返回 127。它随后改为完整 Python 命令并自行修正；宿主的该次 error 和后续无错误复验都保留。自动回归另发现原有进程树测试的预加载脚本意外继承到子进程、递归派生；测试现明确只创建预期的单代子进程，保留进程组退出断言。

正向 Stop 中断点只在真正包含评估文件的提交上触发。较早命中基础设施失败提交的一次中断独立保留为负例，不计入正向评估发布测试。报告部分输出只有在实际 outbox 已提交且第一份 `diagnostic.md` 写出后才计入中断。

模型偶有指标遗漏，程序将该评估保留为 UNVERIFIED。评估发布恢复按原始内容和哈希核对，允许忠实恢复这个未验证结论；恢复后的新一轮模型验收及最终报告必须实际达到 PASS。不会把历史 UNVERIFIED 改写成 PASS。
