## 实现范围

沿用现有需求提取、Skill Reviewer、Stop、实现评审及预算机制。修改仅在 RC 插件内：

- 提取和仲裁共用的来源说明要求保持原文的强度、条件和范围，区分动作与额外的
  顺序关系；建议、编号和通常习惯不能单独成为强制前置条件。允许语义等价改写。
  这也适用于 Skill 图、dependsOn 和 overlays；原动作有强制依据时仍保留。
- Skill 与 Stop 共用流程评审说明，要求把具体条款、资源、适用任务/Skill 调用与
  真实工具调用/返回对应起来。外部文件变化、Reviewer 行为、助手认错不能证明
  业务 Agent 的历史动作。真正有依据且被证实的强制反序仍是 DEVIATION。
- 从同一份已捕获会话生成工具证据索引。索引仅配对调用和返回、保留原始位置；
  同批并发不假装串行，缺失/失败/重复/反序标识明确保留未知。RETURNED 只表示
  工具已返回，动作是否成功仍需核对原返回内容，尤其后台 exec。
- Skill Reviewer 获得本次已扫描原始 Skill 的独立快照；Stop 的 M08 对象保留
  kind/sourceRef。原图的 MUST 标签不再是评审说明中的独立权威依据。
- Skill 输出新增可选 checkerError。明确的检查器故障走已有 UNVERIFIED 路径，
  原始评审被保存，不因空 findings 记为 PASS，不建立业务偏离或消耗 Skill 反馈次数。

运行库没有导入上一轮实验的字面匹配器，也没有新增流程 DSL、shell 效果解释器、
必要性分类器、评审角色或固定模型调用阶段。代码不自动修改已冻结基线、不把全部
流程要求改软，不修改 OpenClaw、模型执行、业务工具路径或权限审批。

## 已知边界

程序提供的是可核对的事实索引与错误出口，不是自然语言蕴含证明器。没有新增逐字
门槛，也没有用程序自动认定任意 shell 命令完成了某个语义动作。

本轮 Skill 图保留了交付前验收，没有重建上一轮的 read-before-any-edit 图约束。
但冻结任务基线中仍有一条 `Read the original Skill and the project contract
(spec/requirements.md) before modifying the application.` 的增强措辞；用户原请求
没有明确 before。实际读取在本轮业务修复之前完成，因此该条没有成为错误阻断。
这保留了“语义提示不能保证完全不增强”的反证，不能仅凭闭环成功宣称所有强度
判断已正确。拒绝一条派生顺序也不意味着豁免原始阅读要求。

本轮不增加第二个应用样本，不提高预算或时限，不为追求零误判扩建通用规则系统。
完整索引、原始输出位置和结果见同名 JSON 证据文件。
