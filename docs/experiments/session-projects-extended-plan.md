# Session 项目作用域扩展实测方案

日期：2026-10-14。基线提交：`ef3054e`。使用已获授权的 GLM-5.3-Flash，分别启动 OpenClaw `2026.7.1-2`、`2026.10.3` 隔离网关。现有宿主安装、配置和工作区不参与实验；仅复制 RC 并添加诊断用 Python 平台描述。

## 实验矩阵

| 编号 | 目标 | 操作与对照 | 必须取得的证据 |
| --- | --- | --- | --- |
| E1-L | 旧版 Stop 闭环与项目归属 | Session A 用 RC 绑定项目 A；预置 CLI 输出 BROKEN，正式要求 READY；首轮按协议只读，收到 RC 反馈后才修复 | 初轮文件仍 BROKEN；Stop DEVIATION；原生反馈 ADMITTED 且被读取；宿主改代码；默认入口及 help 成功；复验 PASS；需求版本/epoch 未被 RC 反馈重开 |
| E1-N | 新版 Worktree Stop 闭环 | 同一缺口和评审设置，New Session 公共接口选择真实 Worktree；RC 不执行绑定 | E1-L 全部证据，加上工作树执行/记录目录正确、源仓库保持 BROKEN、RC 绑定操作被禁用 |
| E2-L/N | 跨 Session 并发隔离 | A 终审开始后，Session B 在另一已启用项目执行正确 CLI 并交付；B 应无需重修 | 两 Session 评审时间存在重叠；不同 taskId 与基线来源；B correctionAttempts=0；B 未收到 A 反馈；两项目实际文件和运行记录各归其主 |
| E3-L | 评审中 RC 手动切换 | 等真实 Stop Reviewer 开始，给同一 Session 绑定新项目，再下达新项目小任务 | 旧评审取消或旧结果被拒绝；无旧项目续作影响新项目；新 taskId/基线/预算；旧项目未被观察者修改 |
| E3-N | 宿主权威与切换接口边界 | 在真实评审中尝试通过宿主公开接口更换目录；如果宿主拒绝忙 Session，保留拒绝证据；仅在宿主允许时测试有效变更 | 不绕过宿主限制、不直接写 Session 数据库；RC 不使用手动绑定；可执行的有效变更被准确跟随；不把无法执行的实验标为通过 |
| E4-L/N | 实际网关重启与恢复 | 关闭并重启同一临时网关；仅查询原 Session 的项目和原生历史，核对任务与预算 | sessionId、项目来源、taskId、需求摘要和 correctionAttempts 保持；不重派旧反馈；查询不启动模型；宿主默认目录不受影响 |

## 控制条件

- A 与 B 使用同一模型和项目评审配置；A 的确定缺口是唯一主动故障注入。不是自然缺陷率或大项目能力实验。
- 第一轮只读是操作顺序，正式 READY 要求仍生效；用户原始消息已经授权收到 RC 反馈后自行修改和复测，实验员不补发修复提示。
- 使用标准库 Python CLI；RC、需求、AGENTS 和配置先冻结哈希。业务执行只沿用宿主工具。独立验收进程只读文件和执行 CLI，不改业务代码或 Reviewer 结论。
- Stop 开启，k=2；需求面板 1 人、无 adjudicator；Reviewer 角色超时 240 秒，Stop 总评审窗口 720 秒，Hook 600 秒。格式修复沿用既有值，不更改核心算法或基础设施预算。
- 保留初轮 `chat.final` 时的源文件快照；等待独立终审和原生续作完成，再核对最终产物。不能用 chat.final 或 agent.wait 成功代替 Stop PASS。
- 报告区分 PASS、行为失败、基础设施失败、无效试验和宿主不支持。首次业务模型提前修改缺口、没有触发 Stop、或缺少原生读取回执，均不视为闭环通过。

## 记录与判定

每组保存脱敏 wire、宿主日志、正式需求、初/终文件快照、独立 CLI 结果、项目状态、task/epoch/预算、Stop 评估和 native-followup/native-stop-review 回执。报告中的结论必须可由原始记录和真实文件复核。涉及同一 Session 的目录变更只使用宿主公开接口；SDK 数据库编辑或伪造 Hook 事件不能计入真实会话实测。

## 现场调整（保留原判据）

新版 E1 首次实测遇到宿主拒绝异步 Stop 的后续调用，尚未启动真正 Stop Reviewer。后续 E3-N 改为额外子实验 `E3-N-onboarding`：在真实需求提取 Reviewer 运行中验证宿主忙会话拒绝切换、公开 `chat.abort`、空闲目录变更及新项目基线。此子实验不能替代原定的新版 Stop 评审中切换验收，原 E3-N 保留“未完成”。不重复消费模型调用去等待同一个已知故障。

E4 独立使用此前已经通过真实模型项目探针的两套临时状态，执行完整网关启动、关闭和再启动。查询命令会被宿主持久化为新历史记录；只要求重启前已有记录按原身份和内容保留，不能把新增查询记录或行更新时间变化误报为状态丢失。

切换试验的首轮纯读取没有可靠触发所需阶段，记录为无效；写回原样 BAD 在旧版遇到宿主 incomplete turn，记录为失败。旧版第三轮改为此前 Stop 试验已验证的只读 Python exec 检查：仍不修改业务文件，但实际进入 native Stop 生命周期。新版子实验沿用写回原样 BAD，并在第一轮需求 Reviewer 开始时经宿主停止；两者测试的评审阶段分别记录。另对已完成旧版修复状态补做 E4，验证非零预算和已完成反馈回执的恢复。
