# Stop 收敛与终止修复

2026-10-25，分支 `codex/stop-convergence-fixes`，基于 `e75f7b3`。修复依据是前一次离线厨房端到端实验的保存轨迹；本次没有重跑厨房开发、没有调用模型，也没有修改原业务项目、原 session 或运行中的 Gateway。

## 修复后的行为

1. **截止后闭合状态。** 原生 Stop 作业与父等待链结束时关闭当前续作回执，保存逐项集合入口，提交 `STOPPED_UNVERIFIED`。旧评审留在原 evaluation，并作为 previousVerification 关联；不消费额外业务纠偏次数。收尾与释放等待独立，晚到的工作不能提交 PASS。旧运行不覆盖新运行，当前已提交 PASS 不被迟到收尾改写。
2. **取消仍有完整清单。** collector 保存已完成记录，并为当前中断项和其余未启动项写 UNVERIFIED 占位。原任务 ID、对象 ID、反馈位置与原因可逐项查找；不是只留下全局 Cancelled。此前有效结果仍保存在各自文件中。
3. **重复过程偏离先复查失败项。** 首次完整审查只有过程类偏离阻断、没有其它 blocking finding、且有程序观察到的稳定读取依赖时，保存原有证据摘要。已给一次纠偏机会后，在基线、真实用户输入、人口、对象修订及读取依赖均未变的情况下，先只复查这些过程项。若仍全部偏离，结束自动纠偏，明确发布 `PROCESS_CORRECTION_NO_PROGRESS / UNVERIFIED`，保留原完整失败及本次负向复查。它不生成新的整体 PASS 报告。任何变化、修复或证明缺失都会回到完整审查。
4. **按真实证明归属路由。** PROCESS 类型的约束、目标等若尚未有执行审查归属，补入 M11，避免只进入 M01 文档覆盖。已有 M09–M15 执行归属不重复生成过程项。
5. **明确源代码交付时不强造文档任务。** 只有配置明确为源码实现交付、未声明 M01–M07、所有 HARD 义务均明确为 IMPLEMENTATION/PROCESS、且没有 ARTIFACT 义务时，这些文档视图记为不适用。每条原 HARD 实现义务仍有真实履约审查，未被其它执行指标承担者补到 M12；PROCESS 义务有过程归属。文档、混合交付、未知证明归属和显式文档指标继续保守保留。
6. **缓存按证据职责区分。** 同一完整输入下，Stop 调度时间和重复 hook 包装不再污染 PASS 身份。明确绑定交付文件的 M01–M07 可以在新执行轨迹到来时复用已有内容比较 PASS；运行、过程及未绑定项仍绑定完整历史。真实用户变化、模型/协议/基线/人口/候选声明或读取依赖变化仍失效。本次没有把“源码没改”当作任意运行证明可复用的充分条件。
7. **宿主能看到未验证原因。** 普通指标 UNVERIFIED、无进展退出及到期退出保留短诊断和保存位置，沿用现有整包 8 KiB 上限；不新增总评 Agent，不把评审故障当成业务缺陷。

这次修改集中在 Stop collector、原生 Stop 收尾、指标人口和已有 PASS 缓存。没有修改业务验收器、Ground Truth 原文、Prompt 预算、文档/Skill 纠偏开关或模型配置。缓存协议与指标目录均升级身份，旧人口/缓存不会冒充本版结论。

## 回归与适用边界

离线测试涵盖：旧任务/当前 PASS 的收尾保护；部分结果与缺项占位；父期限到期、回执结束、下一任务放行与迟到结果隔离；失败过程项优先复查；源码变化、新用户要求与过程已修复后的完整审查；缓存依赖失效；源码/文档/混合交付的保守路由。

过程收敛回归通过真实编排、collector 与程序证据校验，使用 scripted reviewer 提供合法判断；它验证控制逻辑，不能代替模型准确度实验。厨房材料回放同样没有重新审阅全部业务行为。本次不宣称解决所有 UNVERIFIED、所有过程偏离、所有大上下文或复杂项目的运行效率。

已有运行/过程 PASS 仍可能因新增轨迹重新审查；本次先消除同一未修复过程失败引起的整包循环。首次全量审查、基线提取及分类仍可能成为耗时来源。新用户、新项目变动、未知依赖与其它非过程失败继续按原逻辑核验。

验证日志保存于 `.runtime-correction/stop-convergence-*.log`。首轮全量有三处旧断言只期望完成项，现补强为同时检查中断/未启动项；第二轮仅 SessionEnd 的原有耗时断言在并发构建时超过阈值，未调整阈值或修改 SessionEnd 实现。最终结果另记于本报告的验证结果段。
