# 流程约束强度与事件归因：方案分析和隔离验证

2026-10-15。基线 `c1fec6b`，实验分支 `codex/process-contract-lab`。
结论为 **部分有效，尚不能作为生产硬门槛准入方案直接合入**。
本轮只新增诊断脚本、离线用例和报告；没有修改生产纠偏代码、OpenClaw、冻结任务或预算。

## 代码中的机制

1. `lib/openclaw/sources.mjs:91` 与 `ground-truth-provenance.mjs:64` 校验来源身份、
   kind 和权限，能排除内部角色污染；它们不验证“提取后的命题是否被原文蕴含”。
   真实用户来源不等于该来源支持任意更强的改写。
2. `ground-truth-ledger.mjs:118` 接受提取器给出的 authority/severity，只有
   AGENT_INFERRED/BASIS_PENDING 等会强制变 SOFT。错误标记 USER_EXPLICIT/HARD
   的增强要求，仍可进入冻结基线。只增加一个模型自填 explicit 字段没有帮助。
3. `ground-truth-ledger.mjs:374` 保存 Skill 图，sourceRef 是可选字符串，没有
   绑定到已核验原文条款的同等准入检查。`metrics.mjs:69` 又把所有 MUST/PROHIBITED
   直接转为 hard=true 的 M08 对象。这是另一条硬义务入口，不能只修任务 ledger。
   Skill 可以带入自身明确要求，但不能借此让模型推导的新顺序自动获得硬权限。
4. `orchestrator.mjs:1124` 要求 Stop 判断整个冻结人口，但没有结构化事件对契约。
   `process-checks.mjs` 的机械判断只覆盖已有 fresh-Claude-session 特例，不是通用
   时序验证器。流程 DEVIATION 最终在 `orchestrator.mjs:1339` 消耗业务 k。

所以本次问题的链路是：来源身份合法 → 措辞/强度被模型增强 → MUST/HARD 被直接
采纳 → Reviewer 给出无机器可核对事件对的顺序结论 → 被当成业务偏离续作。
同一要求投影到多个指标并不提供独立证据。

## 候选与实验范围

实验原型位于 `scripts/diagnostics/process-contract-lab/`，不被生产 runtime 导入。
模型探针入口为 `scripts/diagnostics/process-contract-lab.mjs`。

候选包含两部分：收紧模型对原文、建议、编号、等价读取及行为归因的说明；另外对
新增严格顺序要求做原文选择检查，对顺序违规做同 task/session、业务主体、完整事件、
时间先后的机械检查。原型刻意返回 `semanticEntailmentProven=false` 和
`businessRepairAuthorized=false`，不能自称完成全部语义证明。

这是冻结证据重放和模型层探针，不是新的 OpenClaw 原生 Gateway/完整 Stop 穿刺。
没有执行应用工具，没有重新开发厨房应用，也没有用合成模型结果替代原生会话结论。

## 隔离结果

离线 **8/8**。其中既有支持方案的用例，也有否决其过度使用的反证：

| 检查 | 结果及含义 |
| --- | --- |
| 普通阅读指引被改写为“任何编辑前必须读” | 拒绝新增措辞 |
| 完成读取后才开始编辑，却被说成反序 | 检出时间线矛盾 |
| 把外部/未知主体改动归给业务 Agent | 拒绝错误归因 |
| 明确要求先读后改，实际确实先改后读 | 保留“反序事实一致”，没有一律 PASS |
| 缺失、未完成、并发重叠、其他 Session 的事件 | 保持证据问题，不证明业务违规 |
| 原文明确是建议，却被标为 HARD，事件确有反序 | 字面与时间均可吻合；仍不能证明强制性 |
| 明确强制要求的无害同义改写 | 字面检查会误拒，因此不能用作通用硬闸 |
| 模型把正确事件的前后角色交换 | 时间自洽仍可能通过，条款到动作的绑定必须独立核实 |

还直接重放了此前真实厨房实验的原始请求和事件时间戳，没有改写原任务。重放中的动作绑定来自已经人工核对的原生调用，
不是一次对模型自主绑定能力的验证：

- 派生的 `Reading the Skill and spec must precede any kitchen.py edits.` 不在原请求
  中作为原句出现，候选提示“新增改写”，不能单凭此断定所有改写不合法。
- 即使单独考察事件事实，原生合同读取结束于 1792043205423，首次业务编辑开始于
  1792043212298，候选拒绝“先编辑后读取”的结论。
- 外部文件观察不属于业务主体，不能拿来充当业务写入的反序证据。

真实模型使用已授权 `doubao-seed-2.1-lite`，总共 **4 次 API 请求，无自动重试**。
首批普通阅读样本混入了“交付前验证”的另一条明确顺序要求，单个 ordering 字段无法
区分关系；候选因此拆分出额外行。该批保留，但不能用于比较方案优劣，原始 3/4
分数不作为基线误判率。

仅补跑一次范围收窄的四项探针：普通阅读+外部改动、明确反序、等价内容读取、中文
编号建议。候选 **4/4** 符合预期；明确的真实反序仍返回 HARD/DEVIATION，普通建议
没有变成严格顺序门槛。基线请求在 60 秒超时，因此没有完整的 A/B 优劣结论。
当前策略片段加统一实验格式也不是生产多阶段调用的精确复制。不能把这四项通过
宣传为所有 Skill、语言、工具包装和真实长会话均已鲁棒。

## 收窄后的推荐方案

1. **原动作与派生关系分开。** “必须读合同”可以保留原要求；不能仅因描述顺序、
   编号或模型输出 MUST，另外产生“任何编辑前必须读”的独立阻断项。拒绝派生
   顺序不等于把原始阅读要求改软。用户/Skill 原文明确的顺序也不能被一律取消。
2. **用程序保存的原文作依据，不要求模型逐字复述。** 现有来源绑定可复用。
   字面匹配只能做审计提示，不能成为新的语义硬门槛；原文存在也不代表 HARD
   强度已经被证明。不能用原型中的逐字拒绝逻辑直接接入生产。
3. **先落地可确定的事件矛盾检查。** 历史顺序违规要有匹配条款、主体、范围及
   完成事件对；还须核对 A/B 确实对应原条款的动作，不能让模型自由交换角色。
   原型尚未实现这一绑定证明，不能直接用“时间自洽”授权生产阻断。明确矛盾、跨 Session、外部主体或缺失证据，进入既有检查器故障/
   未验证处理，不派发“修改代码消除历史”的业务续作。并非因此自动 PASS。
   原型目前只核对 task/session，生产还需绑定条款适用的 invocation/epoch，不能
   自动扩大为整个 Session 历史。对一般 exec 包装无法证明动作时保持未知，不新增通用 shell 效果解释器。
4. **不扩建通用必要性或不可补救性分类器。** 自然语言强制性与条款到动作的绑定
   仍有语义风险，本轮没有证明一个局部校验器能完全解决。新增时序关系没有可信
   强制依据时，不自动获得独立硬门槛权限；已明确硬要求缺少证据时仍如实未验证。
   不自动改写历史冻结基线、豁免 HARD 或清预算。

可确认有效的是“证据矛盾不能直接成为已证实业务偏离”的机械边界；“字面引用+
提示词即可通用判断必要性”被反例否决。生产接入应先限定在这个边界，不能用
厨房文件名、某句理由关键词或当前四个案例写特判。
