# RC 评审可靠性隔离实验

基线：`6b447e9`。只改 RC，正式 OpenClaw 2026.7.1-2 受控运行，模型 `glm-5.3-flash`。实验目录：`/private/tmp/rc-review-reliability-20261011-1`。

采用的小改动：

- 受控评审使用 RC 自有角色与整轮时间窗口，真实 Hook 和父运行截止时间不变。
- 精确绑定 objectId / claimId，按既定终审/实现评审字段读取输出。忽略额外说明，必填字段、合法判断、身份及来源规则仍严格。
- 程序保存有真实引用的逐项结果，整体失败仍可返回部分反馈，相关需求合并。来源或需求版本变化后不沿用旧结论。
- 默认最多三次格式修复，读取 `config/reviewer-defaults.json`，项目/角色 YAML 可覆盖。首次及修复共用同一会话、原截止时间。运输/宿主错误不算格式修复。
- 历史上已移除的可选文件不再冒充当前必需证据。声明必需文件、评审期间变更仍阻断。有效阶段通过显示为阶段通过、整体未验证，不显示成结论失效。

未采用：额外并发/事务提示。早期真实样本仍有 R27 超量借出，未证明该提示有效；最终版保留原判断方法。没有增加总结 LLM、调度器或 SQLite 专用规则。

## 合入前正式实验

| App | 原版独立场景 | 候选独立场景 | 正式运行结果 |
| --- | --- | --- | --- |
| flower | 18/19 | 18/19 | 阶段通过，整体未验证；纠偏 2 次 |
| kitchen | 10/12 | 10/12 | 整体通过；纠偏 0 次 |
| lending | 20/20 | 20/20 | 整体通过；纠偏 2 次 |
| todo | 21/22 | 21/22 | 整体通过；纠偏 1 次 |

所有原先通过的场景均保留。新 50 需求借物 App 从空目录开发；RC 发现并交回宿主修正 R27，真实双 CLI 并发测试由基线 0/3 改为 3/3。旧三个 App 从相同、已固定的业务起点做正式任务和兼容性实验，不据此宣称全需求覆盖率。

实际记录出现同一会话内的第二次格式修复。早期失败记录回放可保留 181/215 项当前有依据的结果和偏离位置，仍标整体未验证。实现评审有效进度也不会因一个错误项整体消失。引文来自程序快照；最终四例共核对 2370 个引用，未发现快照哈希或引文不符。

电话清空测试最初限定空字符串，但 R23 仅要求清除可选值。测试修正为允许空字符串或 null，对原版和所有候选统一执行，保留原断言结果。未用业务代码补丁迁就测试。被替代并主动停止的早期候选不计正常完成。

已知基线问题仍存在：Todo 损坏 JSON 场景、CSV 与数据同路径；厨房份数截断和不兼容备份；花店一项原业务场景未通过。此次优化不宣称消除了语义漏检。
