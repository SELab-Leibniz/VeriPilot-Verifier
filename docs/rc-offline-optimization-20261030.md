# RC 首轮离线优化结果

本文件及配套 JSON 保留首轮历史快照。后续 C1/C2/C3 已修改相关源码；当前合并验证、源码与产物身份及下一阶段前置条件见 [合并验收](rc-offline-integration-20261030.md)，首轮 sourceHashes 不整体代表当前版本。

本轮修复冻结来源和工作区读取器的取消边界，并减少同一内容分页时的重复解析。完整工程回归通过，实际安装宿主的补充无模型契约通过。模型 token、真实语义判断及 F2P 和 P2P 均未在本轮测量。

用户授权经受托代理转达，范围为离线 RC 本体、必要的本仓回归、文档和记录。真实模型、付费实验、外围框架及系统安装修改仍锁定。完整数值及三十场景逐项记录见 [结构化结果](rc-offline-optimization-20261030.results.json)，后续状态见 [任务清单](rc-cross-benchmark-optimization-tasks.json)。

## 生产修改和原版复现

在真实文件读取返回的边界取消请求，原版冻结来源及 live 读取器仍返回成功页面。文档读取器已经正确拒绝此情况。本轮给前两者传递读取取消信号并在读取完成后重新检查，避免返回可接受的成功原文结果；文档控制例同时确认取消后不能取得私有笔记资格。

每个生产读取器新增独立的有界解析缓存。每次仍执行实际文件读取和当前字节的 SHA256，只有内容相同时复用解码、分行和全文字符统计。缓存最多八个内容身份、累计四 MiB 原文字节；这不是堆内存严格四 MiB 的承诺。超限单文件不保留。路径选择、权限、回执和引用资格没有合并，返回的页码及字符事实元数据独立于此前调用者。

修改位于 [冻结来源工具](../lib/review-task/source-tools.mjs) 和 [工作区工具](../lib/review-task/live-source-tools.mjs)。[新增生命周期回归](../test/source-reader-lifecycle.test.mjs) 覆盖真实读取完成后的取消、文档笔记资格、字节一致、同尺寸同时间修改、非法 UTF-8、跨路径隔离、驱逐和超限不保留。

## 工具成本实测

组件对照固定为 28071d1 的原始模块，执行真实文件 I/O 和生产工具调用。每个场景每组五轮、每轮四十次分页，组间交替；固定输入、页数、返回内容和元数据保持相同。下表为最终记录的中位数。

| 场景 | 原版耗时 | 候选耗时 | 变化 | 原文解码量 | 实际读取及返回内容 |
| --- | --- | --- | --- | --- | --- |
| 冻结来源 ArkTS 文本 | 87.02 ms | 16.55 ms | 减少 80.98% | 四十份降为一份 | 读取字节不变，输出摘要相同 |
| 工作区 Python 文本 | 89.33 ms | 19.15 ms | 减少 78.56% | 四十份降为一份 | 读取字节不变，输出摘要相同 |
| 文档控制组 | 14.97 ms | 15.12 ms | 波动约增加 0.98% | 不变 | 没有文档工具优化收益 |

本轮只证明局部解析 CPU 和工具墙钟开销降低；不是 I/O、上下文披露、模型调用、模型 token 或任务总耗时改善。完整 CPU、I/O、返回量和各轮记录在结构化结果中。首次组件比较的摘要保留在 checkpoint-001.json，最终交替比较的原始记录保存在 tool-cost-paired.json。

上述检查包含重叠用例，数量不相加。最终文档补验在完整回归后独立执行，覆盖两种失败写入、未匹配写入、正确完成不携带旧偏差，以及成功 patch 的触发。Skill 正确完成控制实际运行本地验证并保存执行转录，再由受控审阅替身给出空 findings，检查程序结算为 PASS、没有多余反馈、偏差或修复额度；这不证明真实模型误报率。

首次全量的 1905 通过、16 失败、25 跳过保留于 full-regression.log。CLI 与 HTTP 夹具被本地端口权限拒绝，使用允许本地夹具的环境复验；没有用跳过或生产权限放宽掩盖失败。另两项是既有夹具问题：500 ms 低于公开最小合法超时，现改用 1000 ms 验证同一杀进程断言；深目录超过 macOS 路径上限，现缩短物理路径，原有索引路径大于 768 字节、逐项不超过 768 字节、二十对象及精确 ordinal 的断言全部保留。这些不计作 RC 功能或效率收益。

首次新增夹具使用未规范化的临时路径，其失败也保留；规范化后才形成冻结和 live 取消边界的有效生产复现。最初三个模块文件因缺少锁定的 typebox 1.3.27 无法加载，本仓按原锁文件准备依赖且禁止安装脚本，没有修改依赖版本或锁文件。

## 三十场景覆盖状态

十八项的程序契约已验证，十二项仅部分验证。所有场景均没有据此认定真实模型或完整业务纠偏端到端通过。逐项输入、预期、真实断言位置、已验证范围和剩余部分见结构化结果的 moduleCases。

| 模块 | 程序契约已验证 | 部分验证 |
| --- | --- | --- |
| 需求基线 | B02、B04、B05、B06、B07 | B01、B03：提取内容和条件判断的真实语义 |
| 文档纠偏 | D03、D04、D05、D06、D07 | D01、D08：实际语义与完整闭环；D02 另有当前工具覆盖能力边界 |
| Skill 纠偏 | S02、S05、S06、S07 | S01、S03、S04、S08：正确与错误执行的真实语义判断和完整反馈链 |
| Stop 终审 | F02、F05、F06、F07 | F01、F03、F04：真实业务修复、适用性和错误范围判别 |

四模块各有正触发、负触发、不适用、缺证据、重复、取消恢复和来源变化场景，文档及 Skill 另有正确完成控制。受控替身用于验证程序如何消费既定结论，不能替代结论本身是否正确。

D02 的普通 exec 副作用属于当前能力边界，而非仅缺真实模型判断：即时文档链路依赖已识别的 Write/Edit，OpenClaw 另外将已识别 patch 变更投射为文件事件。普通 exec 未提供可识别文件变更时，不支持即时文档审查。依据见 [写入后反馈](how-it-works.md)、[Hook 接口](interfaces.md) 与 [文件映射实现](../lib/openclaw/tools.mjs)。本轮不新增通用 shell 解析或全仓扫描，也不将此类文档宣称为已由 Stop 完整验收。跨 bench 接入预检须单列工具覆盖范围，核对受测 Agent 的实际编辑方式与已支持事件是否匹配。
