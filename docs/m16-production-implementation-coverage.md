# M16｜生产实现覆盖率

以本次任务冻结的需求及实现范围为基准，评估当前产物是否具备与需求对应的、真实、具体且可达的生产实现，以及必要的入口、配置、处理逻辑和数据流是否连接完整。

## 通过条件

一个实现单元只有同时满足其全部必要条件，才能判定通过：

1. **真实存在**：实现位于目标产物实际使用的代码、配置或资源中，而非仅存在于文档、注释、测试替身或示例中。
2. **生产可达**：能够从规定的用户操作、系统事件或业务入口到达；不存在必需配置缺失、前置条件错误或提前返回造成的确定性阻断。
3. **核心处理真实**：要求的业务逻辑或平台能力确实接入，不能用固定结果、成功提示或模拟数据冒充真实处理。
4. **数据流有效**：实际输入参与处理，关键返回值、状态或数据被相应页面、存储、后续流程或调用方消费。
5. **必要分支完整**：纳入该单元范围的授权、拒绝、异常、持久化、安全处理等必要分支具有对应实现。
6. **证据可追溯**：结论能够定位到当前版本的具体文件、符号、配置及调用关系，并说明这些实现如何满足必要条件。

若需求明确允许预留入口、Mock 回退或其他替代方式，可按该范围判断；通过结论不得扩张为未实现的完整能力。

## 不构成通过的情况

以下情况不能单独证明实现覆盖：

- 只有页面、按钮、接口声明、SDK 导入或依赖安装。
- 只有 TODO、未来接入说明或成功 Toast。
- 使用固定返回值冒充识别、查询、认证等真实结果。
- 关键调用存在，但从生产入口不可达。
- 丢弃该单元必需的返回值，或未连接必要的后续处理。
- 仅测试替身通过，生产路径没有对应实现。
- 用其他功能的成功，替代本单元的必要条件。

## 冻结分母与判定

每个有效的 `requirements` 或 `inScope` 原子条目形成一个 `M16:<claimId>` 实现单元。明确归属 `ARTIFACT` 或 `PROCESS` 的条目不进入 M16；任务权威明确限定仅交付文档时不新增生产实现义务。旧基线缺少 `verificationTarget` 时保守保留条目，由审查确认适用性，不能根据源码缺失删掉分母。原有条件、例外、硬软级别、修订和来源继续保留，公共约束及显式依赖通过原有基线选择函数提供。

只有全部必要条件有对应实现证据才 `PASS`。有当前源码证明的占位、阻断、断连或其他具体缺失判为 `DEVIATION`；必要源码、配置、资源或依赖不可读，适用性或版本绑定不确定时判为 `UNVERIFIED`。不完整源码清单或一次搜索失败不能证明全局缺失。六项条件是每个单元的合取条件，不拆成六个可相互抵消的得分。

沿用统一聚合：可计分单元全部判定完成时，覆盖率为 PASS 单元数 / 可计分单元数；存在未验证单元时数值为 `null`，同时保留分母和逐项原因。无实现单元时为 `NOT_COMPUTABLE`，不虚报 100%。HARD 条目的具体偏差或缺失必要证据进入原有有限 Stop 纠偏流程。

## 审阅后的接入位置

- `metrics.mjs`：目录、版本和冻结分母；M16 要求证据，文档及过程对象被排除。M16 不取代原 M12 的履约分母。
- `config.mjs`、项目配置 Schema 和 `artifact-candidates.mjs`：允许声明 M16；默认全指标报告自动包含它。
- `review-routing.mjs`、`impl-review.mjs`：实现阶段及之后接入源码审查，与 M09/M12 同属实现审查的证据分区；需求、设计和规划阶段保留原有跳过策略。
- `orchestrator.mjs`：普通 Stop 同样采集程序生成的源码清单，关闭可选的实现审查也不改用助手自述作为 M16 证明。
- `stop-task-review.mjs`、`prompts.json`：单项源码职责、完整六条件提示与独立审阅类型；不提供过程记录作为该源码职责的替代证据。
- `review-result-validation.mjs`：M16 的通过和偏差需要真实读取的 `SOURCE` 证据。当前文件 hash、读取依赖和任务/基线围栏沿用既有校验；提示摘要及指标目录版本变化使旧缓存失效。
- `review-task/production-trace.mjs`、`review-task.mjs`：单项 SDK 的 M16 PASS 额外保存并校验输入、生产者、消费者、所有相关状态目标及目标之间的合法输入重合分析。源码 citeId、完整目标比较与未知/破坏效果会由程序校验，不能用已读取整份文件代替这份证明。明确反例可直接判偏差。程序校验的是证据协议，语义正确性仍是模型审查的能力边界。

普通 Stop、可选实现审查和不同宿主继续使用各自现有传输。当前基于生产源码、配置和资源的可检查关系作语义判断，不执行新增业务测试，不把 M16 PASS 当作 M12 已运行、M13 验收闭合、M14 里程碑闭合或 M15 旅程通过。平台声明的源码路径、扩展名及既有清单数量限制继续适用；必要证据超出可读范围时保留未验证。

未选择平台适配器的通用项目还会收集根目录的源码/配置入口、常见语言源码及 `config`、`resources`、`public` 下的文本配置和资源，避免根目录 Python/Node 入口被原来的 `src/lib/app` 范围遗漏。平台已声明的源码范围继续按平台配置处理；通用发现不把测试、私密文件或示例当作生产实现证明。

## 验证范围

离线机制回归覆盖冻结分母、文档/过程排除、旧基线、阶段路由、六条件策略一致性、两种审阅角色、实际读取证明、源码变更围栏、配置声明、聚合与缓存，以及实现偏差阻断和修复复验。受控 reviewer/worker 用于验证调用链，不代表真实模型的缺陷检出率或完整宿主端到端验收。

2026-10-25 验证结果：

- 相关定向回归 280 项通过；最终串行复查 M16、实现审查、审计回归和 SessionEnd 共 61 项通过。
- 全量 `npm test` 当轮共 1573 项：1539 通过、25 失败、9 跳过。24 个失败用分支起点的未修改代码逐项复现；另一个 SessionEnd 看门狗测试在并发运行中超过 1200ms，最终串行复查通过。全量结果未记为全绿。
- `npm run build:plugins` 成功生成 Claude、CodeAgent、OpenClaw 三个产物；逐个载入产物确认目录包含 16 个指标，M16 原生/单项审查使用的六条件规则相同。

上述初次接入验证之后，真实 TodoList 实验暴露了路径冲突漏报与 Stop 调用链故障；原始结论见 [端到端实验](experiments/todolist-m16-e2e-20261025.md)，当前机制修复、验证记录和真实模型复验边界见 [后续修复](experiments/todolist-m16-fixes-20261025.md)。没有替换正在运行的宿主插件。
