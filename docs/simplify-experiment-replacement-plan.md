# 清单工具修复后的重跑范围

用户批准一次安装包替换。旧包 SHA256 为 `ec358bfbd52df682ca921a185195293682ee470630f1be011c147e11a480fa9a`，替换包来自 `0bbf9e3c5ff91e2a4018a09a751a96a6d0392520`，SHA256 为 `a678d55b6f58ede1ff686afc02c6438a6ba943158d6e642d38cfe4806a53b059`。主计划仍用原 SHA256，旧包第一轮和暂停的第二轮单独保留，全部排除计分。

- 用替换包做四臂离线准备验证。B1 的 `external-bug` 和 `internal-correct` 同时做不计分验证，Stop 总预算 210 秒。两次都应调用 `set_original_checklist`。仅在工具可用且未重现循环、但审查超时时，按用户要求改为 600 秒各补验一次。若原循环或其他工具缺失再现，停止。
- 第一轮按原 84 个序号重跑。同一样例和重复内四臂同时启动，每组收齐结果再启动下一组。原 210 秒预算、输入、模型、传输和盲评标准保持。重新筛选最多两个入围臂。
- 第二轮沿用已冻结的 `security_tool_1` 正确首稿和缺陷变体。每个对象和重复内同时启动 A 与入围臂。所有工程检查和隐藏评分用同一全局 hvigor 锁，记录等待时间。RC 耗时按同组比较。
- 出现 429 或并发相关错误后保留受影响尝试，剩余改串行，记录切换时刻并遵守原重试和限流约束。
- C 的 6 个原包序号与答案继续使用，前提是替换包与旧包的压缩代码路径一致。C 不纳入新旧 Stop 臂的包一致性比较。
