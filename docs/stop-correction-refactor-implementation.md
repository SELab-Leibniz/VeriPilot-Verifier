# Stop 纠偏重构实现进度

对应需求：[stop-correction-refactor-requirements.md](stop-correction-refactor-requirements.md)，版本 1.1。

当前已实现共享核心、生产 Stop 评估切换、项目配置接入、SDK 单 Agent 分组逐项提交，以及面向 MatrixAssistant 内置 OpenClaw 的启动协议适配。**整体交付尚未验收完成**：真实模型 TodoList、K=1/K=3 对照、真实长时边界和现有回归迁移仍需完成。代码接入、定向测试和真实宿主验收是不同层次的证据。

## 本次审查指出的四项缺陷

1. **取消被准入校验占锁阻塞**：先在短事务内捕获反馈，锁外执行可取消、有截止的依据校验，再重新取得锁核对准入、反馈身份和当前状态。挂起校验不占住会话取消锁，迟到返回不能提交。
2. **派发截止丢失已保存结果**：轮执行器对 `STOP_REVIEW_DEADLINE` 和关闭异常都进入收尾；已保存的条目仍汇总，不能因后续派发失败变成零偏差。
3. **先前 Stop 的 WAIT_REPAIR 残留**：流程结束时释放同一流程内所有 Stop，并保留各自原评估事实。后续有效 PASS、额度退出、取消等都不能留下旧等待。
4. **部分失效反馈无法保留有效子集**：依据接口支持返回原反馈的有效子集；筛选结果、反馈修订和移除原因持久化。保留布尔接口的兼容性，但不得返回新增、修改或重复的条目。

以上都有回归测试。测试名称中的 AC 编号表示机制覆盖方向，不表示对应 AC 已通过生产端到端验收。

## 主流程与分组执行

- `orchestrator.mjs` 的自动 Stop 进入 `production-stop.mjs` / `assessStopCorrection()`；旧 `assessStop()` 已移除，没有静默回退。进入条件保持原规则。
- 额度判断先于自动 GT 准备、分类、源码收集和审阅。零额度、职责关闭或明确的历史迁移缺口不会启动这些模型工作。
- 会话账本位于宿主稳定目录，业务已用与在途预留分开。只有可信实际开始才增加会话和流程已用；任务/GT/周期变化不清零。
- 准备、分组审查共享本次审查截止，结算和交付使用原总截止内的预留。后续 Stop 获取新窗口；可信已开始的宿主修复不占原审查窗口。
- 调度按 P0/P1/P2 和 M 环游标持久化，派发时推进，同轮失败不重派；必要依据未变的单项 PASS 可复用。
- `stop-task-group.mjs` 保留每项原始依据、修订和职责，合并共享源码读取，启动一次 SDK 会话。每项提交经过完整证据校验、插件持久化回执后，Agent 继续同组下一项。
- 部分保存后崩溃不会删除已保存项，也不自动补派另一个 Agent。组结果只报告成员和完成状态，没有可覆盖所有成员的组 PASS。
- M16 PASS 的完整生产链路证明仍必需；具体反证的 DEVIATION 与诚实 UNVERIFIED 不套用完整 PASS trace 门槛。M16 不能代替其他 M 的运行证据。
- 运行/设备验证能力仍归入适用的 M12/M13/M15，并共享截止和取消信号。独立文件质量开关保留；未启用时不静默增加全面终审。
- 显式只读验证复用审查机制，不领取业务准入，不受自动纠偏额度驱动，也不结束已有自动流程。

## MatrixAssistant 适配

当前重点是 MatrixAssistant 内置的 OpenClaw `2026.7.1-2`。`stop-start-protocol.mjs` 使用公开接口，不改宿主源码：

- 通过 `subagent.run` 提交一条带固定身份的反馈引用。引用不内嵌可能过期的偏差正文；不确定请求不自动重发。
- `before_prompt_build` 核对原用户输入、项目、冻结要求和当前反证，只附加仍有效的反馈子集。
- `before_agent_run` 在模型处理前再次核对准入、截止及实际收到的反馈正文；已取消、过期或正文版本不一致时阻止该插件续作。
- 只处理 `onInternalDiagnosticEvent` 中具有可信元数据、真实时间和序号的 `model.call.started`，把预留转为一次实际使用。排队、反馈落入转录和启动门通过都不计费。
- 每个实际执行身份只结算一次。及时开始但确认迟到只更新历史、不重开等待；违规实际开始据实计账并用 `gateway.request('chat.abort', {sessionKey, runId, preserveSideRuns: true})` 停止确切的插件运行。
- 到截止先使准入失效并解除等待。已过启动门、但实际开始尚未确认的请求保留未知在途名额；不能盲目终止可能已及时开始的修复。
- `assessment` 等到核对后的反馈实际交付或有界失败，不把 API 排队回执视为交付。`until_pass` 只有可信开始才进入修复等待，后续 Stop 重新计时。
- 自有 user-role 引用只在可信转录投影中标记为内部消息，保存对应宿主记录身份以支持重启；不修改原生转录或伪造新用户输入。
- 单次评估保存程序拥有者和审查范围身份。恢复时确认原进程已退出，关闭旧审查轮并保留逐项回执；未绑定宿主请求的预留可确认未开始后释放。旧记录缺少拥有者时沿用原绝对截止，不能无界等待；旧迟到事件仅释放所属 Stop，不取消后来的独立等待链。此恢复修补有本地回归，尚未完成真实进程重启及 GT/缓存恢复验收。
- 会话创建事实在宿主级目录保存，即使创建时尚未选择启用 RC 的项目。MA 的 sessions.create 不发 session_start 时，只允许从稳定的完整宿主转录核对空执行历史，或按该固定版本的持久化续作协议核对完整、未分支的首轮真实用户输入。只有初始化元数据的转录可核对为空；压缩、导入、分支、内部消息及已有多轮历史均不自动推断为零。恢复事件不初始化未知历史为零；项目切换、关闭和取消使原作用域准入失效。

本机 MatrixAssistant 的 `resources/openclaw` 已完成真实隔离 Gateway 接线实验：K=1/K=3 均由确认偏差进入一次实际纠偏并得到后续 PASS，分别保存 6/6 个单项回执、消耗一次业务额度，之前 Stop 的等待全部释放。提供器为本地确定性服务；此事实不等于 Electron UI 或外部模型验收通过。其他宿主/版本没有这份经过验证的启动能力时，明确返回 `HOST_START_PROTOCOL_UNSUPPORTED`，保留确认偏差，结束等待且不自动续作、不计费。尚未把 MatrixAssistant 的结果外推为 Claude Code 或 OpenClaw 2026.10.3 的完整支持。

## 配置及迁移

项目 Schema、配置编译和配置生成已接受以下规范字段：

```yaml
stopCorrection:
  enabled: true
  waitMode: until_pass
  maxCorrectionsPerSession: 3
  maxCorrectionsPerFlow: 3
  assessmentTimeoutMs: 1200000
  feedbackReserveMs: 180000
  reviewGroupSize: 3
  fileQualityReviewEnabled: false
```

- 两层上限可以为零；K 和时间必须为正整数，预留必须小于总时限。缩短测试窗口时必须同时显式设置合适的预留。
- `maxCorrectionsPerEpoch` 仅在配置入口显式映射到流程上限，并给出弃用提示；不映射会话已用次数，不保留周期清零。
- `waitTimeoutMs` 仅映射到单次 Stop 的 `assessmentTimeoutMs`；不再表示包含业务修复的整链时限。
- 新旧同义字段同时出现明确报错，不能依赖隐式优先级。
- 新会话必须有可信的宿主创建事实。既有会话只能由可追溯的逐次实际启动记录初始化；无法核对时返回 `STOP_SESSION_MIGRATION_REQUIRED`。不能把某个任务/周期计数当作整个会话历史。
- 已结束流程不会因为增加上限、切换模式或重新读取配置而重新领取额度；新真实用户输入可建立新的局部流程，会话已用仍保留。

## 验证记录与边界

定向回归当前为 **172 项通过、0 失败**，覆盖核心、进程竞争、项目入口、真实 SDK 会话协议、分组证据适配、设备取消和原生宿主适配的受控生命周期。SDK 和宿主受控提供器用于验证执行与持久化机制，不提供真实模型的语义准确性结论。

另有隔离脚本 `scripts/diagnostics/stop-correction-ma-contract.mjs`，使用 MatrixAssistant 实际内置 Gateway、真实 SDK 工具和本地确定性 HTTP 提供器验证 K=1/K=3 的接线。它不替代真实模型 TodoList 或性能实验。本轮实际结果为 PASS_LOCAL_HOST_CONTRACT；K=1 共 6 组，K=3 共 2 组，均 6 个回执。耗时分别 13.598 秒和 8.166 秒，只描述该受控接线用例，不作为真实模型性能结论。证据见 [隔离接线记录](experiments/ma-stop-v1-contract-20261025.md)。

按用户随后指定的简单任务，已运行 [Python 归并排序真实模型实验](experiments/ma-python-sort-live-20261025.md)。两组独立业务验收均为 8/8；K=1 的 RC 为 10/10 PASS，K=3 因预设 160 次总请求上限在 16/17 时退出，保留 UNVERIFIED。两组 GT 拆分不同，不能据此比较性能，也不替代 TodoList 和完整 v1.1 验收。退出后的旧待审状态由显式对账恢复，相关自动恢复修补是实测快照之后的代码，只计本地回归覆盖。

当前扩展回归尚未通过。最近一次有界根测试运行共 1547 项：1369 通过、166 失败、3 取消、9 跳过，约 243 秒；此后新增首轮历史核对的边界用例已定向复测，未重新用旧全量数字代表当前全部代码。生产切换后，原测试中的周期清零、提前计数、单项 Agent、故障自动重试、既有会话隐式初始化及整链共用截止等假设需要逐项迁移；另有环境/基线故障。此前核心初版的 43 项通过及 1518 项旧回归数字只是历史记录，不能套用于当前代码，也不能将本次新增失败全部归为基线问题。
