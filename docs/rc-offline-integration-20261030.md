# RC 离线合并验收：首轮与 C1、C2、C3

本阶段完成已授权的 RC 本体离线修复和工程验收。当前合并源码在实际安装的 OpenClaw 2026.7.1-2 只读条件下，完整回归 187 文件、1966 用例，1955 通过、11 条件跳过、零失败和零超时。三种宿主产物在独立目录构建并通过模块加载和工具检查。没有调用真实模型、安装插件、发布、提交或推送。

整体跨 bench 效果目标仍未达成。四模块的真实语义判断、三套 bench 的完整接入、27 例样本冻结、F2P/P2P 严格提升及模型 token/任务总时间改善尚未验收。

## 修复及证据顺序

首轮保留读取取消边界修复和有界分页解析缓存，详见 [首轮报告](rc-offline-optimization-20261030.md) 与 [首轮结构化结果](rc-offline-optimization-20261030.results.json)。后续三个候选各自先冻结原版、复现、顺序修复、定向验证并经独立复核，最后运行一次合并回归。

| 轮次 | 生产变化 | 已验证行为与限制 |
| --- | --- | --- |
| 首轮 | 冻结来源/live 读取取消边界与按内容复用解析 | 每次仍真实读取和计算当前 SHA；缓存不授予引用资格，最多八个身份、四 MiB 原文字节，并非严格堆内存上限 |
| C1 | 文档 open 先预留完整元数据，再分配实际 JSON 正文预算 | 未披露正文不进行 open 阶段读取；取消、verify-only 不新增笔记资格；最终 verify 仍检查所有文件 |
| C2 | live grep 以实际句柄读取约束字节量 | 不依赖 stat 作为输入上限；额外最多一个 EOF 字节，部分文件不登记完整源，明确返回未完成及恢复提示 |
| C3 | Skill 搜索片段的 excerptOnly 标记 | 现有切片只要省略前缀或后缀即标为片段；搜索、切片长度、分页和显式原文读取保持原契约 |

C1 普通元数据范围内整个 open JSON 不超过 8192 字节。合法完整 manifest/notes/读取提示本身超过预算时保留全部元数据、延后全部正文且不读正文；没有通过拒绝合法范围或删除元数据满足预算。显式原文读取仍可用。

各轮目录为 `.runtime-correction/offline-optimization-20261030/c1-round-001`、`c2-round-001`、`c3-round-001`，分别保存 `report.md`、`result.json`、最小 diff、原版失败及候选 TAP。C1 的首次关联夹具错误也原样保存；没有放宽业务断言。三个修复均已独立复核通过。

## 成本收益与取舍

C1 的五轮交替、相同真实输入组件比较，固定执行构造、open、补读全部原文、字节一致核对、最终 verify。十二文档全流程读取 47→37 次、281483→221593 字节，open 读取 12→1 次；同时首屏 80→70 行、后续读取 11→12 次、总 JSON 返回 81359→81479 字节。密集单文档首屏从零行变为 61 行，后续读取 4→3 次；JSON 转义场景首屏从零行变为 28 行，后续读取 6→5 次。全部原文均能恢复。

C2 的 stat 后真实增长反例从读取 8205 字节并登记完整源，变为读取 65 字节（预算 64 加探测 1）、未完成且不登记完整源。完整八字节边界控制的原文字节、SHA 和搜索命中一致。该结果证明预算与证据边界，未测 token 或稳健时延改善。C3 仅纠正标记，不作效率收益声明。

首轮的冻结/live 分页工具耗时约降低 81%/79%，来自当时固定源码和固定组件场景，仍是历史局部测量。后续 live 模块已有意修改；不能把首轮数字当作当前合并版本或真实任务的效率验收。没有将少读、漏审、未完成审查计作收益。

## 源码与产物身份

首轮 `sourceHashes`、首次 `artifact-verification.json` 及各轮 before/candidate SHA 是各自历史快照；后三轮有意修改后不再整体代表当前版本。本次 `run-input.json` 固定合并回归起点的四个生产模块 SHA，`artifact-verification.json` 将它们逐项映射到三种新产物中的文件 SHA，并核实旧冻结产物和 dist 没有变化。`result.json` 汇总历史轮次至当前身份的关系，`delivery-manifest.json` 固定当前源码、测试、规划及报告和证据文件身份。

当前产物仅供离线审阅，还没有冻结为正式最终验证候选。真实调优后仍须重新冻结候选、构建身份和运行清单，才能开启十八例最终验证。

## 尚未满足的前置条件

三十模块场景保持首轮的十八项程序契约已验证、十二项部分验证，全部没有据此认定真实模型端到端通过。部分项为 B01/B03、D01/D02/D08、S01/S03/S04/S08、F01/F03/F04；真实基线提取、条件判断、文档/Skill 正误判别、终审范围及真实修复闭环仍需模型受控验收。

D02 还存在明确能力边界：即时文档审查支持已识别 Write/Edit 和 OpenClaw 已识别 patch 的文件事件投射；普通 exec 的副作用没有可识别文件清单时不支持即时触发。本轮不新增通用 shell 解析或全仓扫描，也不宣称此类文档已由 Stop 完整验收。

三套 bench 的实际 readiness 均未建立：Terminal-Bench 既有 wrapper 限制为其他 Agent，Harbor 虽有 OpenClaw 适配但 RC 加载、全程资源限制和纠偏后交付未资格验证；DeepSWE 没有已证明的 OpenClaw/RC 全任务到官方评分链；SWE-sweep 的固定数据、verifier 和入口未建立。需要修改外围框架时属于范围外前置条件，不能以更换受测 Agent 或隐含外围修改取得结果。

收尾只读核对了本机 Harbor 0.22.0 的具体边界：已有 `environment.mounts` 支持 bind/source/target/read_only，OpenClaw 适配支持上传合并的 `openclaw_config`，但实际执行命令固定带 `openclaw agent --local --json`。这只说明可能通过现有配置加载冻结产物。RC 的真实终态和续作依赖 Gateway `agent.wait`/`chat.send`，包含受认证 CLI fallback；必须核实 embedded local 路径是否提供同一受信终态和调度能力，不能自动等同于 Gateway 运行，也不能为接入而关闭自动纠偏。依据与文件摘要记录在 `next-stage-preflight.json`，没有启动容器或修改 Harbor。

目前没有选定 27 个任务 ID、固定分档依据、种子和 9/18 划分；没有 RC-off 官方基线；也没有可报告的 F2P/P2P、官方成绩、模型 token 或任务总墙钟时间。满分指标无法严格提高的规则保持不变。

## 下一阶段最小启动清单

无需模型可先做：在现有接口和只读范围内核对隔离产物加载、RC-off 开关、资源累计和结果交付能力，首先核对 Harbor `--local` 与 RC Gateway 终态/续作依赖是否兼容。静态可配置不算运行闭环通过；需要容器、外围修改或真实模型才能继续的部分分别列出，不默认为已授权。

需要用户决定的第一批参数仅为：固定主模型/审查模型及推理配置、可用运行机器与容器使用边界、真实模块小批实验的金额/墙钟/调用上限，以及阶段内并发和单次限制。已有连接可用不代表获准调用，不读出或披露凭据。先申请可结束的小批额度，二十七例整轮额度在组件结果可审阅后再定。

后续按以下顺序推进：

1. 获得上述小批实验授权并冻结组件输入、义务、正确/错误控制和计量口径，逐模块核对真实语义、原文回执、触发、反馈及闭环；每阶段保留全部失败与成本，额度耗尽即保存状态。
2. 小批结果审阅后，再确定 27 例协议的完整资源参数：机器、宿主及 bench/评分版本、公开难度规则、种子、每套每档一例调优和两例验证的任务 ID；固定累计业务额度、私有阶段额度、官方全部活动上限、并发、重复/重试、最大调优轮数与无进展停止条件。未知额度保持未就绪。
3. 在九例开发样本中配对运行 RC-off/候选并按预设停止条件调优。四模块按自然适用性运转，独立注入场景不计官方成绩；验证信息与调优隔离，不读取隐藏答案。
4. 冻结插件及运行清单后运行十八例最终验证；各 bench 分别按既定固定任务集合判断官方成绩和有效 F2P/P2P，并附逐例、等权/加权结果及完整成本。看过验证结果后的修改进入新开发轮次。

预算后续决定；本轮不继续新优化候选，不启动真实模型或旧 ArkTS 实验。恢复入口是 [任务清单](rc-cross-benchmark-optimization-tasks.json) 的 `offlineIntegration` 与 `nextStage`。
