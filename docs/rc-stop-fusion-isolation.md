# RC Stop 小措施融合隔离实验（2026-10-11）

基线为当前分支 `codex/openclaw-2026.7.1-2` 的 `2343d99`。隔离分支 `codex/rc-stop-fusion` 仅调整 RC，保留当前监督执行、交互控制、压缩恢复、Stop 分类、纠偏预算和取消逻辑。

## 采用范围

- Reviewer 私有逐项进度：save 仅返回保存状态与对象身份，get 按需读完整草稿；工具只在所属 Reviewer 中可见。
- Stop Reviewer 最终输出无效或其自身超时时，程序回传同任务、同需求/证据版本且来源仍有效的已完成草稿；整体保持 UNVERIFIED，不推断最终 Stop 分类。取消或共享截止耗尽不会借此继续反馈。
- 空来源根或空扩展名配置不能证明模块不存在；原需求和 HARD 判断范围保留。
- Stop 反馈保留所有已有发现，相关需求合并呈现；未审、检查器错误和放行状态明确区分。模型选择路径/行号，程序取得并保存原文；冻结文件关闭后仍用持久快照位置。

这些是独立功能检查数，不是完整 PRD 完成率。Todo 的 CSV 与 JSON 同路径覆盖、厨房的小数份数导入和不兼容备份保护仍未解决。

花店整体验收仍出现检查器错误，但融合反馈把已有的三条实现发现交给宿主，包括停用花束的草稿仍能确认。宿主补上确认时的启用状态检查，对应独立测试从失败变成通过。这是本轮实际业务收益；没有把终审错误说成 PASS。Todo/厨房的空扫描模块缺失误报也未再出现。

融合组三应用未自然调用 save；不宣称自然草稿恢复率已提高。另一次真实 SDK 故障注入，仅使用 Todo 三个原对象：两次最终输出被改成无效 JSON 后，程序交回 3/3 已保存判断，整体 UNVERIFIED、最终分类未推断。实际 save 确认均为 81 字符，仅含 saved/objectId/state；主宿主工具隐藏，宿主配置与业务文件保持不变，原文引用逐字一致。
