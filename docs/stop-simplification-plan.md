# Stop 简化：目标、进度与验收

目标是让 Stop 直接审查真实工作区，自行规划、少启动 Agent，并用可靠证据得出准确的逐项结论。优化不能靠隐藏验收项、缩减分母或把故障伪装成通过来完成。所有实现、测试、文档和实验留在本 worktree，不修改 MatrixAssistant 或它内置的 OpenClaw。

## 已实现：原工作区按需读取

- Claude、CodeAgent、OpenClaw / MatrixAssistant 默认 Stop 共用 `stop-workspace-review.mjs`，不准备代码仓副本，也不以源码清单限定可读路径。
- `source_read/grep/find/ls` 支持绝对路径、父目录和链接；导航分页，源码按需读取。默认跳过常见生成目录仅影响递归导航，显式路径仍可读取。
- 保存原始依据、过程记录和回执，不生成 `input/project` 或 `frozen-source` 源码镜像。
- 跟踪实际读取/搜索的文件、检索目录和链接目标。相关证据变化使旧结果失效；未访问文件的内容变化不触发全仓重扫。
- RC 可变日志、笔记和本次运行输出是可读上下文，不充当业务证据，也不因继续写入而使业务证据自我失效。原始基线、过程记录和 Skill 仍必须校验。

证据：`test/stop-workspace-review.test.mjs` 覆盖外部与链接文件、无镜像目录、已读文件变化、检索后新增文件、可变日志和历史凭据恢复；真实外部契约案例在 CLI 与原生宿主上均成功读取。

## 已实现：一次 Stop 一个审查会话

- 同一私有会话选择停止类型，规划调查顺序，检查所有选定指标、findings 与可选文件质量。
- `reviewGroupSize` 只控制结算回执分组，不决定默认模型会话数量。
- 必要的来源基线更新单独保留；它是权威来源提取，不重复承担实现审查。
- 确定性能力检查与设备验证通过程序结果交给同一审查者，不再启动实现审查 Agent。
- 最多在同一会话续跑一次，沿用截止、读取凭据、已保存项与笔记。
- 简单流程通过 `review_checklist(stopClassification)` 同时选范围并取得清单，通过最后一项的 `submit_review(finish: true)` 一并结算。缺项时提前请求结算不会跳过剩余条目。计划、笔记工具按需使用。

证据：生产协议回归中的阶段完成、任务完成、中间输出各启动一个会话，同一流程原先的八次模型调用缩减为三次。这个数字来自受控协议回归；实际小案例记录均为一个私有审查会话。

## 已实现：生产入口收口与发行包精简

- 原生和 CLI 的生产 Stop 模型入口仅接受 `workspace-stop`。旧分类、findings、指标或分组请求会在模型启动和证据准备之前被拒绝，没有自动回退。
- 旧原生运行器移入仓库的 `test/compat/legacy-stop-task-runtime.mjs`，机制测试和显式开发对照通过程序注入使用。旧配置值不会启用这些组件。通用 CLI 传输、跨角色移交和非 Stop 来源核验继续独立测试，不把这些功能误删为旧 Stop。
- 三种发行包都排除旧审查 worker、分类/分组调度模块、旧提示词文件和 TypeBox。构建器不再打包这条依赖闭包，也不发布其包与锁文件；声明新的运行依赖会使构建失败。
- 基线提取原本还间接导入旧 worker 取得 `excerpt`，现改为共享证据工具。复制安装目录后，在没有 `node_modules`、且环境 TypeBox 被故意设为失败的条件下，真实插件入口、基线提取和工作区引擎均能导入。

生产编排层现已一并收口：不再依据工厂能力标志选择旧分类、指标收集器、分组模型、补充文件模型或独立实现审查。`production-stop.mjs` 只结算已完成的同一工作区审查结果；分组保留独立回执，不再启动模型。旧通用收集器继续服务非 Stop 角色和显式开发对照，生产 Stop 不再调用它。

- 候选文件收集移入同一会话选择范围后的程序回调，中间/等待/阻塞范围不扫描交付内容。范围结果和清单提供实际候选路径，读取工具继续按需调查原文件。
- 完整输出先验证再分组：未知与重复对象不能被分组筛掉；部分保存保留原始分母。质量结论验证后使用实际校正的结果数组，缺少的已请求文件明确保留 UNVERIFIED。
- 旧过程偏差的无进展检查复用本次完整审查，不先做窄重查再启动全量审查。原始要求、证据归属、M16 证明和动态证据检查继续执行。
- 原生终态处理同时识别新工作区协议和已有的旧账本标记。来源核验、可信业务启动、额度、取消、文件变化、确定性能力检查及非 Stop 独立实现入口均继续验证。
- 测试中的旧多会话模型已迁移为单会话工具与回执，真实读取/缺证据/伪造证据/超时断言保留。复验场景中的实际源码依赖显式登记，不能让仅有脚本化占位证据的相反结论冒充代码变化。

旧完整生产对照入口已退役，开发脚本拒绝把新的工作区编排标为旧流程。之前保存的真实旧、新完整流程记录仍可离线审计；旧单项组件仍能显式运行。

## 已实现：共同协议与可靠证据

- `review_changes` 提供 Git 状态、diff 和宿主编辑路径/片段，作为调查入口。原生 `edits[]` 逐处展开，分页保留所有修改入口；CRLF 补丁路径也可正确解析。
- `review_plan`、`review_checklist`、`review_notes`、`review_history` 支持自行规划、逐项验收和压缩后恢复。
- 每项独立保存；未完成流程保留有效条目和未完成状态。
- 原始依据必须完整读取。OpenClaw 的真实 `tool_result_persist` 或所属 CLI 会话完整、匹配的工具结果才授予引文资格。仅执行 MCP 调用、持有引文编号、导航、笔记和最终文本都不能冒充原文证据。
- CLI 在全新私有会话中使用同一套工具和校验，续跑恢复原会话；关闭内置写入、命令执行和派生 Agent 工具。共享协议不再依赖原生宿主库或环境中的 TypeBox。
- M08 保留原始 Skill、传递依赖和完整条件核对；M16 保留生产链证明。对 stateless 流程显式说明资源数组应为空，避免无谓提交修正。
- M12/M13/M15 的纯执行义务，必须读到可对应的原始调用及结果，或程序实际产生的执行结果。仅有完成声明或缺失记录不能证明运行成功或失败，保留 `UNVERIFIED`。

开发期真实模型曾将“没有执行记录”误判为违规，也曾因搜索自身日志导致证据自我失效。上述校验与上下文区分针对这些实际失败修复，随后用真实模型重新验证；不能只靠提示词要求模型自行避免。

重复显式验收还暴露了一个身份问题：缺少 `assessmentId` 会复用 `undefined` 下的旧结果。事务入口现在拒绝缺少或含糊的身份；允许省略上下文的需求更新命令自行生成独立身份，不改变其调用方式。Windows 并发验证还实际捕获了 `EPERM` 原子替换失败；原生回执和 Session 设置现在复用既有的有界重试策略，设置文件每次重试前重查外部编辑。故障注入验证回执不会因短暂占用停留在 RUNNING，手工编辑也不会被重试覆盖。

CLI 取消也验证了真实进程树：主进程结束不等于其 MCP 子进程已退出。传输层现在有界等待所属终止操作；取消回归先确认 CLI 与桥接进程实际启动，再验证两个 PID 都已退出。临时目录清理只增加有界系统占用重试，没有删减取消或迟到提交断言。

## 真实模型验收记录（2026-10-28）

开发脚本 `scripts/evaluate-stop-workspace.mjs` 仅在显式 `--live` 时调用模型，不属于默认测试或发行包。每个案例创建独立项目、冻结要求和 Git 基线，记录实际结论、工具调用、用量来源及运行目录。CLI 每例有 180 秒和 0.25 美元上限；原生宿主不能执行该美元上限。直接原生审查使用 180 秒窗口；完整生产对照使用 210 秒总窗口，其中 30 秒留给结算，实际审查仍为 180 秒。原生对照每个引擎使用独立进程。凭据从环境读取，不进入保存的配置和报告。

三个已知答案的小案例：正确的 `value + 1` 实现应 PASS；实现为 `value`、而外部契约要求 `+1` 时应 DEVIATION；只有完成声明、没有要求的 `node --test` 调用及结果时应 UNVERIFIED。

- 本机 MatrixAssistant 内置 OpenClaw 2026.7.1-2 通过实际插件加载器加载构建产物、使用 GLM-5.3-flash，三例也均符合预期，各一个已结算的原生审查调用。它们验证真实工具注册、外部读取与原生读取回执。
