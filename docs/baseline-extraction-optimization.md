# 基线提取优化：方案与实验

## 目标与实现边界

基于 `b1297e0ac882d7f412412961d4a2ad08259f7c28`，在外部 Git worktree 的 `codex/optimize-baseline-extraction` 分支实施。worktree 共用原仓库 Git 对象库；运行时不创建仓库副本，不改 MatrixAssistant 或其 OpenClaw。冻结目录只存本次授权来源文本和原基线，保留既有来源校验。

先检查来源协议、提取提示、触发游标、历史恢复、宿主会话和活动事件；再补工具、接入生产路径；最后以协议回归、可重跑性能实验和真实模型小样例验证。

## 八项要求如何落地

1. **适中粒度。** 每条基线对应一个用户操作或结果，附带其条件、异常分支、例外与禁止项。创建订单的字段约束不拆散，CSV 的禁出列跟随导出要求；不同工作流分开。条目内保留可定位的子条件，反馈指向具体失败条件。既有 claimId 不因整理措辞而重写。
2. **工具与 skill。** 私有 `lib/review-task/skills/baseline-extraction/SKILL.md` 由提取程序加载，不加入业务宿主的公共 skill 清单。新增 `baseline_notes`：按稳定键更新、字面搜索、分页恢复、删除，保存来源指针和未决事项。每任务最多 64 条、总计 64KiB；笔记不授予证据权限。
3. **token 与耗时。** 删除启动提示中重复的大来源身份清单，保留请求身份、必读路径和固定路径映射。完整来源仍须阅读。缺口计算由逐行重复扫描改为合并读取区间。小查询缓存最多 16 页；实测 token 与字节指标分开记录。
4. **自然协作。** 任务级普通刷新共用专用基线协议，覆盖用户输入、执行检查和 Stop；Skill/文档专用抽取维持其原协议。原有来源摘要游标未变化即跳过，避免每次工具调用都启动模型。提取过程不往宿主追加日志，已存在的审查路径只发送可行动的发现。来源变化不能静默变成 NO_CHANGE。
5. **无仓库副本。** 不增加 clone、archive 或整仓复制流程；实验只生成合成文本。构建仍按运行模块白名单生成插件交付产物。
6. **高效导航。** 从已冻结文件清单检索，不遍历业务仓库；find/ls/grep 采用有界 JSON 页。后续请求同时传 `nextOffset`→`offset`、`nextLine`→`line`，解决 100 条之后无法继续的问题。grep 在文件中分页；相同检索页可直接复用缓存。所有导航都不授予读取覆盖。
7. **会话生命周期。** 相同宿主进程/API 所有者、项目真实路径、agent 和执行配置共用一个串行基线会话；并发请求等待且受各自取消/绝对截止约束。每次新建 runId、工具绑定、候选、来源凭据和运行租约。上一运行未实际退出时不能复用。空闲 10 分钟删除原生会话身份；模型/权限配置变化隔离。文档纠偏角色仍按次创建，结束后释放。它不是常驻模型循环，也不保证跨进程恢复。
8. **轻量标识。** 宿主原生 tool-progress UI 显示 `RC · 读取基线 / 整理基线 / 校正基线 / 基线待校验`。阶段变化立即更新、同阶段去重；复用现有有限心跳，取消和结束解除监听。不发送 assistant 文本，不把候选完成显示为验收通过。

## 保留的正确性约束

- 原文完整读取只能由当前会话真实 `tool_result_persist` 凭据确认。旧会话消息、旧引用、笔记、导航、synthetic 回执都不能补足新请求。
- 每个候选操作仍绑定原始来源，保持权限等级、冻结规则、条件、版本、claimId 与任务归属校验。
- 当前请求身份不同的笔记自动标记 `stale`；任务隔离，来源引用必须属于当前来源目录。
- 领域修复、并发等待和 compact 不重置截止时间。超时、取消、输入改变仍不能发布部分基线或推进游标。
- 宿主原生 compact 管理长期会话窗口。上下文复用可能增加历史输入；没有将会话身份复用率当成 token 节省率。

## 可重跑实验

无需模型：`node scripts/baseline-experiment.mjs`。结果保存在 `.runtime-correction/baseline-experiment/results.json`。它对照原版逐行算法检查缺口完全一致，检验多页完整导航、重复检索和 12 次身份复用，并报告合成大来源目录的启动提示字节。CPU/文件系统缓存和并发负载会影响时间；字节不是 token。

真实模型语义探针：`node scripts/baseline-model-experiment.mjs`；未用于提示调优的样例用 `--heldout`。显式运行才调用用户现有 Claude 可执行文件，使用默认模型、合成请求、结构化结果，关闭工具、MCP、外部定制及会话持久化。它不读业务数据，不建立仓库副本。它只验证语义分组，不等同完整 MA 内运行。

所有真实模型原始结果分别落盘；初版 skill 的失败结果也保留。完整宿主模型循环、长期上下文缓存命中率、真实 UI 尺寸和长期 token/耗时分布仍需后续更长样本，不能由本轮小实验外推。
