# RC Stop 简化对照实验计划

## 臂与重复次数

| 臂 | Stop | 需求基线 | `originalRequirementsBasis` | `deviationOnly` |
| --- | --- | --- | --- | --- |
| A | 开 | 开 | 关 | 关 |
| B1 | 开 | 关 | 开 | 关 |
| B2 | 开 | 开 | 关 | 开 |
| B12 | 开 | 关 | 开 | 开 |
| S0 | 关 | — | — | — |

四个 Stop 臂统一使用同一份融合安装包，只切换本表中的配置。A 关闭两个 Stop 简化开关，保留现行基线配置。C 在 Stop 对照中保持关闭。`rc-simplify-a`（`efb0577`）的安装包用于门禁一致性对照。C 独立对照。S0 只引用既有首稿记录，例如 etree 注入后的官方新增项 48/52、回归项 15/15。

| 轮次 | 样例 | 重复 |
| --- | --- | --- |
| 一 | `internal-correct`、`six-functions`、`external-bug`、`hidden-dependency`、`alias-bug`、`missing-run`、`mixed-skill` | 每例 A、B1、B2、B12 各 3 次，共 84 次 |
| 二，修复闭环 | etree `DeepEqual` 恒真注入，沿用既有注入前快照、注入方式与原版官方评分器 | A 和入围臂各 2 次 |
| 二，只审首稿 | HTTPX multipart、etree XML diff/patch/merge、Narwhals rolling window 的既有冻结首稿 | 每例 A 和入围臂各 2 次，第二轮共 16 或 24 次；无入围臂则结束 Stop 对照 |
| C | `kitchen/requirements.md` 的 6.1 纵向版本，只做新建菜谱、添加食材和步骤 | C 开、C 关各 3 次，共 6 次，每次最多 30 分钟 |

各样例按重复轮次交替跑臂。第一轮从 `A → B1 → B2 → B12` 开始，每次重复把起始臂轮转一位。第二轮每例从 A 开始，第二次从首个入围臂开始。每次使用新的隔离项目和配置。对照内固定模型、传输、预算与样例输入。失败和超时保留在原序号；限流导致计划无法完成时暂停。所有模型运行使用现有隔离 Gateway，按本计划确认后启动。

第一轮使用 native Stop 审查。A、B2 使用固定基线夹具，B1、B12 将同一案例需求作为真实用户消息交给 Stop，保留原有材料及 Skill 来源。第一轮只比较反馈效果和 Stop 本身的用时、用量及预算内完成率。第二轮 A、B2 启用真实基线提取与审计，B1、B12 用原文清单；冻结首稿只执行 Stop。首稿、公开需求及评分输入按既有记录核对摘要。自然样例以官方测试校验反馈对应的真实缺陷。Narwhals 复用既有同版本 CPU 兼容运行库及原版评分器文件。

## 计分和判定

- 检出以实际发出的修复反馈为准。第一轮的注入缺陷是 `external-bug`、`hidden-dependency`、`alias-bug`。反馈需要指向相应缺陷。正确实现 `internal-correct`、`six-functions` 上每次错误反馈计一次误报。`missing-run` 与 `mixed-skill` 保留逐例记录，缺少运行证据与真实反证分别记录。对这些样例发出的无依据修复反馈也计入误报。
- 第二轮记录 etree 首次 Stop 是否命中注入、最终官方新增项通过数与回归通过数，以及冻结首稿的真实检出和误报。官方结果缺失时标为不可判定，保留运行记录。两次 etree 官方新增项通过数都报告，用两次通过数的平均值对比 A。异常或缺失的官方评分不能作为主指标达标的依据。
- 每次记录臂、样例、序号、是否实际发反馈及反馈是否命中、完成状态、RC 耗时、RC token 和用量覆盖率、插件包 SHA256 及配置摘要。覆盖率为有完整用量的 RC 调用数除以观测到的 RC 调用数。用量缺失保留为空，覆盖不足的 token 对比标为不完整。第二轮 A 单列基线提取与审计占 RC 总耗时和 token 的比例，作为可节省上限估计。
- 第一轮任何臂检出率低于 A 或误报多于 A 即淘汰。其余候选按预算内完成比例、RC 耗时、RC token 顺序比较，最多取前两名。按同轮同样例计算 A 重复运行的极差，候选均值和 A 均值的差超过该极差才记为变化。预算内完成比例同样使用逐次 0/1 记录的极差。每个次指标按改善样例数减退步样例数排序，逐例报告方向和差值；各项都持平时按简化顺序破同分。用量不可比时保留该项的不确定性。
- 最终推荐须同时满足注入检出率、正确实现误报数、etree 修复后官方新增项通过数均至少达到 A。次指标在噪声范围内持平时，依 `B12 → B1 → B2 → A` 优先。证据不足时报告未能判定。结果包含是否建议删除基线代码。

## C 检查点

需求 SHA256 为 `5b59fab560565602276a94485899c073dc3b8a2f973bd743be2de91ece7988fd`。全文原样作为第一条用户消息，下一条消息给出裁剪范围。隔离项目内无需求文件。两臂均启用 F 的原文存档并关闭 Stop、Skill、文档纠偏。仅 C 开关不同。正式运行前在隔离 Gateway 做一次不计分校准，确认降低后的阈值能在几轮内触发真实压缩。将校准验证的 `agents.defaults.compaction` 设定及模型上下文窗口写入本节，再固定用于两臂。校准候选固定为模型上下文窗口及 `agents.defaults.contextTokens` 均为 65536，`reserveTokens` 和 `reserveTokensFloor` 均为 49000，`keepRecentTokens` 为 1000，关闭 `memoryFlush` 和 `truncateAfterCompaction`。宿主预检的名义阈值为 12536 token，实际触发情况由校准记录。首次确认压缩后继续一轮，然后发送固定提问并结束。压缩未发生或单次超时计未完成。
