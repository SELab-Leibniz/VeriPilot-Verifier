# 整份约 164K 的 SDD 直接作为第一条用户消息

2026-11-25。独立验证基于 `0ddd399`，宿主为 MatrixAssistant 附带的 OpenClaw `2026.7.1-2`。主样本是中文流程规范，正文 **164,012 tokens、278,357 个 Unicode 字符、734,837 个 UTF-8 字节**。第 4、2,281 和 4,557 行分别放入适用范围、中段审批条件、末尾重试例外。

实验创建全新业务会话，把全部文本一次传给原生 `runEmbeddedAgent({ prompt })`。默认宿主预算为 200,000，预留 20,000，预检输入预算为 180,000。每个对照用不同的空会话。本地提供方用对应模型的公开 tokenizer 和模板计算完整请求，并按“输入 + 请求的最大输出 ≤ 204,800”模拟一种容量政策。宿主运行、预检、工具调用、请求正文和压缩边界均实际采集，模型的工具选择、回复和摘要由脚本给出。

## 首条消息的结果

**中文正文在默认配置下被挡在第一次模型请求之前。** 预检约 290,000 tokens。前序消息数为 0，可裁工具结果为 0 字符。宿主三次尝试压缩旧历史，三次均记录 `no real conversation messages`。普通请求、摘要请求和已提交的压缩边界均为 0。单独把最大输出从 65,536 调小到 8,192，仍在同一处停住。

**相同原文有实际输出空间。** 诊断对照把宿主预算和它看到的模型窗口提高到 400,000，保持模拟提供方的硬上限 204,800。首包携带系统提示、工具定义和一条包含完整规范的用户消息，公开模板分词为 165,351。此时尚余 39,449 tokens，容得下请求的 8,192 tokens 输出。读取一次真实源码后的下一包为 165,472，再次携带规范的完整字节。两包内均恰好出现一份原文。把请求的最大输出设为 65,536 时，首包仍可派发，模拟提供方按输入与最大输出之和拒绝。本组的 400,000 仅用于让相同原文通过宿主预检，以观察完整请求。

**同样称作“164K”的输入表现不同。** 下表的预检取宿主首次日志。首包分词取实际派发的完整请求。正文 token 数由同一个 tokenizer 直接对原文计算。各组会话 ID 和目录不同，复跑时完整请求的数字会略有浮动。

| --- | ---: | ---: | ---: | --- |

| 同一中文 SDD，默认宿主，最大输出 8,192 | 164,012 | 290,087 | 无请求 | 首轮被挡 |

中文和密集附录的正文 token 数只差 16，预检相差约 225,100。单看这两个样本，中文首包被高估约 75%，密集路径和 JSON 被低估约 61%。两个比例只描述本组语料。路径里的反斜杠按解码后的消息分词，外层传输 JSON 的转义不重复计数。

## 进入 Stop Reviewer 后

默认中文首轮没有生成业务模型答复。为测下游，取相同原文成功派发组的真实业务 transcript，经 RC 原有转换和 `loadStopOriginalRequirements` 送入原生 Stop Reviewer 工厂。这里显式发起一次 Stop，分别测量业务入口与私有 Reviewer，也保留各自失败的位置。

RC 将原始用户消息按不超过 16,384 字节的 UTF-8 边界分成 45 段，全部进入必读集合。这些文件拼回后与首条 prompt 逐字节相等。这里的“256 KiB 后转按需参考”规则只适用于点名的文件。对于本次直接粘贴的外部用户消息，45 段均受完整读页门槛约束。脚本故意在读取之前建清单，两组均收到 `Required original basis not fully read`。已收到的完整工具结果与 RC 保存的读页回执按正文 SHA-256 核对。

| 同一份 734,837 字节的首条原文 | 默认 Reviewer | 放宽宿主预检的 Reviewer |
| --- | ---: | ---: |
| 有完整回执的原文段数 | 42 / 45 | 45 / 45 |
| 对应的原文字节数 | 688,090 | 734,837 |
| 普通请求数 | 15 | 23 |
| 单个普通请求的输入峰值 | 120,840 | 208,662（该请求被拒） |
| 普通请求输入累计，含派发后被拒的请求 | 1,094,869 | 2,302,518 |
| 成功的摘要请求 / 已写入的压缩边界 | 2 / 1 | 2 / 1 |
| 原文清单及单项判定 | 建清单前停住 | 保存末尾例外的 `DEVIATION` |

默认 Reviewer 有一条工具结果随普通请求重复出现 8 次。一次原生压缩把相邻普通请求中的工具结果从 22 条减到 9 条。继续读页后，最后一次预检估到 204,551，可再裁工具结果为 0 字符。再试压缩时两次记录 `no real conversation messages`，最终返回 `REVIEWER_RUN_FAILED`。前 42 段的回执仍在，其中 39 段能与已派发普通请求内的正文逐条匹配。最后一批 3 段已由工具交付并落盘，后续普通请求未能派发。

放宽预检组有一次 208,662 tokens 的普通请求被模拟提供方拒绝。宿主发出两次较小的摘要请求（51,218 和 51,522 tokens），完成一次压缩。下一次普通请求只需 61,567 tokens，工具结果从 43 条减到 9 条。原有回执经检查点重新校验。45 段读完后，Reviewer 通过工具重新取得末尾条款和当前源码，在同一个请求中据此判定偏差。

末尾原文要求密封模式重试 0 次。候选函数实际返回 3，Node 调用作为独立答案。核查脚本预先知道例外的位置，只为这项创建清单。其余条款的语义覆盖和线上模型自主发现例外的能力需要单独评估。

## 这一场景如何处理

1. **首条消息被拒时，由宿主解决输入准入。** 核对文本单位、模型模板下的完整输入和该提供方的输出预留方式。当前业务调用在任何工具执行之前就停住，无法借旧工具结果裁剪或历史摘要腾出空间。400k 是本实验的诊断手段。
2. **需要支持一次粘贴大规范时，客户端或宿主可把全文冻结为带版本的原件。** 给模型一条短指令，说明整份原件均为任务依据。文件对照只把文件名发进首包，下一包约 1,700 tokens，包含宿主实际读出的三行。该文件的 SHA-256 与粘贴版相同。RC 的点名文件清单却把这份 734,837 字节的文件记为 `mandatory: false`。产品采用这条路线时，须把“整份规范生效”单独记作审查范围。三个定位点成功读取只证明文件可访问。[点名文件规则](../lib/runtime-v2/original-requirements.mjs)
3. **进入审查后，RC 持有原件、范围、回执和待核实项，宿主负责上下文。** 本例默认 Reviewer 停住时，清单尚未建成。此前仅验证过“已经建好清单”的续审路径。此时可记录尚欠的原文范围，后续验证同一版本的分批提取与统一封存。需要提前结束时，应展示本次审查未完成。[原文与必读集合](../lib/runtime-v2/stop-workspace-review.mjs) · [已验证的分支策略](large-sdd-review-strategy.md)

## 复现

依赖与 tokenizer 的来源、固定版本、校验方式见[上轮运行说明](large-context-validation.md)。在本分支根目录运行下列 PowerShell，用 `--output-root` 指向新的目录。

~~~powershell
npm ci --prefix lib/review-task --ignore-scripts --no-audit --no-fund
$assets = '../large-context-validation-20261125/.runtime-correction'
$hostRoot = 'C:/Users/user/workspace/program_workspace/MatrixAssistant/resources/openclaw'
$null = New-Item -Force -ItemType Directory '.runtime-correction'
node scripts/validate-large-context.mjs --host-root $hostRoot --python (Join-Path $assets 'large-context-venv/Scripts/python.exe') --tokenizers (Join-Path $assets 'large-context-tokenizers') --cases initial-sdd-164k --output-root '.runtime-correction/initial-sdd-repeat'
~~~

正文 token 数使用业务模型 `deepseek-v4-flash` 的原文分词。实际派发的请求使用业务模型或 Reviewer `deepseek-v4.1-flash` 各自的完整消息模板，包含系统指令和工具 schema。主会话使用原生嵌入式接口、最小系统提示及 `read` 工具。MA 图形界面完整提示、真实模型推理和线上提供方计费口径不在这组数据中。[用例与断言](../scripts/helpers/initial-sdd-pressure.mjs) · [原生实验入口](../scripts/validate-large-context.mjs)
