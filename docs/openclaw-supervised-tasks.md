# OpenClaw 受控任务与防递归约束

目标版本：2026.7.1-2。更新：2026-09-13。

本文件约束后续的任务级自动续跑实现。**任务控制器尚未实现；本文不是功能已完成的声明。**
现有插件的写后检查、完成检查和内部评审继续工作，宿主最终续跑限制见 [专用指南](openclaw.md)。

## 保持的含义

主任务修改后重新验收，是必要的正常循环。需要阻止的是：评审再创建评审、
纠偏轮次再创建一个独立控制器，以及重复事件反复消耗预算或启动执行。
不能为了防递归而关闭主任务的后续检查，也不能只依赖模型遵守提示词。

## 单一控制权

同一个任务、需求版本和受控会话只有一个控制器。执行和验收按顺序完成：

```text
执行当前任务 → 原插件验收 → 通过：报告完成
                     └→ 未通过且原预算允许：安排一次修正 → 再验收
                     └→ 取消、预算耗尽、等待用户：记录原因并停止续跑
```

| 身份 | 可以做什么 | 不可以做什么 |
| --- | --- | --- |
| 任务控制器 | 接收真实用户任务，读取原验收决定，串行安排执行与交付 | 重入自己、同时安排同一任务的两个执行轮次 |
| 主任务执行轮次，包括修正轮次 | 修改实际成果，接受原工具前后检查 | 创建子控制器，把纠偏反馈当成新需求以重置预算 |
| 内部评审，包括抽取、裁定、语义和完成评审 | 在只读隔离会话中检查冻结证据，返回结构化结果 | 创建评审、启动修正、修改成果或向用户交付 |

受控任务模式下，完成 Hook 和外层控制器必须共用一次验收决定与一次预算扣除。
不能同时由 Hook 请求宿主重试、由控制器安排另一次执行。普通插件模式保持原有行为；
只有通过已验证的控制器身份进入受控模式，才移交续跑决定权。

## 续跑实现必须满足

1. **身份来自执行记录。** 将任务、需求版本、控制器代次、轮次及来源绑定到真实执行。
   `USER_REQUEST`、`CORRECTION`、`REVIEW` 必须可区分，不能仅检查提示词中的字符串。
   修正轮次仍属于主任务；只有评审身份整体跳过纠偏 Hook。
2. **先记录再派发。** 为同一任务持有唯一执行权，持久化每轮的派发与结果消费状态。
   重复 Hook、断线重试、插件重载和进程重启都不能启动第二个控制器或重复扣除预算。
   无法确认上一轮是否结束时，先核实执行状态，不盲目重新发送可能产生副作用的操作。
3. **预算不随运行轮次重置。** 所有修正共用原需求版本下的次数和截止时间，调用原有
   偏差去重、终止及状态判断。连续未修好必须按原策略终止，不能通过新建任务无限续跑。
   自动反馈不能提高原需求权威或生成一个新的用户需求版本。
4. **取消优先。** 在安排下一轮和交付前重新核对取消状态与控制器代次。
   已取消或已失去执行权的旧回调只能记录结果，不能恢复任务。原 `WAITING_FOR_USER`、
   `UNVERIFIED`、预算耗尽等状态不能被当成通过或无条件继续的指令。
5. **结果按轮次消费。** 验收绑定对应执行轮次和证据版本。迟到、重复或失效的评审结果
   不能覆盖新状态、启动新修正或放行交付。结果生成后成果有变化时，原通过结果不能直接沿用。
6. **原检查逻辑保持。** Ground Truth、规则、语义评审、严重性、纠偏归因和候选补丁规则
   继续调用原实现；主模型负责实际修改。控制器只安排执行、消费决定和控制交付。

## 已补充的原生评审防护

现有会话标识和内部租约之外，原生评审增加了进程内的异步执行身份：

- 每次原生模型评审及其派生回调保留 `REVIEW` 身份；普通主任务不继承该身份。
- 模块被重新加载后仍共享这份身份，不依赖全局环境变量开关。
- 内部执行直接拒绝创建评审、交接评审或递归追问自己，且在分配资源或关闭原会话前拒绝。
- 评审 Hook 在会话元数据不完整时也会跳过。超时后的派生回调保留身份，
  不因租约及活跃会话清理而变成主任务；已建立的工具关联也保留内部来源。
- JSON 格式修复最多一次，与当前评审共用会话和绝对截止时间；修复失败交还原错误策略。

此异步身份用于同一进程内的原生评审，不是跨进程控制器锁，也不能代替上述持久化派发状态。

## 必须分别验收

已加入自动测试：评审嵌套创建及交接被拒绝、跨模块加载防护、递归追问不取消原评审、
JSON 修复有限次、元数据缺失时跳过内部 Hook、超时后迟到回调不创建主任务，
以及并行存在的主任务仍能接受检查和完成纠偏。

控制器实现后仍需验收：写后最终偏差自动修正至通过、同一轮重复通知只续跑一次、
取消与验收同时发生、无进展达到原预算上限、进程重启不重复派发、旧轮次结果不放行新成果，
以及修正提示不改变需求基线。通过这些测试之前不能声明任务级防递归或完整强制纠偏已完成。
