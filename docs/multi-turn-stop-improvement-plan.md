# 多轮需求与 Stop 验收改进计划

## 目标与边界

修复“快排后追加插排”暴露的六个模块：多轮需求接入、完成分类、审查范围、义务归属、审查可观测性、会话控制页。实现、测试、文档及隔离实验仅修改本仓库，不安装到运行中的 MatrixAssistant，不改宿主和历史运行记录。

## 行为约定

1. 用户输入是需求依据，Hook 只是处理时机。真实新输入支持基线新增、修订和显式撤销；延迟处理不能把新需求当作模型漂移丢弃。保留项目作用域稳定任务身份、历史版本和会话累计额度。NEW_TASK 标签本身不授权销毁旧任务；模型无新用户依据的切换继续拒绝。
2. 保持懒启动：首次闲聊不创建任务、不调用评审。已有任务的新输入先记录，首次纠偏相关动作或 Stop 前同步基线；失败保留未验证，不能使用过期基线宣称验收通过。重复事件与无变化输入不重复应用义务。
3. Stop 分类由隔离模型依据原始需求和最新回复作语义判断。完成后的可选建议不等于等待用户；代码实现不等于 tasks 文档阶段。增加结构化分类依据、阶段适用性和一致性校验，不用关键词自动颁发 PASS。
4. 区分全量对象、阶段选择对象、关闭指标和空范围。阶段的空指标声明不能悄悄吞掉待验收义务；无有效验收范围应明确说明原因并保留 UNVERIFIED。合法仅文件质量审查、关闭全部指标和暂未适用情况单独处理。
5. 原始义务保留，按证据归属分派。测试源代码、实际执行测试和生产实现相互独立；仅依赖已确认的结构化字段，不用文本正则推断来删除要求。
6. 保存每轮基线版本、对象清单、选择前后数量和原因。控制页显示明确目标会话、登记范围和有界任务历史，包括加入、派发未知、开始、完成；不能把领取后的任务直接从用户视野消失。

## 实施顺序

1. 基线的新用户来源游标、延迟刷新和新任务防漂移；以真实两轮输入的回归验证新增义务进入第二轮指标清单。
2. 分类协议与阶段范围校验；验证完成附建议、真正等待选择、外部阻塞、文档阶段、源码完成及未知/空范围。
3. 证据归属、每轮审查清单与明确状态原因；验证未启用/无对象/已完成但未验收之间的区别。
4. 控制页目标会话、登记说明、任务历史及中文状态；验证同项目多会话、立即执行、排队、未知回执、刷新恢复及旧页面竞态。
5. 相关测试、完整回归、三宿主构建与浏览器场景验证。检查失败必须定位，不以缩小场景、跳过测试或改变旧验收事实收尾。

## 完成证据

- 新增需求、修订、撤销、无依据漂移、重复输入和来源伪造的回归。
- 两轮完整生产入口：第二轮正式基线及待验收清单包含插入排序；错误分类或空范围不会变成 PASS。
- 分类协议的真实提交校验、截止和取消测试。
- 指标归属与报告清单测试；任务状态和历史跨重载恢复测试。
- 控制接口鉴权/身份校验及真实浏览器展示验证。
- 完整回归和打包验证；真实模型的概率性行为与离线机制证据明确区分。

## 实施结果与验证（2026-10-28）

六项改进已完成，具体对应如下：

1. **多轮需求接入**：`ground-truth-provenance.mjs`、`ground-truth-ledger.mjs`、`orchestrator.mjs` 跟踪原始用户消息身份和内容摘要。已有任务先登记待对齐输入，在首次纠偏相关动作或 Stop 前刷新；延迟到 Stop 的新要求仍可进入同一基线。新增、修订、撤销有真实新来源才获准，失败不消耗输入游标、不使用旧基线发布 PASS。新请求保留任务身份和已有义务；重复输入不增加相同义务。
2. **Stop 完成分类**：`classification-task.mjs` 和 `stop-protocol-task.mjs` 增加完成声明、必要用户决策和外部阻塞的结构化一致性检查。明确完成后的可选建议不缩小验收范围；纯实现任务排除不适用的文档阶段；显式空阶段不扩展成默认阶段。
3. **指标与阶段范围**：`review-routing.mjs` 和 `production-stop.mjs` 保留原始对象与本轮选择清单。空阶段指标、阶段无适用对象和仅偏差扫描分别记录原因；无有效指标验收且未启用独立文件质量审查时，保持 UNVERIFIED。既有合法文件质量流程保留。
4. **义务与证据归属**：`reviewer.mjs`、`ground-truth-ledger.mjs` 和 `metrics.mjs` 支持生产、测试及支持代码的结构化归属。测试源代码保留在 M12，明确标记 TEST 的义务不进入 M16；用户明确要求的测试执行保留为独立 PROCESS 义务。旧基线缺少归属字段时不猜测删除。
5. **审查可观测性**：运行结果和控制接口携带基线版本、范围原因、原始/选中/已审定数量及逐指标对象。控制页区分当前需求是否待对齐与最近一次已审查基线，切换会话清除旧展示，轮询保留展开的指标。
6. **会话与后续任务控制**：`post-run-dispatch.mjs` 和控制页明确显示目标会话及登记范围；任务有加入、提交、未知回执、实际开始和结束的持久历史。历史限最近 50 个任务，正文超过 4000 字时明确标示节选；未知提交不自动重发，执行结束与审查结果分别展示。

验证边界：多轮生产入口使用可控评审器和协议提交回执，验证需求发布、来源约束、范围计算、并发防护及结果传播；浏览器使用隔离调度器和测试 Gateway，不是运行中的 MA 会话。分类语义通过协议约束、提示和代表性场景加强，不能据此宣称真实模型对所有未来表述都能正确判断。未修改历史审查结论，也未安装或重启 MatrixAssistant；新实现位于本仓库和 `dist/` 产物中。
