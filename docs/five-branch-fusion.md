## 融合后的具体补充

除了保留五分支能力，还修正了实际实验暴露的接缝：

- **进度归属**：基线与 Skill 虽共用 extractor 角色，但显示不同标签；普通基线阶段变化不能覆盖 Skill 标签。专门的交叉回归验证阶段只走 tool/UI 事件。
- **提取可观测性**：提取会话把 QUEUED/READING/EXTRACTING/REPAIRING/CANDIDATE_COMPLETE/INTERRUPTED 写入当前任务的原子侧录，控制台可在决策尚未提交时展示。过期在途状态显示 UNVERIFIED；外任务侧录忽略。候选完成始终不等于正式发布或任务 PASS。侧录失败不能导致纠偏失败，不增加宿主消息。
- **准确的反馈关联**：投影先限定真实会话，再用 hook、evaluation、tool call 和文件身份索引关联；其他会话的回执不能确认当前反馈已送达。历史缺失身份仍保留未知，不猜测。
- **搜索效率**：一次建立关联索引，替换逐条记录的全 journal 重扫。搜索仍覆盖全量可读历史，先筛选后分页，原有 16 MiB 可读边界和显式损坏提示保留。
- **基线协议摩擦**：允许可选 `keep: []`，它不覆盖任何来源；空决策、未知/重复来源、空 split、未读来源仍被拒绝。私有 skill 明确省略无用字段，`fullTextReason` 只作模式切换、不能夹带普通草稿。没有自动忽略模式冲突或降低完整性检查。
- **Skill 触发依据**：先从实际阶段/原始完成声明/发布动作确定触发，再判断原文记录是否证明成功、遗漏或缺失。完整日志不代表任务完成；笔记和旧审查不激活完成条件，也不建立 PASS。

## 最终实验结果（2026-10-29，配置模型 GLM-5.3-flash）

机器可读数据、逐样本判断、计数、失败、候选及已发布条款见 [结果记录](five-branch-fusion-results.json)。下面的百分比仅为对应样本观察。

### Stop：指定起点分支与融合

相同六场景交替顺序：正确实现、隐藏依赖错误、缺少实际执行记录、完成后附可选建议、六项独立实现、项目外原始契约错误。两组都 6/6 命中，11/11 原始对象保留，分别 6 次审查启动和 6 次结束。

- 指定起点：278424 ms，含缓存宿主 token 计数 297241，47 次工具、22 次原文读取。
- 初次完整融合：272640 ms，计数 219704，38 次工具、17 次读取。
- 本轮 token 计数约减少 26.1%，工具调用减少 19.1%，累计耗时减少 2.1%。样本少且模型路径/缓存不同，不能宣称统计显著或证明某单一改动的因果收益。
- 完整矩阵绑定 `4e8654e` 的运行源码摘要；后续补充涉及阶段侧录、控制台、基线协议和 Skill 私有协议。最终源码又配对核验缺失执行证据：两侧均 UNVERIFIED，没有把缺失记录当作 PASS 或已确认偏差。最终全量测试覆盖其余边界。

### 文档：冷启动与复用加批量取证

当前融合代码上运行真实 CLI + 真实 MCP 文档工具，覆盖云端导入偏差、本地离线正确、遥测网络偏差。两组均 3/3 正确。

- 冷启动：3 个会话，输入含缓存 17574、输出 854，模型报告耗时 56790 ms。
- 复用加批量取证：1 个会话，输入含缓存 13045、输出 439，耗时 28225 ms。
- 输入减少 25.8%，耗时减少 50.3%。这里同时改变复用和导航方式，不能分别估计两者贡献；它不是两个分支真实 MA 桌面的因果 A/B。

### Skill：机制收益与负面观察

- 原始专项和融合使用相同 80 辅助文件机制实验；完整源恢复和笔记重建均通过。融合入口披露 708066 → 10833 UTF-8 字节，减少 98.47%；7 次热扫描内容读取均为 0。文件字节不是模型 token。
- 最初轻量披露模型实验：旧内嵌组 4/4，优化披露组 3/4；后者把完整日志误当作完成声明，不能宣传准确率不降。
- 完成触发规则明确后，用生产私有协议进行完整原文回放，加入未发布和验证失败两个负例。旧/新协议均 6/6。输入含缓存分别 4542 / 5076，输出 1002 / 1796，墙钟 52562 / 72874 ms。**新协议这组更长更慢，也没有证明总体准确率提高**；保留它是为了明确触发依据，并以原始失败作为持续回归材料。
- 该回放不提供私有工具，不冒充完整原生看护循环。原生私有工具的绑定、撤销、笔记和当前性另由工程测试验证。

### 基线：完整性优先，保留修复成本

两个新鲜场景为同一行独立流程与跨域预约要求，检查条件/例外/禁止项、独立流程分开、检查归属、来源绑定和正式发布。旧协议回放为 1/2，专项分支为 2/2，初次融合为 2/2，最终融合为 2/2；不是四组总体准确率估计。

- 初次融合：同一行场景 3 次调用、23049 token、45647 ms；预约 1 次、10980 token、17468 ms。额外重试分别因空 `keep` 和误用 `fullTextReason`。
- 最终融合：两例各 1 次调用；同一行 11492 token、20839 ms，预约 10528 token、11311 ms。条款数分别 9 / 12；完整原文和条件保留，候选及发布内容均存于结果 JSON。
- 同样两例的专项分支为 5628 / 5554 token、14194 / 13443 ms。最终融合累计仍比专项分支耗费更多 token、略多时间，不能描述为每项都超过专项最佳值。其提取引擎大体相同，采样、缓存、输入和模型生成差异存在。
- 旧协议回放为 11750 / 10760 token、41615 / 24867 ms；同一行例把独立流程合并且条数超界，按原规则判失败，不删样本。最终两例相对旧协议改善了本组完整性/粒度结果，不能外推到所有需求。
- 机制实验：50000 行的相同缺口恢复约 88.49 → 0.25 ms；240 个来源完整分页，重复查询约 101.75 → 0.19 ms；12 次刷新复用 1 个身份。以上都是生成数据上的工具开销。

### 控制台与体验

专项原版和融合索引版读取相同类型的 3000 条产物、6000 条关联事件，每组 7 次查询。中位数 260.64 → 20.67 ms，约减少 92.1%；选中记录、结论及反馈的 SHA-256 摘要相同。实验包含全量日志读取；尚未改为数据库或无限历史流式索引。

8 项真实浏览器检查通过：在途基线阶段、默认折叠、全文反馈搜索与文本安全呈现、筛选清除和分页、自动刷新保留展开与草稿、390px 窄屏、跨会话迟到响应隔离、单条记录深链接。生产 UI/RPC/证据投影真实，Gateway 传输为隔离实验替身，未发布到桌面 Electron。
