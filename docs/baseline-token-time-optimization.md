# 基线提取第二轮：准确性、token 与时间

最终四场景配对回放：新方案 8/8 通过预设条款、粒度和元数据完整性检查，旧方案 2/8。全部观察累计 token 减少 23.4%，回放耗时减少 56.2%；两侧均通过的两组分别减少 48.9% 与 47.6%。全量回归 1,717 通过、8 跳过、零失败。以下保留方案、失败过程和测量边界；这些数字不是完整 MA 长期运行的准确率或节省保证。

## 方案与验收

起点为外部 worktree 分支 `codex/optimize-baseline-extraction` 的 `f6def80`。继续保留项目会话复用、只读原文、完整读取凭据、原子发布、稳定 claimId、任务与来源隔离、有限修复和原截止。没有建立代码仓副本或修改 MatrixAssistant。

这轮优化不以减少必要阅读或丢弃要求换取节省：

1. 每个非空原文行形成一个草稿单元。模型按段落做决策：`keep`、`split`、`merge`、`exclude`，不重写完整正文。默认将一个流程的触发、字段、失败条件、例外和禁止项放在一起；只有不同功能共用一行时才拆分。不是按分号机械切成基线条目，也不规定所有任务必须有固定条数。
2. 拆分必须覆盖该行全部顶层分号条款且不得重复，引号/括号内部的分号保持完整；合并须同来源、原顺序的连续行。结束时程序检查所有单元已有决策。遗漏的全局要求不能因“已读”而静默消失。模型仍须判断语义分组，结构覆盖不是语义正确性的保证。
3. 模型提供显式共享 `defaults`，程序从冻结来源复制精确正文、生成规范引用并寻找当前真实读取凭据，再走原 schema、来源权限、领域与事务校验。未读、伪造文字、材料提升为用户授权仍拒绝。原始批次与展开候选都保持 50KiB 上限；默认值不推断权限。相同输入重试恢复原回执。
4. 操作 schema 已在工具参数中提供，取消在 system prompt 中重复一次。辅助 skill 用一个可执行形状示例减少无效修复。
5. 单分片冻结文件引用可确定地映射回原来源；真实目录 ref/alias 优先，来源种类、权限和读取范围继续校验，不猜测分片坐标。
6. 用户原文中的 agent 生命周期、工具、流程、恢复和 UI 要求属于 MAIN_TASK，即使其内容描述 RC 本身。不得把这些用户约束当成内部角色提示而丢弃。
7. `exclude` 只允许未采用材料上下文，或由显式当前 claimId 证明的重复用户原文。用户段落须与至少一条 USER_EXPLICIT/USER_MESSAGE 当前条目的完整文字一致，不能以子串或虚构编号蒙混。用户声明“引文不是授权”本身是约束，必须保留。其他语义排除通过完整文字协议处理。
8. 草稿模式只新增要求。已有条目修改、跨来源综合、分片来源、任一来源超过 128 行或总单元超过 200 时使用完整文字方式。`fullTextReason` 可在同一会话、原截止和原修复预算内切换工具；保留已存批次。SUPERSEDE 必须引用真实 claimId，并保留该条目内未修改的条件。完整文字模式不声称具有逐段决策完成保证。
9. 私有检查点记录分组名称、决策、剩余单元和笔记指针；`review_history` 分页恢复。原始文件、原基线和请求仍完整阅读；没有用笔记、草稿或历史摘要补足证据，也没有克隆业务仓库。
10. 每个新条目明确提供 `verificationTarget`；代码行为还须提供 `implementationRole`。`overrides` 调整某段的元数据，`split.groups[].metadata` 调整该段内不同流程的证据归属。仅出现在 overrides 中的段落等同显式保留整段，不会漏掉正文。不同有效元数据的段落不能合并为一条；程序不代猜权限、检查归属或适用条件。

之前的笔记、分页、缓存、同项目串行提取会话、文档纠偏按次释放、无 assistant 文本的阶段标识继续有效。对应测试还覆盖了旧笔记过期、compact 恢复、取消后未退出模型不得重叠、文档会话只释放一次、条件和全局义务保留。

## 配对实验方法

最终命令：`node scripts/baseline-paired-experiment.mjs --all-cases --repetitions=2`。早期三场景三次命令仍可单独运行：`node scripts/baseline-paired-experiment.mjs --repetitions=3`。

- 三份预设合成材料：花店及全局流程约束；跨段导入/权限/引用/纠正；同一行多个工作流、隐私与授权范围。每份三次，交替 before/after 顺序，共 18 个观察。
- before 使用 `f6def80` 的私有 skill、工具 schema/描述快照、重复操作 schema 及完整文字批次协议；after 使用当前逐段决策、短描述及共享元数据。两组材料、业务范围说明、生产角色 low effort 和修复上限相同。共同使用当前只读冻结与来源校验层，是提取协议的受控比较，不是两套完整 MA 安装对比。
- 真实模型由现有 Claude Code 默认配置调用，不指定新模型、不加载工具/MCP/用户定制。依据生产角色传递 effort。以累计 `modelUsage` 的输入、输出及缓存 token 合计为主，保留原始字段；不把顶层单次 usage 当总量，也不把字节当 token。
- 驱动读取所有 requiredFiles，并通过模拟宿主持久化边界的凭据将原始页完整交付模型。返回的批次通过真正的 RC worker、来源绑定、完成协议及正式账本发布，随后检查持久化结果。真实 MA Hook Runner 另行做契约测试。此回放不等同 live MA 模型循环、UI 和网络时延验收。
- 最多三次结构/来源修复，原截止不重置；每次模型调用、失败和修复的累计消耗全部计入。固定条款见证、关键条件同组、独立工作流不被合并及合理条数范围是预设检查；另由实现代理逐条核对文字含义、引用和条件，并非独立人工标注。检查失败的结果不删除。
- 耗时覆盖基线调用内的来源冻结、真实模型、候选校验和账本发布；不包含合成项目夹具建立，也不宣称宿主整体任务耗时。
- CLI 回放缺少原生函数调用信封：两组统一允许 JSON 外的说明文字，仅提取唯一完整 JSON 对象；存在多个候选则拒绝。不会把说明中的新要求加入基线。保留所有原始响应，解析、来源或结构修复调用都计入消耗。修复不提供验收答案。
- 最终增加预约跨领域场景，两次交替顺序对照，共 16 次观察。该场景最初为留出材料，后续检查归属工作也使用过，最终不称作未见过的留出测试。两组共同明确交付目标是业务应用及 RC 插件代码，避免把用户描述的运行能力误当作回放执行步骤；没有向模型提供验收答案。
- 可取得用量的失败调用照计；无法取得的用量标记 unknown，中途停止时未完成调用的消耗不估计为零。最终 16 次均取得完整报告用量，无未知用量、无修复调用。

## 早期探针发现

探针暴露了用户流程约束被误认为内部提示、重复输出来源文字、来源引用组合错误、条目过细、独立工作流混成一条、忽略单句全局要求等问题。直接范围选择与扁平 outcome 分组都出现过失败，未作为最终默认协议。逐段初版虽降低消耗，仍有把授权边界误排除的问题；随后增加当前基线覆盖验证。早期结果和中途停止的已完成观察均保留在 `.runtime-correction/baseline-paired/`，最终证据夹具会列出完整及中止试验，不筛除不利结果。未经正确性检查的低 token 结果不计为有效方案。

## 逐段核心协议阶段

实验编号 `2026-10-28T15-17-18-123Z`，真实默认模型返回 `glm-5.3-flash`。两组各 9 次，均一次模型调用完成，均通过当时的正文/分组检查和逐条语义复核。此阶段未要求每条都提供检查归属，不能当成最终完整验收。新方案花店为 8–9 条、导入为 9 条、同一行多流程为 9–10 条，保留了独立功能和可定位条件。

- 累计 token：61,553 → 39,977，减少 **35.1%**。输入 44,560 → 35,931；输出 16,993 → 4,046。本轮缓存读取/写入计数均为零。
- 累计调用墙钟：187.477 秒 → 105.605 秒，减少 **43.7%**。包含来源冻结、模型、候选检查和正式账本发布；不是整体宿主开发任务耗时。
- 九组配对均同时减少 token 和耗时。单组 token 减少约 9.0%–58.4%，耗时减少约 14.2%–69.1%。不依靠移除失败样本或只比较输出 token。
- 旧方案也全部通过当时正文/分组检查，因此该阶段收益不是拿不完整旧正文作参照。调试阶段不利结果同样保留：例如 `15-11-17` 的草稿初版虽减少约 52.6% token，但仅 8/9 通过，误排除授权边界，未接受为最终方案；扁平 outcome 预试只有 1/3 通过。

逐条检查确认：订单字段/可空条件、库存拒绝不扣减、取消释放、筛选导出与隐私、本地离线、不清空旧要求、项目复用与隔离排队、笔记非证据、UI 不进入模型消息均保留；导入原子拒绝、日志成本限制、查看/编辑权限、停用保护、15 分钟替代并保留其他约束、全局恢复与引文非授权均保留；同一行中的备注历史、仓库查询和日报分别成条，日报重试和禁止重复仍在同条。

完整模型输入、输出及来源冻结文件保留在忽略目录 `.runtime-correction/baseline-paired/<实验编号>/`。before 工具定义快照单独保存，不复制代码仓。去敏证据夹具由 `scripts/baseline-evidence-report.mjs` 汇总，既保存选定最终观察的累计用量、输入哈希、候选及发布正文，也保存先前完整或中止试验的结果。

这些是有限合成材料的受控结果。材料曾用于发现协议缺陷，不能据此估计所有项目的准确率或长期节省率；另以方案冻结后的新场景做留出检查。真实 MA 的模型工具循环、长期会话历史/缓存、compact 摘要质量与 Electron 实际显示仍不由这组回放证明。`modelUsage.costBasis` 为 unknown，累计计数也不作为最终账单金额。

## 检查归属补充与最终验收口径

交付复核发现正文完整还不够：后续检查必须区分代码、文档和实际动作。因此两组都补入生产编排器已有的检查归属指令；新工具允许按段/组覆盖元数据，并要求明确归属，最终样例检查也验证这些字段已正式入账。

检查归属不同可以产生必要的独立条目，例如“不需新文档”和“压缩后继续执行检查”。导入样例的条数上限明确从 10 改为 12；这是一项公开的验收口径修订，不能把两阶段通过数直接对比。完整条款、关键条件同组、独立流程分开、引文非授权、原文证据和事务校验均未放宽。`15-32-42` 轮仍保留其旧口径和协议错误结果，未拿它宣称最终成功。

## 最终四场景结果

实验编号 `2026-10-28T16-04-26-368Z`，四个场景各两次、交替前后顺序。两组各八次模型调用，所有调用及正式发布均记录；没有把旧方案的失败观察移除。

驱动的 `allPassed` 检查两组，因此本轮因旧方案失败而退出 1；这不表示新方案失败。证据报告另列 `candidateAccepted`，保留两组原始通过数与所有失败内容。

- 预设检查：新方案 8/8，旧方案 2/8。检查包括原文条款见证、关键条件同条、独立工作流分开、条数范围，以及已发布条目的检查归属字段完整性。实现代理另逐条复核原文与候选；不是独立人工准确率评估。新方案条数：花店 8/8，导入 10/10，同一行多流程 9/8，预约 12/12。
- 全部请求累计 token：77,734 → 59,516，减少 **23.4%**；输入 52,873 → 51,972，输出 24,861 → 7,544，缓存计数均为零。
- 全部请求回放墙钟：273.509 秒 → 119.820 秒，减少 **56.2%**。旧方案多数没有通过完整检查，所以这项不能叫“两侧都正确完成任务的时间”。
- 两侧均通过的两组单独比较：token 21,288 → 10,886，减少 **48.9%**；墙钟 56.144 秒 → 29.404 秒，减少 **47.6%**。这两组数量很少，不外推稳定均值。
- 四个场景按各自两次汇总，token 和耗时均减少。逐次配对中 6/8 减少 token，2/8 增加；8/8 减少耗时。预约场景 token 总量只减少约 6.2%，不能把整体 23.4% 套用到每个场景。

归属复核确认本轮 agent 复用、压缩恢复和阶段 UI 运行能力均没有丢失，也没有再误当成文档内容。非授权引文等约束的检查归属仍有模型分类差异；字段完整性不代表所有归属语义均已证明正确，宿主的领域/来源校验仍须执行。原文、禁止项及 USER_EXPLICIT 权限没有因整理而下降或被删除。

去敏证据夹具保存最终 16 次候选及已发布正文、累计用量、输入哈希、配对指标和全量回归计数，并保留 23 轮先前试验摘要，包括负收益、语义失败及中止观察。报告生成时的源码摘要与各次实际模型输入哈希分别保存，不将报告时源码哈希当作旧试验源码证明。
