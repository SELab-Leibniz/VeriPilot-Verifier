# 工作原理与信任边界

Runtime Corrector 共用策略编译、确定性规则、证据校验和状态存储；构建时选择宿主适配器。Claude/CodeAgent 使用七种 JSON-stdio Hook，OpenClaw 使用固定版本的原生生命周期、会话及工具接口。

## 写入后反馈

写入事件 → 解析项目及 RuntimePlan → 匹配启用的 artifact → 收集 bundle 和直接工作流入边 → 执行规则与 Schema → 按配置做隔离语义审阅 → 校验证据和编辑计划 → 保存结果 → 向主 Agent 发送有长度限制的反馈。

版本 1 的产物检查只在实际匹配的 Write/Edit 后执行。版本 2 的全工具 PostToolUse 还用于回合对账、证据记录及到期 Skill 看护；普通读取不会被当成产物写入。UserPromptSubmit 识别真实用户输入并更新任务依据，不因提到产物名称而预加载工作流。压缩后的 `compact_boundary` 用于恢复必要导航。

`check`、`explain`、`spec` 和 Hook 使用同一策略边界。CLI `check` 没有宿主父会话时不自动启动隔离 reviewer；开启语义审阅的节点返回 `agentReview.status = requested`。Hook 才能等待 reviewer 并返回完成或失败状态。

工作流只检查配置中启用的直接入边。`pathTemplates` 与 `workflow.correlation` 将同一 change 的上下游绑定，歧义不会通过“最近文件”猜测。Bundle 的文件数、大小和读取预算受限，截断或缺失不能视为完整通过。高频源码写入可用 checkpoint 和 `file-digest-manifest` 聚合审查，摘要必须对应当前快照。

## 任务基线与 Skill

版本 2 显式开启 dynamicGroundTruth 后，用户要求和项目约束进入带来源、修订及摘要的 Ground Truth 账本。抽取/小组核对/裁决可逐层保留来源；Agent 总结和自动反馈不能自行变成用户要求。冻结后的修订继续受来源权限、适用性和证据约束，面向审查的分页视图不会修改原基线或分母。

真实任务、父 Session、项目作用域和内部审阅各有身份。真实新任务与任务切换通过存储协议处理；不能凭模型自述完成重置。Skill watcher 只在成功保存并核验约束后准入，按选择规则、回合间隔和反馈上限检查；条件化步骤保留条件和例外，不把不可重做的历史步骤强制改成源码义务。

## Stop 与判定

Stop 先核对开关、额度和有效作用域，再冻结本次分类、要求、指标分母及截止。当前生产路径通过共享 Stop 核心分组审查；同一优先级、同一指标的条目可以共用一个审阅 Agent，每项仍有独立身份、证明与保存回执。

- PASS：指定范围的必要条件有当前有效证据支持，不能扩张为整个任务通过。
- DEVIATION：有适用的当前反证，反馈须保留原要求与证据身份。
- UNVERIFIED：缺失、过期、未完成、检查器故障或证据不足。
- ALLOW：控制流程允许停止；额度耗尽、取消或不支持续作也可能放行，并不等于 PASS。

检查器故障不自动归因为业务缺陷。历史偏差与当前确认偏差分开；依据变化后旧结果保留历史身份，不能直接进入当前反馈。当前有效子集可以交付，新增或改写的伪造条目不能混入。

每次 Stop 的审查与交付共用总窗口，交付预留包含在窗口内。会话与流程额度只在可信实际开始业务修复时消耗；排队、审阅、通知和保存不扣。任务/GT/模式/项目变化不能重置会话累计额度。详见 [Stop 审查](stop-task-review.md)。

## 证据与隔离

只读 reviewer 使用冻结请求及受限工具。实际读取证明记录路径、当前字节摘要、披露范围和调用归属；仅有模型提交的路径、行号或引文不构成读取证明。超大行、二进制、失败读取、未披露分页和来源变化均不能静默取得覆盖。M16 PASS 需要真实生产入口、写入者、数据流、消费者及必要分支的完整证明；它不能代替 M12/M13/M15 的执行证据。

内部运行使用私有身份与租约，阻止递归审查、工具越权和自动反馈污染用户基线。独立 reviewer 清除父凭据后注入指定提供器环境；配置只保存环境变量名，日志、argv 与请求不保存令牌。预算、取消信号和绝对截止贯穿读取、格式修复、提交及反馈发布。

## 持久化与恢复

任务位于 `.runtime-correction/tasks/`，事务日志增量提交、校验、checkpoint 和原子替换保护结果。重复事件、跨进程锁、取消与迟到回调在提交前再次核对身份和状态；旧回执不能覆盖新代次。宿主级会话额度与项目任务分别持久化，项目切换不绕过会话累计账本。

默认输出目录为 `.runtime-correction/`，也可配置集中目录。完整诊断、候选补丁、引用和未完成清单在限长反馈之外保存。SessionEnd 在配置加载前走静默、尽力而为的清理路径，不能启动新的审阅或压住宿主恢复提示。

普通入口故障按其协议 fail-open；活动 Stop 在缺少有效终结评估时保留未验证并依其终止门约定处理。宿主执行、文件权限、模型选择、工具审批与真实业务修复始终由宿主负责。固定宿主的支持边界见 [OpenClaw 指南](openclaw.md)。
