## 冻结交付内容

每次交付写入 `.runtime-correction/rc-supervision/daily-deliveries/<香港日期>/`。封存后另建版本，不覆盖文件。`delivery.json` 至少包含：

1. 交付 ID、截止时间、实际冻结和交接时间、阶段目标及当前状态。
2. Git 基础提交、dirty 状态、实际源码快照路径及逐文件摘要；不能只用 HEAD 标识未提交代码。固定依赖、宿主、Node、模型、提示、输入、运行参数与评分器摘要。
3. 可直接执行的准备、运行、验证和结果读取命令；源码快照完整可运行，避免依赖随后变化的工作树。
4. 正常链路与故障纠偏链路的原始结果、真实触发、正式反馈送达、修复后当前验证、模块独立验收，以及失败或未运行项目。保留源文、owner、全部义务和原分母；不能把内部回执、SETTLED 或测试通过当作效果通过。
5. 必要工程检查及同产物 native/Linux 资格的适用范围；没有执行的检查明确标注，旧资格只按相同输入复用。
6. RC 关闭/开启评测的样本、同等预算、官方分子/分母、有效/无效/未运行状态；效率只在同等完成度下比较。固定 TB9、DeepSWE9、SWE-bench Lite3，优先 Lite，不恢复旧 SWE-sweep 或 27 例口径。
7. 已知 token、时间、请求、在途、未知用量完整预留、累计账本与实际账单未知项；已知限制、风险和下一步。
8. 交付清单摘要、独立评测目录及交接消息回执。包内不得包含凭据、无关私人历史或真实业务源码。
