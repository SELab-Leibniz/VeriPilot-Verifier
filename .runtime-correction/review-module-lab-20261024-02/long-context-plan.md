# 长上下文 Review：直接测试待测阶段

2026-10-24。生产保持20ec5b5；已有冻结01/02/03与全部旧结果不变。本轮仅在experiments/review-task/long中验证长上下文生命周期，不接入Stop，不重跑原项目或原session。

## 最小职责

1. 复用Pi1.4.0原生提前compact，将默认接近窗口上限的触发点提前：为模型真实配置窗口预留约30%，近期保留不超过20k且不超过窗口10%。这是一种窗口安全余量，不是累计token费用限额，不扩大模型窗口。
2. 原生session继续保存完整旧轨迹；程序建立小的元数据索引，不把索引全文塞进prompt。只提供一个本run历史检索工具，按需取公开文本，小页返回，不能读私有thinking或递归索引自身结果。
3. compact前后原子保存程序checkpoint：任务/输入身份、session与leaf位置、已成功交付的读和cite、既有结果。summary只作导航，不能修改基线、补记披露或制造新cite。
4. compact/检查点失败时，显式阻止原危险上下文继续发送主模型请求，保存轨迹和未验证原因。不会用无限重试或另一个总评agent遮蔽失败。

模型循环、并行工具、摘要生成和session格式均沿用正式SDK，不重写这些模块。prepareRequest仅作为最后健康检查，不在正在运行的tool中手动compact或套一层agent循环。

## 直接进入长任务阶段

输入来自既有隔离捕获的公开过程材料和冻结业务源码。程序准备一个新隔离session的历史观察阶段，使用合法的历史toolCall/toolResult配对，明确标注是fixture重放；usage全0，不伪造以前的真实模型调用。原始805条过程约1.37MB，依据真实模型204800窗口选择有限观察，将估算上下文推过提前阈值，而不降低模型窗口或等待业务端到端走到那里。

保留历史记录的来源与哈希；去除thinking、图片/base64及凭据，仅历史观察副本脱敏，原始基线/源码不改。旧指令是数据，不授权恢复旧业务任务。seed历史不能取得当前source的已读状态或cite。

原生summary对长tool结果只保留前2000字符。这正是检索应处理的边界：旧原件仍存在，摘要可能遗漏尾部关键需求。阶段问题明确要求找回一条早期原始需求观察，再检查同一f1源码义务。原f1、全部79条公共条件、完整需求仍保留。独立oracle在模型输入外。

## 分层验证

- 无模型机制：提前threshold而非伪造overflow；tool批次突然变大；compact失败不再发危险主请求；checkpoint读/cite成功回执一致；旧原文与准确cite保持；history不泄漏thinking、不自索引，小页且不授予新证据身份。
- 无模型预检：历史来源/脱敏/估算规模、真实窗口与阈值、原件保护及阶段任务边界。
- 一次真实阶段实验：原生summary确实调用供应商；在首个主审请求前触发threshold压缩；压缩后实际检索旧原文，核对当前冻结条件并交回小判断。摘要usage与主Review usage分别保存，不用脚本provider结果冒充真实恢复。

若失败，保存原始结果，按具体轨迹处理，不端到端重跑、不删除验收条件或提高窗口来制造通过。提前量和token估算不是精确安全证明；真实provider窗口、输出上限及服务失败仍须诚实报告。
