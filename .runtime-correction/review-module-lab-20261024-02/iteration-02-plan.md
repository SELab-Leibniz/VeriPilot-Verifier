# Review 小模块第2轮：先证明有效，再比较效率

2026-10-24。生产HEAD保持20ec5b5，本轮只修改隔离目录下的v2实验文件，不接入Stop。v1代码、输入、真实结果及原0/4记录保持不变。

## 独立子任务和停止条件

本轮只有三个工程子任务，每个都有独立结果，不依赖模型生成一份大JSON总评。

1. **证据身份与小结果提交**：读取工具为实际披露区间生成cite ID；模型只选择ID。程序从冻结原件取路径、行号、精确字节与哈希，保存到文件。验证伪ID、跨runID、截断、源变化、取消与同批读取/提交。机制测试通过才进入真实审阅。
2. **审阅判断的有效性**：固定五个厨房对照，预期及独立verifier放在模型不可见区。每次只问一个清楚的问题，不要求列举全量通过项。全部预期提前确定，不用重复运行挑好结果。
3. **长材料查证与效率**：同一个复杂f1义务，全部79条条件及原需求保留，去掉根因提示，真实复测一次。比较有效判断、证据完整性和成本；不是把一个实现结论替代原四指标。

三个子任务分别保存记录。只有前两层安全性和语义验证成立后，才将更少回合/更低用量视为效率改善。失败不改写为通过，也不通过减少验收条件修正分母。

## 最小合同

Review输入是一个非空问题、完整适用基线、目标源码入口和可选可信diff。问题须明确是源码实现还是运行验收。相同义务下的不同证明目标是不同任务；条件和例外不与文件/指标做组合展开。

Review输出只是一条状态、一句机制与影响、少量cite ID。程序负责关联任务、基线、版本和原件。证据原文及详细轨迹是文件，不进入宿主短反馈。不要求模型复写引文、路径和行号，也不要求末尾生成整包JSON。

citation身份由本次run、文件内容哈希和实际披露区间确定；只有read发可提交的ID。grep/find/ls用于查找，不能凭截断搜索片段生成精确引文。读取整页就诚实称整页范围证据，需要窄范围时再读取该区间。程序获取原文能保证内容来源准确，不能自动保证模型选的证据支持结论。

PASS需要完整赋予义务得到支持；一个确定反例即可DEVIATION，但所有强制条件仍须完整披露。缺运行证据不能把源码层判断提升成运行验收。UNVERIFIED是有效的不确定性输出，不等于证明业务符合或不符合。

## 预先固定的真实对照

- 正确源码，候选只增加注释：源码R04审查预期PASS，独立verifier21场景通过。
- 删除库存扣减循环：源码R04审查预期DEVIATION，对应persisted-consumption失败。
- can-cook写入查询记录并保存：源码R04审查预期DEVIATION，对应只读查询改变store字节。
- Git基线已经有扣减缺陷，候选仅注释变化：源码R04审查仍预期DEVIATION。检验diff只导航，不能免除现行实现查证。
- 正确源码，但问题是实际运行验收且不提供运行记录：预期UNVERIFIED。独立verifier仍在输入外，不能自动将其通过提升为reviewer已经有该证据。
- 复杂项目仅f1实现义务：保留f1、79公共条件、原需求与冻结源码；去掉整页spinner等已知根因提示。预期由保留在模型不可见区的既有源码oracle和独立检查核对。

厨房使用中性案例编号和相同源码审查问题，不在模型可见路径、注释、task中放good/broken/预期结果。上述对照是已控制变异的查证测试，不声称统计盲测或生产完成率。

## 计量与限制

同时报告语义结果、引用是否由原件精确提取、全basis披露、有效结果落盘、主模型回合、验证错误、read/grep/所有工具返回量、缓存/非缓存输入及输出、耗时。静态prompt文件大小不能冒充完整实际请求大小。主Review用量不能冒充compact或SDK内部重试的完整账单。

不加额外token/时间硬预算；继续有限尝试、原生SDK重试/compact及防循环。独立读取可使用SDK原生并行；提交保留sequential屏障，同时禁止与source工具同批：仅“工具执行先后”不能证明模型作出判断前已看到新条件。最终提交需在收到取证结果后的另一轮调用。不新增调度层、batch工具、summary agent、结果数据库或生产缓存。

真实测试前冻结v2源码；后续修复另存迭代，不覆盖初次失败。最终保持原项目与session只读、原宿主配置不变、生产仓库干净。
