# 指标 Review Prompt 对照实验

2026-10-24。先保存当前进展为 `73390e0`，再开始本实验。范围仅隔离 Review 阶段；不重跑业务开发、App、verifier、设备或原 session，不接入生产 Stop。

## 固定问题与真值

选择当前 `vp-m01-m15-v1` 中的M01需求分解覆盖、M05验收准则覆盖、M12需求执行三个指标。每个运行只判断一个冻结对象，不把它扩写为整个指标分母或全项目通过。

厨房和花店各9个案例：每指标2个开发对照（正/负）及1个未用于调优结果的复核案例。共12开发、6复核。厨房包含明确标注的文档受控变异和已有正确/缺扣减源码；花店复用已有正式OpenSpec、人口对象、权限声明和冻结源码，必要变异仅在隔离副本中。完整原始需求保留。

oracle在模型workspace外，记录预期状态、语义机制、源位置与哈希。先审查跨章节同义覆盖和公共约束，防止把局部删句但别处仍覆盖的案例误标为负例。已有模型结论不作为真值。历史独立verifier只核对其记录及源码版本，不重新运行。

## 固定控制

baseline使用73390e0原六段system prompt（1894字节，SHA256 `d7e8379fd3977e5307cf6a464b303c8b6270e940bd6d0e0a05a64d94370fa695`）。新增可选可信promptAppend参数；空值的实际provider prompt与基准逐字节相同。工具、schema、任务文本、输入版本、maxAttempts=2、maxTurns=100、每次回复8192及模型窗口保持一致；没有累计token或时间预算变化。

每种候选仅增加相应指标的通用语义rubric，不提供case标签、变异信息、预期结论或具体缺陷答案。每轮新session、同一冻结case输入；保存完整组合prompt及其SHA。session、时间、cwd与cite UUID等自然身份字段不同，不能称全部网络payload只差一个字符串。

## 有限迭代

1. 冻结输入与oracle，跑baseline的12个开发案例；同时检查状态、诊断与来源，不能只看verdict。
2. 冻结rubric-v1，在同12案例对照；独立核对差异与误判。
3. 依据具体错误形成rubric-v2。只重测受修改影响指标的开发案例；未改指标不重复消耗。即使基准已全对，也不宣称候选提高准确率；可用一次风险对照确认更简短的prompt是否同样可靠。
4. 按指标选择开发集上有证据支持的版本；同分优先更短、成本更低，证据不足时保留baseline。冻结后在6个复核案例上对照baseline与选定版本；结果不再用于修改本轮prompt。

最多三个prompt版本；不无限搜索，不修改失败case的原条件或oracle，不用扩大上下文/预算来帮助某版本。基础设施失败单列，保持原记录，最多针对确有错误的实验设施修复一次。

## 评价口径

- 主指标：状态正确且诊断机制由实际引用支持；PASS需覆盖指定对象全部义务，DEVIATION需具体反例，UNVERIFIED需明确缺少哪类证明。
- 分列误报、漏报、错误PASS、过度弃权与基础设施失败；UNVERIFIED不是业务PASS。
- 独立逐字节cite核验与独立语义审阅分开。语义审阅不看prompt版本身份，按小批次审查，不把全部长轨迹塞给一个总评模型。
- 次指标：成功提交次数/错误次数、模型回合、重复读取、输入/缓存/输出token、worker耗时、短反馈字节。
- 不能用开发集得分证明泛化；6个复核仅是小规模对照，不能估计生产稳定率或完整15指标准确率。
